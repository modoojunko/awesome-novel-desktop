## 三、缺陷与卡壳点清单

### P1（主功能阻断 / 跨环境缺陷）

#### Bug1｜S端 前端在任何本地/私有部署下会把 API 请求打到生产域名
- **现象**：本地栈打开 C端登录 → S端授权页后，授权页的 `check-auth` 轮询与 `authorize` 提交全部发往 `https://www.awesomenovel.com/api/...`，本地后端零请求；设备授权在本地栈完全不可用（登录主流程阻断）。生产端同时暴露 CORS 双头：`Access-Control-Allow-Origin` 含两个值 `'http://localhost:6173,*'`。
- **根因链（三层叠加）**：
  1. 运行时层：S端前端启动时加载同源 `site-config.json`（部署级换发点），仓库内该文件 `apiBase` 硬指生产域名，运行时覆盖一切构建期值（`server/frontend/public/site-config.json`）；
  2. 构建层：`.env.production` 兜底值同样是生产域名；
  3. 构建层补充：`.dockerignore` 排除 `*.local`，导致 `.env.production.local` 本地覆盖通道在 docker 构建中失效（CI 部署链路不受影响，因为 CI 直接写该文件后构建）。
- **影响**：任何 docker/私有化部署的 S端 前端 = 装饰物；本地联调、e2e 之外的真实授权流程全断。本地测试者的配对挑战会被发往生产（本次被 CORS 挡下，若生产 CORS 修好则可能把本地设备写进生产库——**有生产数据污染风险**）。
- **修复建议**：仓库内 `site-config.json` 的 `apiBase` 置空（回落构建期值），生产域名只由部署流水线写入；同时给本地 docker 构建一条官方的本地化通道。生产 CORS 双头独立修（网关与后端只留一个 ACAO 来源）。
- **测试中的环境级 workaround**：本地重建镜像（`VITE_API_BASE=/api`）+ 挂载本地化 site-config，修复后配对流程全程通过。
- **证据**：`t13` 前后 console-log（`t04`~`t12` 期间）、`qa-evidence/console-log.txt` 17:31~17:35 段、`t48/t49` 截图。

#### Bug2｜「AI 生成正文」后端 404（路由注册缺陷），且前端对失败零提示
- **现象**：章纲已确认、模型已绑定、提示词预览弹窗正常（内容组装完整），点「生成正文」→ **无任何反馈**（无 toast、无报错、无转圈），正文不变。
- **后端实锤**：`POST /api/novels/{id}/chapters/vol-3-ch-2/write → 404 Not Found`（backend 日志）。
- **根因**：`client/backend/write/router.py:29` 的 prefix 已以 `/write` 结尾，`:290` 的 `@router.post("/write")` 再拼一段 → 实际注册路径为 `.../write/write`；前端 `client/frontend/src/lib/ai.ts:54` 调用的是 `.../write` → 404。同文件的 `/prompt`、`/prompt/polish`、`/quality-check`、`/continue`、`/polish` 均因前缀拼接恰好正确而可用——**唯独最核心的「生成正文」路由错位**。
- **附加缺陷**：404 被前端吞掉，用户点击后毫无反馈（无网络错误提示）。建议：所有 AI 动作失败必须 toast + 可重试入口。
- **按 3 次重试规则**：已尝试 3 次触发生成（含解锁只读路径），均 404，停止该测试点。
- **证据**：`t72/t73/t74/t75` 截图、backend 日志、代码行号如上。

### P2（明显体验缺陷 / 状态一致性）

#### Bug3｜归档上一章后，下一章正文不即时解锁，需手动刷新
- **现象**：第一章已归档、第二章章纲已确认，第二章正文编辑区仍显示「还不能写这一章——先完成前面的章节。完成前面的章纲并归档后，这里会自动开放。」；刷新页面后立即解锁。
- **影响**：顺序写作的作家每写完一章都要「刷新一下」才能继续，提示文案还与实际状态矛盾（前面的章明明已完成）。
- **证据**：`t66/t67/t68` 截图对比。

#### Bug4｜角色卡自动保存竞态造成「假丢字」观感
- **现象**：连续填完主角卡 11 个字段后立即点击认知层展开项，卡片瞬间回显「未命名 · 人设缺1/1 · 档案缺6/6」；数秒后数据实际已落库（重载后全部恢复）。
- **影响**：极易被作家误判为「输入全丢了」而恐慌重打甚至弃用；「有未保存修改」标识也随回显消失。
- **建议**：保存完成前锁定区块切换，或回显时明确标注「保存中…」。
- **证据**：`t32`（填满）→ `t33`（回显旧值）→ `t34`（重载后恢复）。

#### Bug5｜确认题材后顶栏书名旁仍显示「待定题材」，刷新才变「玄幻」
- **证据**：`t16`（确认后立即）vs 重载后。所见即所得断层。

#### Bug6｜书卡「更新于 8 小时前」——时间戳时区错位 8 小时
- **现象**：书刚建 1 小时内、最后更新就在几分钟前，书架显示「更新于 8 小时前」。
- **根因方向**：容器内 UTC 时间戳与本地 +08:00 混用（与 S端 日志时区错位 8h 同类）。用户可感知、影响信任。
- **证据**：`t79/t80` 书架页。

#### Bug7｜无 API Key 时 AI 入口行为不一致 + 空态 CTA 静默无反应
- **现象**：角色页空态引导按钮「从简介立主角」点击后无请求、无提示、无跳转（3 次重试确认）；同页右栏 AI 行「从简介立主角」则会跳转模型配置页。其他设定页右栏 AI 行在无 Key 时多为静默。
- **建议**：统一行为——无 Key 时全部跳模型配置页并说明原因；空态 CTA 与右栏行为对齐。
- **证据**：`t21_*` 连拍、backend 日志零请求。

#### Bug8｜写作页头部「写作 0/6 章纲」计数失真
- **现象**：6 章章纲全部确认、全书归档后，头部徽标仍显示「写作 0/6 章纲」；逐章页签「已确认」与预览页「全书概览」正常。计数从未随确认更新过（全程 0/6）。
- **证据**：`t83`、对照 `t70/t79`。

#### Bug9｜归档与章纲确认的门禁时序缺口（状态一致性风险）
- **现象**：章纲未确认的章也能写正文并点击归档，但归档**静默不生效**（预览页显示草稿，无错误提示）；后续补确认章纲后需再次手动归档。本次实测 ch3/ch5/ch6 全中，靠预览页目录才暴露。
- **建议**：归档时校验章纲状态并明确报错；或归档成功后同步刷新预览统计。
- **证据**：`t79`（预览 3 草稿）vs 写作页逐章「已归档」假象；补归档后 `t78` 全部已归档。

### P3（打磨项）

10. **卷名重复前缀**：树节点显示「第一卷 · 第一卷 · 灯火初明」——弹窗 placeholder 引导输入「如：第一卷 · 风起」，树又自动加「第一卷 · 」前缀，必然重复。建议 placeholder 改为「如：风起」或去掉自动前缀。（`t58`）
11. **AI 提示词文案污染**：生成正文提示词预览中出现「你是你是全球闻名的小说作家」（「你是」重复）与「此为默认角色定位——Phase 2 选择类型档案后，Phase 4 将自动替换…」内部阶段说明。前者是拼接 bug，后者不该出现在用户可见的提示词里。（`t74` 前的弹窗截图 `t73`）
12. **「续写」在编辑器无光标时静默无反应**：光标位置是接口必填参数，前端未聚焦时不发请求也不提示。（`t76`）
13. **章纲确认按钮的禁用恢复滞后**：填完段落规划后按钮短暂保持禁用，等待自动保存完成（或刷新）后才能点；期间无「保存中」标识。（实测于 ch5/ch6）

## 四、测试工具层问题（与产品无关，但影响后续自动化测试）

- **T1｜ZCode 内置浏览器（IAB）鼠标事件路由失效**：落地页可点，但同一会话后续标签页中坐标点击落点与目标错位（点输入框落到别的字段、点勾选框无效）、locator click 全面超时；注册页勾选框因此无法 GUI 勾选。**应对**：切换为仓库 Playwright + 独立 Chromium（CDP 桥 `pw-bridge.cjs`），全程稳定。建议仓库 e2e 继续用自身 Playwright，勿混用 IAB。
- **T2｜Playwright 桥的持久 profile 会缓存旧 index.html**：镜像更新后浏览器仍从缓存加载旧 bundle（资产 404 都不报），表现为「修复无效」。**应对**：换 profile 目录重启桥。
- **T3**：`getByText('添加角色')` 等按钮文案带图标前缀（「plus 添加角色」），exact 匹配易失败——写 e2e 时用 `hasText` 或 data-testid。

- **销毁全部测试数据与环境**：
  ```bash
  docker compose -p qa-night -f .docker-data-qa-night/compose.yml down
  rm -rf .docker-data-qa-night          # 含全部测试数据、截图、compose
  ```

- **截图证据**：`.docker-data-qa-night/qa-evidence/t01~t83*.png`（命名对应上述各缺陷）。
- **给开发的最短复现**：

  - Bug3：归档当前章后不刷新直接点下一章正文页签。
  - Bug8：确认任意章纲后看写作页头部计数。
