爱小说 C 端 · 统一设计语言规范 v2.1

承接 Open Design v2（#181~#187 已落地的令牌 / 组件 / 门禁）· 配套《页面使用路径与逐页评估》 · 本文件是唯一权威标准（2026-08-27 起），机器强制层为两端 scripts/design-vocab.mjs，词汇改动须与本文件同批对齐

定位说明：这不是推倒重来。v2 已经把色彩、组件类、图标、门禁、原型 parity 都立起来了，本规范做三件事—— ① 把已经隐性一致的东西写成显性规则；② 把散落的写法收敛进既有档位；③ 为还没有界面的业务面（推演 / 归档回路 / 导出）预留语言。 所有改动都要走既定的「先改原型 → 改实现 → design:check 全绿」流程。

一、设计原则（两条继承 + 四条新增）

原则判定标准（能用来吵赢的句子）已落地证据
P1 永远知道下一步 继承每一屏至少有一个明确的下一步入口；阶段完成即出现下一阶段入口。modnav 计数；OgPane「去写正文」；VolumePanel「去配章纲」
P2 状态可见 继承进度 / 保存 / 确认三种状态全局同一套语义，完成即变色。三态圆点；保存四态；设定 n/8
P3 允许旁路 继承设定未完成也可以先写；高级配置标注「可后补」。任何必填门槛都必须给一句「为什么缺这个不行」。canDefer 标注；空书直达编辑器；主线三项可只填部分
P4 正文优先 继承写作中屏信息密度从低到严控；宋体排版、专注模式、状态安静不打断心流。17px/2.0/缩进 2em；专注模式 Esc
N5 同一对象同一套状态语言 新一个业务对象（章 / 卷 / 设定项 / Key）在树、卡片、徽标、页签里的颜色语义必须完全同源。禁止为单屏发明新的状态色组合。待落实 —— §5 总表是唯一来源
N6 红色只表示不可逆或即时生效 新--err 只用于删除确认主按钮 / 破坏结果描述 / 校验阻断。营销式强调、警示但不危险的内容用 --warn 或 --accent。待落实（当前 list 卡片菜单危险项误用 warn）
N7 AI 行为必须可预期、可拒绝、可改 新每个 AI 入口都要回答四个问题：它会动哪里？停不停得下来？结果能不能不要？能不能手改成我要的？答不全就不许上线。AiModal 两段式 + 停止 + 对比弹窗已有雏形
N8 中文阅读优先，术语说人话 新界面文案遵循卖点文档的翻译律：内部术语不出现在用户可见层（§13 有对照表）。页面名「模型配置」已是范本

4.2 间距（4pt 栅格 + 一枚节奏变量）

  • 栅格取 4 的倍数：--s1 4 / --s2 8 / --s3 12 / --s4 16 / --s5 20 / --s6 24 / --s8 32 / --s10 40
  • --field-gap（建议 16px）是唯一表单纵向节奏变量。现在 base 弹窗 14px / 书内 16px 的分叉以 16px 统一，把「有意为之」的注释换成「共用一个变量」，否则新屏永远在猜。
  • 两处模块级节奏（config 屏 main 顶部 44 vs 标准 48、cards gap 16 vs 20）若确要保留紧凑，登记为 --main-pad-top-dense/--card-gap-dense 并注明适用屏，而不是匿名写死。

这张表是全站唯一的对象状态视觉来源。新功能出现新状态时，先在这里加一行，再写样式——不允许局部发明第四种绿或第二种黄。

5.1 进度三态 + 衍生态

5.2 过程态（时间性状态）

规则 S-R1：同一对象在不同视图中的状态表达必须由同一份数据驱动（例如章的三态由服务端 status 派生），UI 不允许只在某一视图里表现更乐观的状态。
规则 S-R2：「进行中」永远比「未填」更暖、「已确认」永远是绿色系——这条优先级高于屏幕内的美观判断。
规则 S-R3：警示性的常态化徽标禁止（反例：卷纲面板永久挂「草稿」warn 徽标会把警示日常化）。常态属性放到副标题里说。

十、AI 交互四形（每个 AI 入口必须归入其中之一）

形态结构适用已有的范例实现
A1 就地建议形字段行内小按钮「AI 帮我填」→ AISuggestionModal（loading 骨架 → 结果 → 换一个 / 接受这个 / 关闭）；字段已有内容则先展示现值再给强制重试单个字段的起草世界 / 文风 / 伏笔字段
A2 对比替换形双栏：原文 ↔ 生成稿；底部 拒绝 / 换一个 / 接受；结果就绪后 Enter=接受；说明一句「接受后将替换原文选区」局部改写且有损ContrastPreviewModal（润色 / 扩写）
A3 组装审阅形先生成可读中间物（提示词）→ AI 润色 → 用户过目编辑 → 才真正执行；被拒绝不会产生副作用不可逆 / 大范围输出AiModal 两段式生成正文
A4 流式伴随形编辑器锁定 → accent 呼吸点 → 停止可随时中断且保留半成品 → 结束给非阻断质检横幅并指向补救动作（如「续写」）正文级连续产出ProsePane startWriting

公共守则（对应原则 N7）

  • 来源声明：凡是内容会被 AI 读走的，入口处用一句话说明来源（「由设定 + 章纲组装，可先润色再编辑」）。
  • 去向声明：会写回到哪要说清楚（「生成内容将追加到本章末尾」）。
  • 覆盖警告：AI 结果将覆盖用户已有内容时，必须 confirm 一次（AiModal 起草覆盖当前表单的做法是标准）。
  • 降级路径：没有前置条件时不阻断而降级——「本章尚未配置章纲，将仅依据设定生成。建议先去大纲补章纲（不强制）」这句就是这个模式的范本。
  • 会员拦截统一出口：入口可见、点击触发后端 403、由全局 MemberBlockPrompt 统一弹升级窗；具体卡片自身只做视觉上的锁定态，不再各自弹窗（消灭重复劝导）。向导类（ArcWizard）需要在卡上先声明「会员功能 · 每步产出先落卡、随时可改、中途可续」，避免点击后才知情。
  • 能力预告（路线图占位）规范：Rail 的「规划中的能力」折叠成一行，并在 PRD 范围更新时同步改名；占位不算宣传承诺。

十一、免费 / PRO 门控的视觉规则

商业模式主张「免费 = 人工写作完整能力，PRO = 同一界面解锁 AI」。这是设计语言的一部分，不是运营话术。

策略什么时候用视觉
可见 + 锁定（首选）AI 能力入口、被额度挡住的操作、提示词这类 PRO 专有页签降透明 / 锁徽 / PRO 星徽；点击要么给 UpgradeModal 要么由后端 403 触发 MemberBlockPrompt；锁定态必须附一句收益描述
完全隐藏（例外）仅当该入口的存在本身会让免费用户误解功能边界时隐藏必须在别处有一次补偿性告知（比如书架 notice）
能力等价人工路径的一切功能零差异；包括归档 / 版本 / 偏好这些质量设施
按此规则的整改清单：① 书架满额时的「新建/导入」从隐藏改为锁定入口 + 说明「免费版最多 1 本书 · 升级无限创建」（评估 C1）；② 提示词页签对免费从隐藏改为锁定页签（评估 F3），保持 tab 架构稳定且兑现「同一界面」；③ 引导卡补齐免费用户版本（评估 D1），但去掉 PRO 步骤「提示词」的展示或把它画成锁定节点。

十二、删除与破坏性操作分级

级别条件形式实例
L1 行内即时草稿性质、可重建的小行（阶段分配行 / 冲突阶梯行 / 例句行）直接删，无确认；建议补 UndoToast 化的软撤（复用 api-config 的 UndoToast）SubTable / ListEditor 行删除
L2 盘点确认删除会影响关联内容的实体ConfirmGuard + 内容盘点 chips（「章纲已确认」「正文 N 字」「自定义提示词」）树上删章 / 删卷（卷版还要 N 章 M 字合计）
L3 名称输入确认不可逆且对象具有身份（书 / 角色 / 自建题材）DeleteConfirmModal 输入名称匹配；后果说明写清楚；409 冲突要列出受影响的书删书 / 删角色 / 删题材
L4 软删除 + 撤销技术上可恢复、且恢复价值高立即生效的 toast + 8 秒撤销窗口API 配置删除（现阶段唯一一处，应推广到 L1 行级删除）
归档 ≠ 删除—归档是生命周期态不是销毁：入口叫「归档」，解除走 UnlockModal，且解除后自动续跑被打断的动作章节归档链路
规则 D-R1：破坏性文案必须写「丢了什么 + 是否可逆」，不能只写「确定吗？」。
规则 D-R2：同一次操作链条里只允许一道确认；归档 + AI 摘要额度这种叠加要合并为一个对话框（e2e 里 trial 双 confirm 的特例应当作为回归教训记录）。

书写规范

  • 称呼一律「你」，不用「您」（全文已一致）；避免卡通语气词与感叹号。
  • 按钮词永远是动词（保存 / 确认 / 删除 / 去写正文），不放「好的」「知道了」以外的主谓句。
  • 补救语句必须包含一个可点击的出口（「还差 800 字，继续写。」而不是「字数不足」）。
  • 数字用等宽字体 + 千分位（2,486 字）；时间用相对时间（刚刚 / N 分钟前 / 昨天 HH:mm / 更早 M月D日）。
  • 每个上限都要在界面里可见：≤500、1–3 条、500–6000 字这类约束写在输入框 hint，不藏在报错里。
