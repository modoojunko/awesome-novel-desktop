# 导入自有书 · 架构整改方案（2026-10-18）

牵头：架构师视角。目标不是把评审意见逐条补丁，而是把「导入自有书」收敛成一个可落地、可回滚、A/B 可分阶段交付的架构。以下每条都给出**决定、改动、验收**；最后给分阶段计划和需要拍板的少数点。

## 0. 总原则

1. **产品语义不变，实现少加状态。** 「导入章是历史章、可编辑、不计完本、续写 N+1」必须成立；但不再往 `chapters.status` 里加 `imported` 值，改用不可变 `origin=import` 派生历史语义。现有 confirm/unarchive/version-restore 六个入口会改写 status，新增状态值守不住。
2. **一个事实一个来源。** manifest 是解析事实，structure 是作者确认的布局，origin 是章来源，baseline/coverage 是导入状态，open_receipt 只是快照；不再让 `source=import` 同时承担「旧书识别 / 新 A 路 / 是否播种」三种语义。
3. **A 路先闭环，B 路先做技术验证再排期。** A 路不依赖拆书管线；B 路的「分段」目前是未经验证的方案，先跑 180 万字实测，再决定删分段还是改两遍式。
4. **不把「历史章」塞进「本章变化」表。** 拆书卡给的是可见状态，不是变化；导入基线单独建表，章档四域表继续只存归档提取的「变化」。
5. **所有跨模块判断集中到一个谓词模块。** `is_historical / counts_toward_completion / is_writable` 单源，任何 `status == "archived"` 分支必须分类，禁止各模块各写一套。

## 1. 逐条方案

### 1. 开工基线：先换 worktree

- **问题**：当前工作区落后 `origin/main` 61 个提交，任务清单/详情/拆书前端不在工作区。
- **决定**：从 `origin/main` 新建独立 worktree/分支；主检出只用于设计文档。
- **改动**：`git worktree add ../ai-novel-wt-import -b c-import-own-book origin/main`；记录 commit；先跑前端 vitest/tsc 基线。
- **验收**：`git rev-list --left-right --count HEAD...origin/main` 为 `0 0`；`client/frontend/src/components/tools/` 存在；基线测试绿。

### 2. 章节编号：`global_no` 派生，不落库

- **问题**：`frontier.chapter_no` 是卷内号，两卷 42 章的下一章会变成第 19 章。
- **决定**：存储继续保留卷内 `chapter_no` 与 `ref`；新增派生 `global_no`，由卷序累计计算，**不落库、不重排 ref**。
- **改动**：
  - 后端新增 `chapters/numbering.py::global_no(volumes, chapters)`；`/frontier`、`/volumes`、`/tree`、章详情返回 `global_no`。
  - 待写占位返回 `global_no = 主线活动章数 + 1`（排除 ghost）。
  - 前端删除 `last.chapter + 1`、`chapters.length + 1` 等本地计算；新建章默认标题、树/预览/拆章素材统一用 `global_no`。
- **验收**：2 卷 42 章时 `vol-2-ch-3` 显示第 27 章、待写第 43 章；1 卷/空书/ghost 各一组；拆章素材的「第 N 章」与界面一致。

### 3. 历史章：`origin=import` 派生，不新增 status 值

- **问题**：`status=imported` 会被 confirm→confirmed、unarchive→draft、版本恢复回写旧 status；改六个入口也容易漏。
- **决定**：`chapters.status` 保持 `draft/confirmed/archived`；新增不可变 `origin`（`authored|import`）与 `imported_at`。API 派生 `historical: true`（或 `imported: true`），产品文案仍是「原文/历史章」。
- **谓词**：
  ```text
  is_historical(ch)            = origin == 'import' and status != 'archived'
  is_imported_archived(ch)     = origin == 'import' and status == 'archived'
  counts_toward_completion(ch) = status == 'archived' and origin != 'import'
  ```
- **改动**：
  - 迁移只加列+回填 origin，不改任何 status；旧导入书的 draft/confirmed 原样保留，靠 origin 识别。
  - `frontier` 跳过 historical；`is_writable` 保持「有正文可写」，另补 archived 只读守卫（现有 spec 承诺）。
  - 章节树/预览/章档按 origin 显示「原文」；作者确认章纲、恢复编辑不会改变历史语义。
- **验收**：对历史章依次执行 confirm、unarchive、版本恢复、归档，`origin` 始终为 import；续写始终 N+1；「confirm 后变回普通章」用例为红。
- **回退优势**：旧版本代码不认识 origin，只会忽略新列；status 没变，旧库仍可启动（历史语义退化，不损坏数据）。

### 4. A 路落库：新写一个事务级 writer

- **问题**：`create_project`、`save_chapter`、旧 `import_persist` 内部各自 commit，做不到「整笔回滚」。
- **决定**：不复用旧写入口，新增 `novels/import_writer.py::persist_import()`，一个 session/一个事务完成 Novel/Volume/Chapter/Content/import_token。
- **改动**：
  - `Novel(source='import', import_kind='direct')`，不调用 `create_project`，不播种设定；`import_token` 唯一索引。
  - 批量 `add_all`（每批 200–500 章），显式写 `word_count`、`has_prose`、`outline_status`，避免 `chapter_repo.upsert` 默认值把章判成空章。
  - 先按 `import_token` 查已有书；命中直接返回，不再走配额检查（重试不 403）。
  - 正文从 `import_sessions` 的 manifest 区间切片，不在 HTTP 里回传全文。
- **验收**：240 章/180 万字导入成功；在第 120 章注入异常，库里零卷零章；同一 token 重试返回同一本书；`has_prose/word_count` 与正文一致。

### 5. 消费面收口：一个谓词模块 + 11 份 delta

- **问题**：至少 6 处 archived-only 判断，以及完本分母仍含导入章。
- **决定**：新增 `chapters/lifecycle.py` 谓词；所有跨模块判断只调用它。完本/阶段用 `authored_total` 与 `authored_archived`，分母排除 origin=import。
- **逐面改法**：
  - `write/story_state.py`：archived 取变化行；historical 取导入基线；stale 跳过并注明；stale refs 纳入 historical。
  - `write/prompt_sources.py`：上一章是 historical 时给摘要/原文摘录，不再返回「上一章未归档」。
  - `volumes/service.py::resolve_prev_ending`：archived 或 historical 都算「实际收尾」。
  - `chapters/ai_plan.py`：历史上下文集合与当前卷配额集合分开；导入章进「已写过什么」，不占配额/末章；无摘要回退正文首段（独立块、限预算）。
  - `archive/dossier_router.py`：historical 且有基线时 `rows_only`；无基线时 `not_extracted` 可补算。
  - `novels/router.py` + `lib/novelStage.ts`：下发/消费 `authored_total/authored_archived`；只有导入章的书阶段=写作中，不能完本；全部 authored 章归档才 ready。
  - `works-finish-flow`：finish 守卫改为 `authored_total > 0 且 authored_archived == authored_total`。
  - `preview-reader`：计数桶 `archived_authored / archived_imported / historical / draft / planned`，四桶加总等于总章数；完本进度只用 authored。
- **新增 delta**：`works-finish-flow`、`novel-workspace`、`write`、`volumes`、`archive`（原 proposal 只有 7 个 capability）。
- **验收**：同一 status 分支全站静态扫描 + 端点矩阵；「42 章导入 + 新章归档」到 ready；「42 章导入全部归档」仍写作中；A 路无基线 story_state 不出空段。

### 6. 导入基线：单独建表，不冒充「本章变化」

- **问题**：拆书卡只有 `world/characters/relations/foreshadow` 等可见项，没有 evidence、没有变化语义；写进 `chapter_setting_changes` 是把「状态」冒充「变化」。
- **决定**：新增 `chapter_import_baseline` 表，存「导入时可见状态」；章档四域表继续只存归档提取的「变化」。v1 接受有损基线，不改卡片契约。
- **表**：`chapter_id`（FK CASCADE）、`domain`（summary/world/character/relation/hook/cast）、`key`、`value_json`、`source_card`、`ranges_json`、`evidence_absent`、`created_at`；唯一 `(chapter_id, domain, key)`。
- **覆盖**：`chapter_dossier_coverage` 用 `chapter_id` FK，记录每域 `full|partial|not_extracted` 与 `ranges: [[from,to],...]`（首 4000 + 尾 2000 是两段不连续区间，不能用一个 char_from/char_to）。
- **story_state 优先级**：historical 且基线未被显式重提 → 用 baseline；作者显式「重新提取」→ 写四域变化行并把 baseline 标 `superseded_at`；archived 章 → 用四域变化行。
- **补算**：`fill_missing` 只补缺失域，不替换已 accepted 行、不归档；补算结果写四域变化行并标 `origin='fill'`，或写 baseline 的 item/cognition 域（二选一，建议后者，保持「变化」表纯净）。
- **验收**：卡→baseline 的字段映射 golden；coverage 标 partial；无 evidence 不写假证据；42 章基线不触发 42 次 AI；补算非目标域逐字不变。

### 7. 伏笔：台账只认 `foreshadow` 维度，卡片只做章节标记

- **问题**：卡片 `foreshadow` 只有 `desc/kind`，没有 plant/payoff 章；书级 hooks 服务不写章 FK，单次限 20 条。
- **决定**：书级台账只从拆书 `foreshadow` 维度产物建（它有 `plant_ch/payoff_ch`）；卡片级 foreshadow 只写 baseline 的 `hook` 域，作为「本章有埋/收动作」的展示，不建台账身份。
- **改动**：章节落库后把 `plant_ch/payoff_ch` 映射成章 ref，回填 `introduced/planned/resolved_chapter_id`；`batch_create_hooks` 改成分批循环，>20 条在回执明示；去重键 `desc 归一 + 相似度阈值`。
- **验收**：42 章 30 条伏笔全部落台账；埋/收章号正确；同一 desc 不重复；>20 条有回执。

### 8. B 路管线：manifest 进管线，分段先验证

- **问题**：`_load_chapters` 重新解析源文件；任务级 cards/dims 完成状态会跳过/覆盖段；现有管线可能本来就支持长文。
- **决定**：
  1. **先做技术验证**：用现管线跑 180 万字/240 章（桩或真模型），记录是否完成、耗时、token、内存、失败点。若完成，**删掉外层分段**，只保留章级断点；若确有 60 万硬限，采用两遍式。
  2. **两遍式**（只有验证失败才做）：每段只跑逐章卡，存到独立段表；全部段完成后用全量 cards 跑一次十维归并（带段上下文/角色表/世界块/未收伏笔），graph 用全量 cards + 章号 offset。禁止每段独立跑十维。
- **manifest 改造**：`_load_chapters` 按 `manifest_json` 的 `source_idx/char_start/end` 切片；忽略/删除后的活动章序稳定；`parser_version` 不一致拒绝续拆或强制重建。
- **产物存储**：若两遍式，新增 `deconstruct_segment_cards`（task_id, segment_index, chapter_idx, cards_json），`products_json` 只放最终十维；不要用 `segment_index` 当产物命名空间。
- **验收**：180 万字任务可完成或明确失败点；忽略第 5 章后 41 章基线 ref 正确；v1 建任务/v2 续拆章映射不变；段失败只重跑该段，已完成段不重复。

### 9. 开书状态机：租约 + 回执 + 完整组合表

- **问题**：`opening` 崩溃永久卡死；九种组合有六种未定义。
- **决定**：加 `open_claim_token`、`open_claim_at`、`open_stage`、`open_receipt_json`；claim 带租约，启动 sweep 回收。
- **组合表**（必须全定义）：
  | task.status | open_state | book | claim | 动作 |
  |---|---|---|---|---|
  | completed | none/confirming | 无 | 无 | 确认/开书/调整结构 |
  | completed | opening | 有/无 | 有效 | 只看进度，禁止第二个写者 |
  | completed | opening | 有/无 | 过期 | sweep→partial，显示继续 |
  | completed | partial | 有 | 无 | 继续/删除未完成书+任务 |
  | completed | partial | 无 | 无 | 继续（validate/book）/删除 |
  | completed | done | 有 | 无 | 进入书内 |
  | failed/cancelled | partial | 有 | 无 | 跳过设定开书/继续/删除 |
  | need_reupload | partial | 有 | 无 | 章节已写完则 done，否则重传 |
  | any | confirming | 有 | 无 | 非法→done 或 partial，修复 |
- **阶段**：validate → book → settings → baselines → chapters → receipt；每阶段完成写回执，重试跳过已完成阶段；`apply.import_book` 改为 `open_import_book`，显式 `seed_settings=False, condense_world=False`，世界压缩移到拆书收尾。
- **部分书**：`deconstruct_jobs.book_id` 是唯一指针；书架查询 join 任务，`open_state != done` 的书不显示；任务行显示「开书未完成·继续」；部分书占书位，删除任务时二选一「保留书并完成」或「删书+任务」，不能留隐藏书。
- **验收**：开书到章节阶段 kill 进程→重启→继续→不重复建书/设定/章节；并发两次 claim 只一次成功；九种组合各有按钮与测试。

### 10. 迁移与 backfill：carry 之后幂等回填

- **问题**：新列 `default=` 在 carry 后是空串；旧书 backfill 没有触发点；`source=import` 一字段三用。
- **决定**：所有新非空字符串列加 `server_default`；旧书回填在 carry 完成后按 `app_meta.import_backfill_v1` 幂等执行。
- **改动**：
  - `chapters.origin` 默认 `authored`，`imported_at` 可空；四域/基线 `origin` 默认 `extract`。
  - `deconstruct_jobs.source` 默认 `manual`，`open_state` 默认 `none`。
  - `books.import_kind`（`direct|deconstruct|legacy`），`import_token` 唯一可空。
  - 只保留 `deconstruct_jobs.book_id` 一个 book↔job 指针；删掉 `books.import_job_id`/`import_state` 的设想。
  - 回填：`source='import'` 且 `import_kind IS NULL` → `legacy`；其章 `origin='import'`、`imported_at=created_at`；status 不动。
  - 旧 `/import/persist` 返回 410；旧 md/docx 入口退役。
- **验收**：真实旧库 carry→回填→续写 43/预览原文/完本阶段不变；旧任务 source=manual、open_state=none；回滚演练「旧版本+旧库可启动」；新库备份可恢复。

### 11. 删章：v1 只做导入前忽略/删除

- **问题**：现有删除只允许「本卷最后一章+拟定+无正文」，导入章全有正文；落库后删章要重排 ref，会破坏 last_write/归档引用。
- **决定**：v1 只在第 2 步做「不导入此章」；落库后不提供删章。需要大改时另立 tombstone change。
- **改动**：删除 `volume-chapter-service` spec 中「删除导入章」的要求；第 2 步支持忽略/撤销 + 确认弹层；A/B 书内提供「删除本书重新导入」出口（删书，不删源文件）。
- **验收**：第 2 步忽略第 5 章后 41 章、结构范围连续；落库后无删章按钮；删书重新导入只留一本。

### 12. 产品闭环：先冻结规则，再改界面

- **A 路终点**：建书成功直接进工作台并选中第 43 章待写位；主 CTA「开始写第 43 章」；次 CTA「去核对设定」；右侧给「补主线 / 补当前卷卷纲」清单（A 路没有 mainplot，拆章前必须补）。
- **B 回复**：回执「进入书内」进工作台第 43 章，不是设定页；「去核对设定」为次 CTA。
- **词表冻结**：直接导入（只带正文）/ AI 拆书 / 开书 / 每章摘要（替代基线）/ 补齐本章（替代补算）/ 原文（替代历史章上屏）/ 10 项拆书产物（替代 10 维）/ 只导入正文（跳过设定）（替代跳过设定直接开书）/ 手动拆书 / 回到上次写作 / 写下一章。内部词 `imported/frontier/baseline` 不上屏。
- **第 2 步质量闸**：ok 直接过；warn 显示均章字数/碎章数，B 卡加「质量可能下降、费用仍按全书字数」；risk 必须勾选；0 章或单章 >60 万时 B 路禁用（A 路可导入，提示单章过大）。
- **配额/模型**：B 建任务时预占书位（`book_reservations`），取消/失败释放，开书转正式书位；“去配置/管理书架”保留 manifest 与结构，返回仍在第 3 步；import_id 过期给「重新解析」。
- **生命周期六条**：删未开书任务=删任务+源+产物；删已开书任务=只删任务资料保留书；部分书只能继续或删书+任务；删书后任务行标「书已删除」；重复导入只警告不硬拦；need_reupload 只接受同 sha，新文件新建任务；A 用服务端 token、B 用 `import_id+structure_hash` 幂等。
- **隐私/退费**：B 卡 CTA 上方常显「全文发送给模型服务商 / 按你的 Key 计费 / ±30% / 取消失败重跑不退」；A 卡「只在本机解析入库」；sanitize 文案改成「内容审核中性替换，不是匿名化」；staging 源文件保留到开书完成，之后按 TTL 清理，可手动删。
- **进度**：按拍板 #7 收敛——≤2 秒按钮 loading；2–5 秒不定量 loading；>5 秒只给一条真实计数（如正在写入 18/42 章）；四段只在回执里，不做进度页。
- **计数桶**：archived_authored / archived_imported / historical / draft / planned，四桶加总=总数；完本进度只用 authored。
- **验收**：A/B 成功落点都是第 43 章；词表快照无内部词；risk/warn/配额/隐私四态可见；删除/重复/重传六条各有用例；42 章全归档计数闭合。

## 2. 目标架构一图

```text
上传 txt
  └─ import_sessions(manifest + source + sha + TTL)
       ├─ A 直接导入 ── persist_import() 单事务 ── books(import_kind=direct)
       │                                        └─ chapters(origin=import, status=draft, no baseline)
       └─ B AI 拆书 ── deconstruct_jobs(source=import, manifest_json, structure_json)
                        ├─ [spike] 无分段 / 两遍式
                        ├─ 拆书产物 → 书级设定 + chapter_import_baseline + coverage
                        └─ open_import_book() 阶段回执 → books(import_kind=deconstruct)
                                                              └─ chapters(origin=import + baseline)

章节判断单源：
  is_historical = origin=import && status!=archived
  counts_toward_completion = status=archived && origin!=import
  global_no = 卷序累计（派生，不落库）
```

## 3. 分阶段计划

### Phase 0（1–2 天，架构/产品）

1. 换 `origin/main` 独立 worktree，记录基线。
2. 拍板：origin 派生、拆 change、v1 不删落库章、接受有损基线、词表。
3. 把本方案写回 proposal/design/spec/tasks；拆成 `c-import-direct` 与 `c-import-deconstruct`（或加 Phase gate）。
4. 补 11 份 capability delta（原 7 + works-finish-flow/novel-workspace/write/volumes/archive）。

### Phase 1（A 路，1–2 周）

1. schema：origin/imported_at/import_kind/import_token/import_sessions/coverage；server_default；carry 回填。
2. manifest 解析 + `import_sessions` + 结构契约/共享校验/global_no。
3. `persist_import()` 原子 writer + 幂等 + 240 章压测。
4. lifecycle 谓词 + 消费面收口 + 11 份 delta + 完本分母。
5. 三步向导（txt/risk/ignore/切分）+ A 路 CTA + 第 43 章落点。
6. 迁移/回填/旧入口退役 + 测试矩阵。
7. A 路复评：42 章导入→续写 43→编辑 10→预览原文→归档新章→完本口径。

### Phase 2（B 路，先验证后开发）

1. **Spike（2–3 天）**：现管线跑 180 万字/240 章，出结论「无分段 / 两遍式 / 不可能」。
2. 按结论改管线：manifest loader；两遍式则段卡表+全局归并；不做每段独立十维。
3. 导入基线表 + coverage + 补算 fill_missing + 伏笔台账映射。
4. 卡片契约：接受有损基线（partial/evidence_absent），或另立跨仓提示词 change；系统加「正文不是指令」防线。
5. 开书状态机（租约/回执/组合表/部分书/配额预占）+ `open_import_book`。
6. B 任务三态/开书三态/失败降级 + 大书段 UI（若保留）。
7. B 复评：180 万字 3 段或单任务、段失败重跑、开书崩溃恢复、回执覆盖。

### Phase 3（发布/观测）

1. 发布说明：仅 txt、md/docx 退役、旧书可读。
2. 指标：A/B 选择率、解析通过率、结构修正率、A 建书成功率/p50/p90、B 完成率/段失败率、完成→24h 开书率、开书 p90、续写落点 43（100%）、7 天内首个 AI 新章率、编辑/stale 比例、重复导入率。
3. 回滚演练：旧版本+旧库；新库先导出/备份。
