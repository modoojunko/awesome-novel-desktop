  • 取舍 / 风险：有效设置一次点击可达（较原弹窗路径更短）；裁撤全局字号 / 行距与摘要开关后，改排版要多走一步（进书 → 本书偏好）、摘要无界面可关（行为默认开、数据层不动）——属「少即是多」的可接受代价；PrefsModal 退役的组件 / 用例 / 原型迁移面见口径节代价清单；退出登录警示调 + 沉底降低误触，轻确认已定案（终审①）。
  • 与 #336 的关系（改写）：状态条版本仍是报障终点、唯一话术（「窗口最下面一行右下角」）；菜单底部版本行标为可选展示（与 #336 同源、只读零交互）——结论：保留。理由：控制中心成为设置唯一入口后，用户截图求助时一张菜单同时可见账号、套餐、版本，工单沟通成本最低，代价仅一行小字；若实测面板纵向过挤，优先裁它，报障职责由 #336 兜底不丢。

推荐（已拍板）：V4' 控制中心面板——头像菜单收编客服与接线审计后保留的设置项，PrefsModal 退役，顶栏右侧只留头像一个入口。「菜单只是轻入口」的旧假设被拍板推翻：设置的唯一入口就是面板本身；冗余项（全局字号 / 行距）经审计裁撤。本节把判断变更摆上台面，并把剩余决策收敛为四项。
  1. 为什么推翻「V4 另开一期」：① 用户直接拍板头像菜单方向——产品判断让位于明确的用户偏好，这是需求不是争议；② 客服收编放大了减法收益：单独收编设置只省一个按钮，客服一并收进后右侧收敛为单一身份入口，「界面更简洁」的诉求从边际改善变成结构改善；③ popover 的组件成本是一次性投入，菜单形态为后续「账号独立页 / 多账号」预留 IA 位置，越早落位越少返工。原判断的保守点（新组件 + 退出登录 IA 风险）已在口径节逐条给出交互纪律与代价清单，风险可控。设置细项并入（本轮拍板）是同一逻辑的延伸——用户要的是更少的容器，不是更多的入口；偏好项即存即效、无「保存」语义，本就不该独占一个 Modal。
