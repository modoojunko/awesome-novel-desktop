# 设计草案：章际衔接向导——检查与修复（c-seam-refill）

> 状态：**设计稿 v3（2026-10-10 收窄范围）**，待拍板立项。**只管一件事：本章开头 ↔ 上一章结尾的衔接**——人物态度、道具状态、重复内容等其他问题不在本功能范围（归检查其他类/后续功能）。
> 交互参照：去 AI 味修改向导（c-deai-wizard #828 四步弹窗）＋ 卷走法三选一抽卡模式。
> 依赖：#832 章际衔接检查（检查能力已实现，feat/chapter-seam-check）＋ 状态域新鲜度（已修）。

## 一、一句话

**「章际衔接」独立功能**：正文页签一个入口，点下去弹窗——第一步展示「本章开头有没有接住上一章结尾」的检查结果；接不上进入第二步，AI 起草 **3 选 1** 的重写方案；第三步**当前开头 vs 新方案**对照取舍；作者确认后落到正文。

## 二、能力内核（知前后、补中间）

起草方案时模型读「前」（上章结尾原文＋状态域四域）与「后」（本章断点之后的既有正文＋章末落点），只重写断点覆盖的段落——两侧原样保留，中间自动长成接住两边的样子。LLM 的条件补全（infill）能力，任务窄、上下文足，对中等模型也友好。

## 三、四步向导（用户拍板的交互）

### 第 1 步 · 检查报告（有问题才继续）
- 复用 #832 的 `chapter_seam` 检查（范围已收窄＝只查开场衔接）：展示 findings——**只报三类**：①另起炉灶（开头与上章结尾的画面/时空/在场人物接不上）②无过渡的时间或场景跳切 ③把上章已写的画面或对话重写一遍。每条附证据对（本章开头原句 vs 上章结尾原句）。
- **无问题＝空态结束**（「与上一章衔接良好」，可关闭）；有问题显示「下一步」。
- 上章无正文（首章）时同样空态结束。

### 第 2 步 · 重写方案三选一（知前后补中间）
- 模型读「前」（上章结尾原文）＋「后」（本章接续段落），起草 **3 版互斥的开头重写方案**（沿用产品三选一抽卡模式）。
- 每版＝**替换开头段的完整新文本**＋一句「这版怎么接」说明（差异轴：如 A＝顺时直承／B＝补一拍过渡再接／C＝换信息顺序），互斥判据同拆章「挪过去就讲不通」。
- 约束：只重写开场段，替换区间之外的正文一个字不动；上章已写的画面不重写；不发明素材外情节。

**等待态（防「以为卡死」，用户拍板：三卡完成后一起出，等的时候必须有活反馈）**：
- 点生成即出**三张骨架卡**（shimmer 微光动效）——一眼知道「会有 3 个方案」，不是空白转圈。
- 阶段文案随已用时间轮换：0-15s「正在读上一章结尾与本章现状…」→ 15-45s「正在起草三种衔接方案…」→ 45s+「好的接法需要一点时间，模型在思考…」（glm 类强制思考模型首卡预计 40-90s，deepseek 15-25s——文案就是管这个预期的）。
- 「已生成 N 字」实时计数（SSE chunk 驱动；只计字数，**不显示原文**——流式片段是 JSON 碎片，展示出来像乱码）。
- 全程可「取消」（AbortController 断流，零残留——draft 不落库）。
- 三版完成：骨架卡替换为方案卡 A/B/C，进入第 3 步对照。失败＝错误态＋重试（重开流）。

### 第 3 步 · 当前 vs 新方案对照取舍
- 左右对照：**当前正文原样** vs **所选方案落位后的效果**（前文灰｜新写段亮｜后文灰）。
- 可切换三版反复比；可「都不满意」→ 回第 2 步重抽（exclude 已否决，同拆章模式）。

### 第 4 步 · 应用落正文
- 作者确认 → 选中文本替换进正文对应区间 → 走既有 prose 保存链（作者确认制，同 c-prose-regen-replace 的确认门禁口径；替换前正文进 ghost 可找回）。
- 应用后提示重跑「章际衔接检查」复检空数组＝闭环。

## 四、范围界定（用户拍板：只管开头衔接）

- **只管「本章开头 ↔ 上一章结尾」这一条缝**：检查只报三类开场断裂；修复只重写开场段。
- 明确不管：人物态度跳变、道具状态断环、重复内容（归检查其他类与后续功能）；金手指/爽点节拍等结构问题（归章纲/卷纲层）。
- 检查能力复用 #832 的 `chapter_seam`（AI 检查 kind 保留，供 API/无向导调用）；向导是它的**产品化外壳**。

## 五、技术落点

- **prompts 仓**：新模板 `seam_refill.prompt`（pro 档建议）——输入：前文（上章结尾原文＋本章前段）／后文（断点后正文＋落点）／断点 findings／状态域／文风；输出：JSON 三版 `{versions:[{text,note}], ranks}`（互斥、两侧原样、状态域硬事实、不发明情节；纪律沿用 polish_text：不硬造人味、人味写法缺省笔法）。
- **C 端**：新端点族 `POST .../write/seam-refill/draft`（三选一，operation=`seam_refill`）＋ `POST .../write/seam-refill/apply`（前端回传替换区间与文本，走 prose 保存链）；向导弹窗组件照 #828 四步形态；门控＝ai-generate（PRO＋本书模型）。
- **前端**：正文页签入口行改「章际衔接」向导入口（替换现「章际衔接检查」直查行；#832 的 ai_check kind 保留供 API）。

## 六、验收草案

1. 构造断点：第 1 步报出；第 2 步三版互斥（挪用判据）且替换区间外逐字不变；第 3 步对照正确；应用后正文正确、复检空数组。
2. 首章/上章无正文：第 1 步空态直接结束。
3. 「都不满意」重抽 exclude 生效；应用后旧正文可从 ghost/版本历史找回。
4. 三版与「当前」四方对照：模型只在替换区间内产出。

## 八、技术落地方案（双评审定稿：提示词工程师＋后端架构师，2026-10-10）

### 8.1 核心技术裁决：两侧原样＝提示词成块注入＋代码拼接，不依赖 API 原生补全

anysearch 调研结论：GLM（open.bigmodel.cn）chat 接口**无**前缀续写/后缀参数；DeepSeek 前缀续写是 beta 且只保前侧（尾缝无保证）、FIM 在 completions 端点无 system/user 角色与 JSON mode——均与本书模型路由（作者级配置任意端点）冲突。**裁决**：模型只产中间段；「两侧原样」由 apply 时代码拼接构造性保证（模型从头接触不到两侧）。防漂移三件套：①前后文哨兵块注入＋接缝铁律；②`before_echo/after_echo` 凭证（各 ≤20 字原句照抄，attention 锚＋「读到缝」的廉价判据）；③后端字符串校验链（无边界标记/句界收尾/与两侧 ≥15 字公共子串判负/echo 错重试一次）。语义级换说法复述由「应用后重跑 chapter_seam 复检」兜底。

### 8.2 输出契约（终稿）

```json
{"before_echo": "≤20字前文末句照抄", "after_echo": "≤20字后文首句照抄",
 "versions": [
  {"approach": "直承", "text": "…2-6段…", "note": "这版怎么接，≤30字"},
  {"approach": "过渡", "text": "…", "note": "…"},
  {"approach": "重排", "text": "…", "note": "…"}]}
```

- **去掉 ranks**：缝修复只有「接上/没接上」二元判据，名次会诱导三版磨平差异；**approach 是闭集机判字段**（后端断言集合=={直承,过渡,重排}）。
- 三版差异轴（互斥判据特化为「对断口交代了什么的讲法互斥」——拆章判据在缝修复不成立）：直承＝不补桥，上一拍下一瞬直接写；过渡＝先用状态域允许的时间流逝/移动/过场垫一拍再接；重排＝从后文首句需要的东西起笔，前文悬事当既成事实半途带过（不是倒叙重演——那是三类病之一）。
- 模板渲染用 `<<before>>/<<after>>/<<finding>>/<<rejected>>/<<story_state>>/<<style>>` 顺序 replace（正文含 JSON 花括号，禁 str.format——chapter_split 先例）；`<<rejected>>`＝重抽已否决方案注入（v3 漏项）。
- **被替换的旧开场原文必须进输入**（标注「病文，禁止效仿」）：后文首段的指涉是对着旧开场写的——旧开场引出的人/物/话头，新中间段必须重新自然带出（v3 完全没提的最隐蔽坑）。

### 8.3 端点与数据安全（终稿）

- **唯一新端点**：`POST .../write/seam-refill/draft`——**SSE 流式**（非流式 90s read 必炸：glm 强制思考＋三版输出；流式 read=120s 是事件间隔）；ai-generate 门控＋`seam_refill_draft(_fail)` 计费；**draft 不落库**（关弹窗即弃，零残留）。
- **apply 不设端点**：前端单事务替换（照 PolishWizard `applyParagraphEdits`：段号＋folded 锚文全等校验，漂移即拒整批；一次 `run()` 单撤销单元）→ 双写 store＋显式 `await store.flush()` → 既有 `PUT /chapters/{ref}/prose` 链（frontier 门禁、版本快照 ≤50/章＝找回路径）。**不建 ghost**（ghost 是整章重写归档语义，段落替换建 ghost 会污染支线统计）——修正 v2「进 ghost」写法。
- 素材窗口：上章结尾 ≤800（复用 PREV_TAIL 单源）＋断点前段 ≤1200（截尾）＋断点后 ≤2000（句界取头）＋落点 ≤200＋状态域＋findings 回传；总盘 ≈8k tokens。`para_count ≤6`；门控 409：首章/无正文/ghost 章。
- 三选一互斥：**单调用流式**（三次各出一案否决——互斥性退化且 3× token）；策略分工写进 system（直承/过渡/重排各占一轴）；不传 temperature（全族口径）。

### 8.4 已知边界与残留风险

- echo 校验抓不住语义级换说法复述→复检兜底（双层）。
- 三版互斥对采样温度敏感：低温趋同风险，上线前生产端点实测调参（假设待验）。
- 正式包用户随下个提示词包＋C端发版获得；5274 dev 直挂即时验证。
