- 触发词：轻量开书 / 双路径 / 快速出正文 / 开书弹窗

## 0. 一句话

开书后一个弹窗让作者选两条路之一：**「我要快速出正文看效果」**（一句话 → AI 起草三卡：简介/主角/开篇背景 → 直接拆卷拆章写第一章）或 **「我要仔细配置全书设置」**（现有 7 项设定流程原样）；两条路只在第 1 章开写前分叉，第 2 章起完全收敛——设定随写作自动沉淀。

## 1. 背景与问题

大量用户反馈：开书后要设定 7 大项、再拆卷拆章，才体验到 AI 写文，直接劝退。要求评估并给轻量流程。

**病灶诊断（实勘后纠正直觉）**：7 项设定今天**没有任何硬门禁**——拆卷/拆章/章纲/写正文全部放行（`workflow/gates.py:26` 恒 `hard_block=False`，产品决策原文「Creation does NOT judge settings completion」）。劝退来自两件事：

1. **表象工作量**：OnboardingCard 六段时间线、modnav「设定 n/7」进度、逐项「确认完成」制、7 项全确认才出现「去写作」CTA（`SettingsView.tsx:738`）——把设定呈现成开书前置任务；
2. **空设定的隐性质量惩罚**：AI 生成确实吃设定素材，空着写出来的第一章质量差，用户更不敢跳过——自我强化的劝退环。

所以轻量化 = **把必做收窄 + 让设定随写作自动长出来**，不是拆门禁（无门禁可拆）。

## 2. 节点链模型（本设计的底层口径，用户 2026-10-09 定调）

```
0 号节点（初始设定）→ 1 号节点（第 1 章）→ 2 号节点（第 2 章）→ …
每个节点挂：设定、角色、关系、物品、认知、伏笔动作、正文……
生成第 n 章 = 0 号节点 + 折叠(1..n−1) + 第 n 章章纲
```

与现有实现高度吻合，**是口径不是重构令，表结构不动**：

- N 号节点 = 章节 + 章档四域行（设定变化/关系/物品/认知，带证据句，`archive/dossier.py`）；
- 「折叠(1..n−1)」= `story_state_upto`（`write/story_state.py:53`），喂下一章「故事状态（截至上章）」——**「第 2 章用第 1 章的设定、背景、角色」今天已经在跑**；
- 0 号节点 = 书级设定（story.yaml / world-setting.yaml / characters 表 / novel_genre / novel_hooks…）；
- 提示词组装（`write/chapter_writer.py:919 build_chapter_context`）= system 层渲染 0 号节点静态块 + user 层渲染折叠态与本章。

三条设计结论由模型直接得出：

1. **两条路线只是 0 号节点初始化方式不同**：专家版 = 填满 0 号节点再开写；快速版 = 0 号节点只填三样，其余属性由 1 号、2 号……节点归档提取逐级挂上链。1 号节点之后数据与提示词完全同构。
2. **回填方向 = 变化挂发生的节点，0 号节点是作者显式设定的锚，不被悄悄改写**（现架构即此立场）。缺的是 **rollup 视图**（如人物档案从各节点关系/认知行归并「当前态」），不是新增写回通道去重写人物卡。
3. **提示词组装 = 节点渲染**：任何 AI 调用表述为「0 号节点切片 + 折叠到当前节点」。现存素材裁剪差异（拆章不给伏笔、拆卷 options 不给铁律等口径缝隙）在该模型下即「按调用类型选切片」，便于统一与审计。

## 3. 产品事实（设计边界，均已实勘）

1. **真闸只有三处**：拆卷需主线非空（`volumes/ai_plan.py:571` 422，快速路径三卡含主线起步 → 自动满足）；拆章需卷纲三问（`chapters/ai_plan.py:554`，流程内自洽）；写正文需 API Key/模型（503）＋档位（ai-generate = PRO）。
2. **settings-ai 能力齐备可编排**：一句话→书元信息（`novels/router.py:146 suggest-meta`）、从简介立主角（`characters_ai.py:467 bootstrap`）、简介→主线（`settings/ai_router.py:1081 arc_draft`）、世界骨架（`:610 world_draft`）、题材五格（`:2064`）——全是散在 7 面板右栏的手动入口，缺聚合编排。
3. **归档提取已有一半**：四域提取（设定/关系/物品/认知）落章级、作者采纳制、折叠回流下一章；书级回填仅「伏笔登记/世界要素」两条 reconcile 通道（`archive/reconcile.py:32`）；**人物档案、文风零回填**。
4. **`ai_backfill` 现成**（`novels/ai_backfill.py`，今定位=导入书/存量书补救）：从正文反推简介/世界/角色/文风——即「归档后增量沉淀」的复用底座。
5. **档位口径**：settings-ai = 标准档起；ai-generate = PRO；文风蒸馏 = MAX。免费档点「快速」会退化成手填三卡，耗时标注须给区间并标前提。
6. **提示词模板已迁出主仓**（awesome-novel-prompts 仓 + 发布链）：三卡起草大概率要新增模板 = 跨仓改动。

## 4. 开书弹窗规格（原型屏 1）

创建书名后立刻弹（建书表单仍只问书名），标题「这本书想怎么开始？」，两张选项卡，各三行信息：

**卡 1「我要快速出正文看效果」**（主位，意图措辞非水平措辞）
- 流程条：`一句话简介 → AI 起草三卡（简介/主角/开篇背景）确认 → 拆卷拆章 → 写出第一章`
- 耗时：`约 20–30 分钟看到第一章`（小字：已配模型；首次配 Key 约 +5 分钟）
- 产出：`最快见稿；设定边写边长，随时可补`

**卡 2「我要仔细配置全书设置」**
- 流程条：`逐项搭设定 ×7（简介/题材/世界/角色/主线/文风/伏笔）→ 拆卷拆章 → 写出第一章`
- 耗时：`约 1–2 小时开写`（小字：每项都有 AI 辅助，纯手填取上限）
- 产出：`开写前地基最全，第一章素材最足`

**两卡下方共用收敛行**：`第 2 章起两条路完全一样——设定随写作自动沉淀，写第 2 章时自动带上第 1 章的设定、背景、角色变化。`流程条终点对齐画成同一个「写出第一章」，视觉表达收敛。

执行细节：耗时给区间不给点值、标前提（是否已配 Key/档位），初版保守偏大、上线后埋点校准；流程条用步骤 chip 不用真图形；两卡同一样式对齐。

**三条护栏**：①随时可逆——设定页/写作页留切换入口，切换不清数据；②不锁功能——可记 `onboarding_path` 埋点/文案，但不参与任何权限判断；③三卡起草出卡确认（AiCardModal 采纳制），不直接落库。

## 5. 能力清单与分期（弹窗只是分流器，工程量在后面）

**一期（用户可见价值全在这）**
1. 开书弹窗（两卡+流程条+耗时+埋点）——纯前端，最小件；
2. 三卡起草流水——编排既有 settings-ai 能力 + 落库映射（简介→story.yaml.synopsis、主角→characters 表、开篇背景→world-setting.yaml 骨架 + story_arc；**不新造「开篇背景」对象**）+ 新增提示词模板（跨仓）；
3. 配模型引导收编为快速路径第一步（接既有「配模型引导」草案）；
4. 专家路径加「先跳过，直接去写」常驻出口（废「7 项全确认才出 CTA」）；
5. 双向切换入口。

**二期（成长闭环，承重墙）**
6. 归档 rollup：人物档案「当前态」视图（由各节点关系/认知行归并）+ `ai_backfill` 提级为归档链自动增量、出卡确认；设定生长可视化（「本书设定正在生长 n 条」）。

**三期**
7. 文风攒样回收（攒够样本主动请蒸馏，MAX 口径过档位）；伏笔「该收了」提醒强化（不承诺自动长出规划）。
