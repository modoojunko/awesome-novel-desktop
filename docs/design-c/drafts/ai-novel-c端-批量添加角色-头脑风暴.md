## 一、现状（事实盘点）

- 建卡只有一条路：设置页「添加角色」按钮建一张**空名卡**，再在右栏就地编辑、逐格自动保存
  （`CharacterManager.tsx:406-420`）。要立 10 个龙套就得点 10 次按钮、切 10 次卡。
- 后端建卡端点 `POST /api/novels/{pid}/characters`（`character_service.py:224-291`）
  实际只收 `name + role + persona + prefill{plot, background}`（白名单外 400）。
  八格、认知 30 格都不是建卡必填——门禁六项（name/persona/plot/w5/p3/p4）只在「确认」时查
  （`character_model.py:143-151`）。
- 重名硬约束 `UNIQUE(novel_id, name)`，撞名 409（`models/character.py:43`）；每书至多一位主角
  （部分唯一索引 :45-50）。
- 列表左栏按角色类型分组，组内顺序固定创建序（`order_by(seq)`，`character_service.py:185`）；
  搜索只搜名字+别名，且收起的分组里搜到也看不见（隐藏缺陷）。
- 列表接口一次给全每张卡全部字段（`list_characters` → `card_to_dict`）。

## 二、方案：下载模版 → 填好 → 上传导入（唯一路径）

### 入口

角色列表顶部「添加角色」旁加「批量添加」，弹窗三步：**下载模版 →（Excel/WPS 里填）→ 选择文件导入**
→ 解析预览（行内可改可删、重名跳过、主角标红）→ 建卡。

### 模版与导入

1. **下载模版**：点「下载模版(.xlsx)」拿到固定格式表格，两个 sheet：
   - **「角色」**：第一行列头（固定中文，见下表），从第二行起一行一个角色；
   - **「填写说明」**：字段说明＋完整示例＋规则（一行一个；类型四选一；别名用 `·` 分隔；
     只填名字也行；重名会跳过；导入前删掉示例行）。
2. **填表**：作家自己填；填不动可以让 AI 照列头帮着填，粘回表格再导入。
3. **导入**：点「选择文件」→ 前端解析 → 预览表格 → 确认建卡。

**模版列头（字段全集＝导入面）**：

| 列头（中文／导入兼容英文） | 必填 | 落到 |
|---|---|---|
| 名字／`name` | ✅ | `name`（书内唯一，重名跳过） |
| 类型／`role` | | `role`：主角/配角/反派/路人；不填或非法＝默认配角 |
| 一句话人设／`persona` | | `persona`（clamp 300） |
| 别名（用·分隔）／`aliases` | | `aliases`，随卡带入、参与名字解析 |
| 性别／`gender`、年龄／`age`、种族／`race` | | `dossier.gender / age / race` |
| 势力·身份／`faction`、外貌标签／`look`、语言特征／`speech` | | `dossier.faction / look / speech` |
| 背景／`background`、剧情定位／`plot` | | `dossier.background / plot` |

- 列头中英文都认（列顺序无关、多列忽略）：模版导出＝中文列头（作家母语）；
  导入解析同时认英文键（`name/role/persona/aliases/gender/age/race/faction/look/speech/background/plot`，
  供 AI 生成或英文习惯的文件）；未知列忽略不报错。**认知 30 格不进导入**（建完用「一键立卡」补）。
- 解析器：真实现用 SheetJS 读 xlsx（CSV 也顺手支持，加 BOM 防 Excel 中文乱码）；
  原型阶段用 CSV 演示同一套交互。
- **示例行防呆**：模版里的示例行名字以「示例-」开头，解析时标黄「示例行，不导入」，
  确认按钮不计数——作家忘删也建不出垃圾卡。
- **说明同屏可得**：弹窗内置「字段怎么填？」折叠块（默认收起，展开为可滚动表格），
  内容＝说明 sheet 的同一份文案——不下载模版也能在页面上看到每个字段填什么。
  实现时两处共用同一份文案源（常量/JSON），避免双处漂移。

**「填写说明」sheet 定稿文案**（真实现逐字进 xlsx；每字段一行，三列：字段／填什么／示例）：

| 字段 | 填什么 | 示例 |
|---|---|---|
| 名字* | 必填，书内唯一（重名会跳过）。只写称呼本身，称号昵称放「别名」 | 苏晚 |
| 类型 | 四选一：主角 / 配角 / 反派 / 路人。不填默认配角；主角全书只能一位 | 配角 |
| 一句话人设 | 此人是谁、凭什么是他——一句 60 字内最好（上限 300）。每章都会带进 AI 上下文，写「身份＋特质＋关系钩子」 | 北岭号二副，灯语专家，陆沉的旧识 |
| 别名（用·分隔） | 称呼变体：昵称、称号、职衔，用 · 隔开。AI 靠它认出「二副」「窈姐」都是同一人 | 老柳·二副 |
| 性别 | 照实填，可留空 | 女 |
| 年龄 | 数字或概数都行 | 31；约四十 |
| 种族 | 照设定填，可留空 | 人类；妖；机械体 |
| 势力·身份 | 所属组织＋职位，用 · 分隔；无组织写身份即可 | 北岭号 · 二副；渡口船家 |
| 外貌标签 | 2~4 个短语，标签化，别写成散文 | 瘦长个 · 旧道袍 |
| 语言特征 | 说话习惯、口吻、口头禅 | 话少 · 命令句式；嗓门大 · 爱哼船歌 |
| 背景 | 出身与来路，一两句（上限 300） | 在货运航线跑了六年，上个月才转到拾荒船。 |
| 剧情定位 | 这个人在故事里干什么、承担什么功能（主角必填） | 守着锅炉，也守着一个关于沉船的秘密 |

通用三条（写在说明 sheet 末尾）：①只有名字是必填，其余都可以留空、建完在角色设定里补；
②一格一句，别在格子里换行；③类型不填默认配角，反派路人也要填类型（AI 写章按类型分量）。

### 预览与落库

- 预览行内可改名字/类型/人设、可删行；带别名/档案的行标「将新建 · 别名×2 · 含档案」。
- 重名（库内/批内）→ 黄条「已有同名，跳过——已有卡的设定不会被改动」（不覆盖不合并，
  重复导入幂等）；批内选多个主角 → 标红「每书一位主角」。
- **落库＝扩既有建卡端点**（评审 P0 整改，见「七」）：`POST characters` 载荷增加可选
  `aliases` 与 `dossier`（白名单严格取八格、逐格 clamp），单事务原子建卡，每卡恰 1 个请求。
- 建完 toast：「已建 N 张卡 · 跳过 M」＋**「撤销本次全部」**（前端循环调既有 DELETE，
  自带单卡撤销）；新卡落列表末尾，建完自动选中第一张新卡。

## 三、刻意不做的

| 不做 | 理由 |
|---|---|
| JSON 粘贴入口 | 用户拍板（2026-10-09 四轮）：填表才是作家母语，一个弹窗一条路；AI 生成场景＝让 AI 照列头填，粘回表格 |
| Word/PDF 模版 | 解析不可控；表格才是结构化填写的正形 |
| CSV 单格式作为唯一模版 | Excel 直接开 CSV 中文易乱码；真实现 xlsx 为主、CSV 只作解析兜底 |
| 认知 30 格进模版 | 字段面太大，批量填不动；建完逐卡补或「一键立卡」 |
| 模版里做下拉/数据校验 | 依赖作家开启宏/校验的不可控性；类型不填＝默认配角已兜住空值，非法类型回落配角 |
| 弹窗「本次默认角色类型」选择器 | 用户拍板（2026-10-09 五轮）：导入的是文件，类型就在模版「类型」列里定义，弹窗不再有默认类型概念 |
| 拖到别的分组＝改角色类型 | 一个手势改语义数据太危险，还有「每书一位主角」的雷 |

## 四、二期备忘

1. **重名行→更新已有卡（只补空格）**：语义复用 AI 采纳的「只补空格，写过的字不动」先例；
   触发信号＝跳过率阈值（评审建议）。
2. **多选批量「一键立卡」**：解批量导入后的门禁缺口债（见「八-②」）。
3. 搜索语义词扩容（人设/势力/背景）＋命中高亮＋拼音首字母（数据都在列表载荷里，纯前端）。
4. 模版「下载」也提供 CSV 备选（仅当 xlsx 生成在打包链有坑时启用）。

## 五、验收口径（v2）

- 下载模版 → 填 4 行（全字段/最小/纯名字/重名）→ 导入 → 预览逐行正确；示例行标黄不计数。
- 列乱序、多空白列、英文列头的文件照常解析；未知列忽略。
- 建卡后：别名落别名栏、八格落基础档案、类型/人设正确；新卡在列表末尾、自动选中第一张。
- 弹窗「字段怎么填？」展开后的内容与模版「填写说明」sheet 逐字一致（同一文案源）。
- 「撤销本次全部」一键清掉本批建的卡（含档案与关系），列表恢复导入前状态。
- 重复导入同一份文件幂等（第二次全跳过）；非 .xlsx/.csv 文件给明确报错。
- 拖拽/搜索口径见姊妹篇方案稿的验收节。

## 六、原型口径（本仓库演示用）

原型弹窗为单路径：「下载模版」生成带 BOM 的 CSV（免依赖；真实现换 SheetJS 出 xlsx），
「选择文件」解析后填充预览，示例行防呆、重名/主角校验、建卡/撤销齐全。

## 七、评审整改（2026-10-09 三路评审已吸收）

- **[P0] 写入路径**：放弃「前端循环 create+逐格 PATCH」（每卡 ≈10 请求、半途失败后重贴被
  重名 409 挡死），改为扩 create 载荷 `aliases + dossier`（白名单八格、单事务原子）。
  `PREFILL_KEYS` 不动，向后兼容。
- **[P0] 批量撤销**：create 本无撤销回执（CharacterOp 只有 delete/merge）——「白拿现成」说法作废；
  改为前端收集本批 id，toast「撤销本次全部」循环调既有 DELETE。
- **[P1] 拖拽排序范围重定性**：它不是纯前端功能——每次自动保存后 `reloadList` 会把本地顺序打回
  创建序。立项范围必须含后端三件套：characters 加可空 `sort_rank` 列（走整库迁移通道，存量用户
  升级触发一次迁移，成本写进立项书）＋ `PUT /characters/order`（全量 id 数组、子集语义、未知/跨书
  id 400、单事务不 bump rev、路由静态段声明在 `/{id}` 前）＋ list 读路径
  `ORDER BY sort_rank IS NULL, sort_rank, seq`。失败语义：回退视觉顺序＋toast；连续拖拽合并提交
  （串行队列只留最新数组）；与 reloadList 的回弹竞态用「本地 rank 优先」解。
- **[P1] 提示词顺序防泄漏**：list 顺序改了会带进写章提示词的角色锚
  （`chapter_writer.py` 直接消费 list）——writer 内按 seq 显式重排（一行），钉进测试。
- **[P2] 已采纳**：备份往返带 `sort_rank`（提前到同变更集，约 4 行）；服务端 clamp
  （name[:50]、alias ≤20 条各[:50]、dossier 各格[:300]）＋弹窗 100 行上限；重名跳过文案说满
  「已有卡的设定不会被改动」；分组开关按书记忆（localStorage）；弹窗误触关需确认或保留草稿；
  order 失败回退＋验收补「失败时 UI 行为」；搜索零结果率埋点挂二期触发；前端拆
  `BatchAddModal`＋`characterImport.ts`＋列表面板（CharacterManager 已 1228 行）；把手
  `aria-hidden` 防 e2e accessible name 失配；React 转写时拖拽视觉态进状态不直改 DOM。

## 八、待拍板（评审提出，未定）

1. **重名行→更新已有卡（只补空格）**是否按触发信号立项二期（当前 v1＝只跳过＋文案说满）。
2. **多选批量「一键立卡」**是否提前进 v1——批量导入 20 张 ≈ 60 个门禁缺口、确认存档作废，
   不给出口的话再确认成本很高；提前的代价是 v1 范围＋1。
3. 批量撤销「前端循环 DELETE」是否够用（备选＝后端把一次批量记为单个 op，要动 CharacterOp）。
