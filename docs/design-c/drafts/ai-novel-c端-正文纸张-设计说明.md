## 1. 一句话

正文页从「一整列白」变成**三层**：外圈是桌面，中间一张纸，纸上用一圈极淡的虚线框标出真正写字的那 680px（虚线框只在编辑态出现）。

## 2. 为什么现在做

现在正文区的实际几何（真机实测，见 `prose-paper-captures/metrics.json`）：

| 量 | 值 | 说明 |
|---|---|---|
| 正文列 `.col-editor` | 860px | 三栏布局里的中列 |
| 滚动区 `.editor-wrap` | 860 × 542 | 底色透明 → 透出列底 `--bg`（oklch 98%） |
| 版心 `.editor` | **680px** | `max-width`，两侧各 90px 空白 |
| 行高 | 34px | 17px × 2.0 |
| 编辑态底色 | `--surface`（纯白） | 与 `--bg`（98% 白）几乎同色 |

结果就是：**纸、写字范围、桌面三件事全看不见**——整列一片白，只有文字浮在上面。写字的人没法判断「还有多少余量」「这行会不会写到边」，长章滚起来也没有"翻页"的空间参照。

写作软件里这件事有成熟答案（Word 的页面视图）：**桌面（暗）→ 纸（亮）→ 版心（写字范围框）**，三层之间靠明度差和一条投影分层，不靠线框。

## 3. 原型怎么看

**2026-10-22 拍板后，原型只保留确定形态：A 连续纸 ＋ 白纸。** 演示条剩两个组（**非产品 UI**）：

| 组 | 选项 | 看什么 |
|---|---|---|
| 状态 | 阅读态 / 编辑态 | 虚线框只在编辑态出现；两种宿主都是从真机抓的同一个页面 |
| 视野 | 标准 / 专注 | 专注＝点界面右上角真实的「专注模式」按钮（`body.focus` 既有机制），侧栏收起后桌面变宽，最接近 Word 的一屏 |

界面上那个真实的 **专注模式按钮**（⛶）在原型里是可点的，和演示条的「视野」联动——原型不是一张死图。

## 4. 设计结论

### 4.1 三层几何（推荐值，已按真机数值算过）

```
┌─ .editor-wrap ───────────────────── 860（桌面，oklch 94.2%）───────────────┐
│ 36px                                                                      │
│   ┌─ .prose-paper ────────────────────────────────── 808 ─────────────┐   │
│   │ 56px                                                              │   │
│   │   ┌─ 写字范围 680（.editor）──────────────────────────┐           │   │
│   │   │ 写字范围框：1px 虚线，只在编辑态画                   │           │   │
│   │   └──────────────────────────────────────────────────┘           │   │
│   │ 64px                        ← 纸边距 →                        64px │   │
│   │ 72px                                                              │   │
│   └───────────────────────────────────────────────────────────────────┘   │
│ 56px                                                                      │
└───────────────────────────────────────────────────────────────────────────┘
     ↑ 左右各 26px 桌面（1440 三栏态）；专注态左右各 316px
```

| 项 | 值 | 为什么是这个数 |
|---|---|---|
| 纸宽 | 680 + 2×**64** = **808**（上限）；两侧永远留 ≥ **12px** 桌面 | 必须 ≤ 列宽，且纸不能贴满整列——贴着列边就不像纸了 |
| 纸边距 左右 | **64px**（宽屏）；列不够时**先挤纸边距，最后才挤版心** | 硬下限 56：人味边注 `.zq-mark` 在 `left:-46px`，朱雀标小旗也住在版心外 |
| 纸边距 上／下 | 56 / 72 | 上边距＝首行到纸边；下边距比上多 16，避免末行贴边 |
| 桌面外间隙 | 上 36 / 下 56 | 滚动到顶/底时能看见纸的上下边 |
| 纸边 | **1px inset 阴影**，不是 `border` | `border` 会吃掉 2px 内容宽，版心就从 680 变 678（原型第一版踩过，自检第 ⑥ 项现在钉死这条） |
| 纸投影 | 1px 贴地 + 18/44 软影 | 只往右下压一点，纸才"浮"在桌上 |
| 写字范围框 | **1px 虚线，18% 灰，只在编辑态画**（阅读态整框隐藏） | Word「文字边界」的意思：写字的人看得见范围，读的人看不见装饰 |

**窄列的退化顺序（已实测）**：1920/1440 → 纸 808＋桌面 26；1280（列 700）→ 纸 676、纸边距 0、桌面 12、**版心仍 680**；1024（列 494）→ 纸 470、版心 470。
取舍是明确的：**先保版心，再保纸边距，最后保桌面缝**——写字的人最在意行宽。

顺带一个**会被看见的副作用**（同一套页面实测，未上纸 vs 上纸）：

| 窗口宽 | 列宽 | 今天版心 | 上纸后版心 |
|---|---|---|---|
| 1920 | 1340 | 680 | 680 |
| 1440 | 860 | 680 | 680 |
| 1280 | 700 | **556** | **676** |
| 1024 | 494 | **371** | **470** |

原因：今天 `.editor-wrap` 的 `padding-inline: clamp(24px, 6vw, 72px)` 在窄屏吃掉的比纸边距更多。上纸后**窄屏行宽变宽**（更接近设计常量 680）。这不是白拿的：行宽变化会改变阅读节奏，验收时要按 1280 单独看一眼，不能只看 1440。

> 所有颜色只用 `oklch()` / `color-mix()` / 既有 token，没有裸色值（自检第 ④ 项）。

### 4.2 三个变体（**已拍板 A**；B/C 留档备查）

| | A 连续纸（**推荐**） | B 固定纸 | C 只标范围 |
|---|---|---|---|
| 观感 | 纸随内容长，滚的是整张纸；长章里只看得见左右桌面 | 纸钉在视口，上下纸边常驻，文在纸内滚；长章也一直像一页 | 不上纸面；桌面 + 680 宽的一列浅底 + 编辑态虚线框 |
| 长章滚动 | 纸边跟着走（像 Word 的连续页） | 纸边不动，文字在纸里滚（滚动条挪到纸上） | 同 A |
| 实现成本 | 中：加一层 `.prose-paper` 包裹 | **高**：滚动容器要从 `.editor-wrap` 挪进纸里 | **低**：只改背景 + 一个虚线框 |
| 对现有代码的冲击 | 滚动仍在 `.editor-wrap`，`wrapRef`/`resumeScroll`/「滚到底自动续」全部照旧 | 会打断 `wrapRef` 语义、`free-writing-flow.spec.ts` 的 `wrap.scrollTop = scrollHeight`、思考面板锚尾滚动等一串依赖 | 最小 |
| 适合 | 默认 | 很长的章、想一直看到"一页"的边界 | 只想解决"看不出写字范围"，不想动版式 |

**2026-10-22 拍板：A 连续纸。** 它拿到 Word 的纸面感，同时**不碰滚动容器**（`wrapRef`/`resumeScroll`/贴底自动滚全照旧）——这是 B 最贵的隐性成本。B/C 两列只作为决策留档，原型里已移除。

### 4.3 纸色（**已拍板白纸**）

**2026-10-22 拍板：纸色固定为白纸** `oklch(100% 0 0)`（＝现有 `--surface`），不做纸色偏好。桌面恒中性灰，图层关系因此只有一条明度轴：桌面 94.2% → 纸 100%。

米黄（`oklch(97.6% 0.014 88)`）作为备选留档：它只影响纸面与纸边、不影响桌面与侧栏；若以后要开纸色偏好，加一个 `data-paper` 开关即可，不必改版式。

### 4.4 与既有特性的关系（都要在实现时逐条验）

| 特性 | 关系 | 结论 |
|---|---|---|
| 生成等待行 `.gen-line` | 原本 `absolute; top:36px` **硬编码了 `.editor-wrap` 的内边距** | 上纸后它随内容一起进纸，`top` 改成 `var(--pp-pt)`（纸的上内边距）；`36px` 这个魔数就此消失。这条是隐性耦合，改 `top` 必须同批 |
| 思考面板/回看/超时卡 `.tk-*` | `max-width: 680; margin:auto`，挂在 `.editor-wrap` 下 | 它们属于**纸内容**，应随正文一起进 `.prose-paper`（否则面板浮在桌面上） |
| 呼吸灯 `.prose-body.generating` | `box-shadow` 环绕「工具行＋正文区整列」 | 现在会把桌面也罩进去；建议实现时环到 `.prose-paper` 上（视觉上只亮纸） |
| 人味边注 `.zq-mark`（left:-46px） | 住在版心左侧空白里 | 纸边距 64 容得下；**纸边距不得低于 56** |
| 朱雀行底色带 `.zq-warn/.zq-err` | 每条 `<p>` 上的 repeating 渐变，跟行高 `--zq-lh` 同源 | 不受影响（画在字上，不画在纸上） |
| 专注模式 `body.focus` | `.editor-wrap { padding-inline: 8vw }` | 纸自己居中，padding 不影响；专注态桌面自动变宽，观感最好 |
| 编辑工具行 `.ol-top.edit-bar` | 现状是与正文**连体**的「一个控件」（上圆角条＋下圆角内容区、同为 `--surface`、无下边框） | 上纸后必须解耦：工具留在列头，纸是内容。原型里工具行改成通栏条＋下边框 |
| `.editor-status`（字数/已保存） | `--surface` 底 | 改成桌面底——这是"桌面级的账"，不挂在纸上 |
| 空章 | `.editor` 为空 → 纸只有上下内边距那么高 | 见 §7 待拍板 |

### 4.5 明确不做的

- **不做真分页**（按页切开、跨页断行）。正文是连续纯文本，分页要动数据与流式写入，收益远小于成本。B 是"一页的错觉"，不是分页。
- **不做标尺/页边距拖拽**。Word 有，但这里版心是设计常量 680（`design-language` 的阅读行宽），不是用户可调参数。
- **不做纸张纹理/噪点**。与现有 oklch 扁平底座冲突，且在低分辨率屏上会脏。
- **不改版心 680 与行高**。上纸只改"纸和桌面"，不改"字"。

## 5. 落地改动清单（拍板 A + 白纸）

1. **组件**（`ProsePane.tsx`）：`.editor-wrap` 内加一层 `<div className="prose-paper">`，把 `.gen-line`、`.tk-*`、`EditorContent` 一起包进去；`wrapRef` 仍挂 `.editor-wrap`（滚动容器不变）。
2. **样式**（`design/book.css`）：
   - 新增令牌：`--paper-desk / --paper-bg / --paper-edge / --paper-lift / --paper-guide / --paper-pad-x/y-top/y-bottom / --measure`；
   - `.editor-wrap`：去 `padding-inline`、换桌面底；`.editor-wrap.editing`：去连体边框/圆角/`--surface` 底；
   - 新增 `.prose-paper` ＋ 一个装饰节点 `.prose-frame`（`position:absolute; border:1px dashed`，`pointer-events:none`；位置与纸边距同源，都由 `clamp(0px, (100% - 680px)/2, 64px)` 算出——注意同一个式子用在 padding 上按「列宽」解析、用在 `inset` 上按「纸宽」解析，这正是纸满列与纸窄于列两种情形都能对上的原因）；阅读态用一条 `:not(.editing)` 规则把整框藏掉；
   - `.ol-top.edit-bar` 解耦、`.editor-status` 换桌面底、`.gen-line` 的 `top` 换 `var(--pp-pt)`（顺手删掉 36px 魔数）。
3. **原型基线**：`docs/design-c/prototypes/book.html` 同批改（否则 `design:check` 的 book parity 必红），并在 `prototypes/ADJUSTMENTS.md` 登记"正文区上纸"这一条。
4. **自检**：`npm run design:lint` + `design:check`；e2e 至少跑 `free-writing-flow`（`.editor-wrap` 滚动）与 `design-parity-book`。

## 6. 风险 / 回归面

- **parity 必红**：`design-parity-book.spec.ts` 用 `prototypes/book.html` 逐像素比对正文区。这是**预期内**的，实现 PR 必须同批更新原型 + ADJUSTMENTS，不能靠调阈值过。
- **滚动**：A 方案滚动仍在 `.editor-wrap`，`resumeScroll`（`scrollTop/scrollHeight`）、"贴底自动滚"都照旧。**B 方案会动这些，属于隐性地雷**。
- **横向溢出**：纸宽 808 + 桌面必须 ≤ 列宽。纸宽写 `min(808px, 100% - 24px)`，纸边距用 `clamp()` 自适应；1280/1024 两档实测 `scrollWidth - clientWidth = 0`（`proto-shots/geometry.json`）。
- **窄列的边注**：列宽不足时纸边距会被压到 0，此时 `.zq-mark`（`left:-46px`）会压到纸边/桌面上。实现时把边注偏移改成 `min(46px, 纸边距)`，或只在纸边距 ≥56 的宽屏显示边注。
- **生成期**：等待行、思考面板、呼吸灯的定位都跟着包裹层走，**必须一起验**（这四个是 `c-prose-gen-phases` / `c-thinking-display` 两个已上线 change 的成果，不能回退）。
- **`.editor-wrap` 的 padding 是个隐性契约**：`gen-line top:36px`、`body.focus` 的 `8vw` 都建立在它上面。删 padding 时两处都要同批改。
