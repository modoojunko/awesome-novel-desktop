# 修稿向导 · 三路评审汇总（2026-10-10）

> 评审对象：原型 v2（ai-novel-c端-修稿工作流-原型.src.html）＋ 旅程数据 IO v2（修稿向导-用户旅程与数据IO.md）
> 评审人：Prompt Engineer ／ Frontend Developer ／ Product Manager（三路独立）
> 结论：**架构方向三方一致通过**（候选态、单一写口、逐段取舍、指纹 stale 收口）；共发现 **3 个必须修的缺陷、2 个需拍板的分歧行为、若干一期增强**。

## 一、必须修的缺陷（三方共识，上线前必改）

| # | 缺陷 | 来源 | 修法 |
|---|---|---|---|
| D1 | **stale 进向导未建模**：原型永远假设检测数据新鲜；真实场景正文改过→检测 stale→segment 段序错位，勾选写回会写错段（数据破坏级） | 前端 | 入口硬闸门：`status==="ok" && !stale` 才可进；应用前逐段校验 `seg.text === 当前段文本`，不一致跳过＋toast |
| D2 | **中途关闭静默丢候选**：scrim 点击/✕ 直接 close，作家花 token 生成的候选全弃 | 产品＋前端 | 有候选时关闭先弹确认（「已生成 N 段改稿尚未应用，关闭将丢弃」）；v1 必做；草稿暂存 fast-follow（前端缓存，复用 prose_hash 判新鲜） |
| D3 | **右栏两张卡都叫「去 AI 味」**：选区单发按钮与整章向导撞名 | 产品 | 向导卡改名「去 AI 味 · 修稿向导」，选区按钮副文案「选中一段，即时去 AI 味」；边界一句话：改一段找选区，改一章走进导 |

## 二、门禁（PM 提出 → 实施期按 entitlement 事实修正）

> **实施期修正（2026-10-11，以 tests/test_ai_feature_http.py:135-158 事实钉为准）**：
> 「去AI味」= ai-polish = **MAX 专属**（非 PM 假设的 PRO）；朱雀检测同为 MAX。
> 故向导门禁收敛为一条：**MAX＋本书模型**（与朱雀同门）——free/standard/pro 一律锁＋升级出口，
> MAX 未配模型硬禁用＋去配置；MAX 未配朱雀 Key/无存档＝规则模式可进＋软引导。
> PM 的「PRO 规则模式不穿透」原则保留为约束：规则模式全程无朱雀数据露出。

**原 PM 门禁矩阵**（前提已修正，仅存档）：

**PM 裁决：向导门禁跟 polish 走（PRO＋本书模型），不跟朱雀走（不要求 MAX/不要求有检测存档）。** 理由：向导核心动作（polish＋写回）全在 PRO 门内；朱雀存档只是清单的一个输入增强；「烧一次作家自己的腾讯检测额度才能进向导」是资产错用；且原型①文案「先清机器项省检测次数」本身就支持「先清后测」。

**门禁矩阵**：
| 档位 | 呈现 |
|---|---|
| free/standard | 卡片可见＋锁＋「PRO」角标，升级出口 |
| pro（已配模型） | **规则模式**可进：①③④全跑，清单只有文字层规则行（无占比/无判定段/无重检收口），收尾一条 Upsell：「升级 MAX 可用朱雀重检看人味变化」 |
| 任意档未配本书模型 | 硬禁用＋「去配置模型」 |
| max | 完整体验；无存档/未配 Key 时规则模式＋软引导「先检测，判定段会进清单」 |

实现注意：PRO 规则模式要**剥离全部朱雀衍生数据**（清单行/占比行/收尾 toast 三处逐一过），否则权益穿透。

## 三、Prompt 工程五裁决（PE）

| 决策 | 裁决 | 要点 |
|---|---|---|
| A. polish 复用与「确诊零」 | 复用照旧；**响应加 `changed` 布尔**（程序 diff 派生，非模型自报）；相似度 ≥0.995 也按无操作 | 否决模型输出 JSON 信封（双格式污染事故）与二次诊断调用（成本翻倍）。UI 三态：无操作=卡片置灰「未查出可修的硬伤，原样保留是合规结果」＋不给采用开关；重试仍无操作→「建议保留原文」 |
| B. hint 喂不喂 | **一期不喂**（确认设计稿 §8 倾向） | 锚定偏误绕过诊断门的反证校准；误改面扩大（把受保护对白错配）。二期触发判据：方向错配率/二次重试率埋点。预备措辞已给（user 段 `{lesion_hint}` 槽＋「以你自己的第 0 步诊断为准」声明；三条红线过检） |
| C. dx 一句话来源 | **选①前端模板化渲染**（rule_id→话术表，放 `ai_flavor_scan.py` 同模块） | 否决 polish 回传诊断（时序矛盾＋契约矛盾）。措辞纪律：正则确证=直陈；启发式=加「疑似」；朱雀段无规则命中=「朱雀判定疑似 AI 腔 71%（整段指纹，无具体病灶定位）」——宁可钝不可谎 |
| D. 逐段上下文隔离 | 否决二次全文 polish（契约违约 keep_original＋max_tokens 截断风险＋成本）；一期两招：**③队列按文档序＋已采用候选拼回 surrounding_context**；④加一行「多段同改建议连读衔接处」 | 失败模式：重影自查对着过期上下文＝查了个寂寞 |
| E. 改后程序化校验 | **加，一期**：polish 响应附 `flags`（quick_verdict(before, after, banned_words)，复用 ai_flavor_scan 规则） | 判据分级：书级禁用词/新增结构红线/引号奇偶/格式泄漏=blocking（标红＋默认翻 keep_original，作家仍可强行采用）；字数带 0.80-1.65 外/数字守恒/专名缺失=advisory（黄条「请核对」）。注意「新增命中 vs 存留命中」区分（原文自带破折号不算违约） |

**关键结论：polish_text.prompt 一期零改动**——五条裁决都不需要动模板；`changed`/`flags` 是端点响应附加字段，右栏老客户端忽略即可。

## 四、前端实施方案（FE 要点）

- **组件**：`workbench/polishWizard/` 子目录 7 文件（容器＋4 面板＋types＋scanRules＋applyProseSegments）；弹窗壳必须用现成 `design/Modal.tsx`（portal/Esc/焦点圈/locked 全有），不复刻原型手写 scrim；入口装配照 AiCheckModal 先例（ChapterWorkspace 条件挂载）。
- **写回**：正文是 TipTap 3——禁止 innerHTML 替换；正确姿势＝`doc.forEach` 数非空段得位置映射→采纳段**文档逆序**在一条 `editor.chain()` 里 `insertContentAt`（一次 ⌘Z 整批回退，必须入撤销史）→事务后**双写 store**（`lastSyncedRef`＋`setProse`，否则查看态被同步 effect 静默回滚）。建议扩 `ProseHandle.applyParagraphEdits()`。自动保存 flush 一次前置；**stale 触发零成本自动**（docChanged 监听已有），原型手动摘 class 的写法实现时丢弃。
- **编排**：串行＋预取 1（不上并发池）；`polishText` 补 AbortSignal；关弹窗全 abort＋零写入 toast；入口 disabled 矩阵（running/非 ok/stale/streaming 四臂）。
- **diff**：不加依赖——`diff@9` 已在主包（VersionDiff 在用）；段级对照用 `diffChars`（中文准确），阈值 <3% 或 >60% 变更退化纯文本。
- **预检放前端**：一期 `scanRules.ts` 纯函数（即时离线零额度）；规则 id 稳定化，将来 CLI 共用时再起后端端点（YAGNI）。
- **TS 类型**：Step/ScanFinding（含 `paraIndexes`）/ProblemSegment/FixCandidate（status: loading|ready|error|empty, attempts, decision）/PolishWizardState——完整定义见评审原文。
- **坑清单**（11 条，全文见评审原文）：步骤回退缺失、③无 loading/error 态、全取消勾选空态、keep 段不参与写回事务、可访问性（role=dialog/aria-pressed/aria-live）、事件绑定时机、footNote 额度话术去数字等。

## 五、产品决策与指标（PM 要点）

- **额度体验**：入口②给「预计 N 次模型调用」、③给「本次会话已用 X 次」、重生成第 3 次软提醒；不报金额（作家自己的 Key）。应用激活条件放宽为「≥1 段已取舍」；中途失败三出口（重试/跳过此段/带已生成段去应用）。
- **信任**：空应用（全保留原文）＝合法完成，独立收尾态「本轮未采用任何改稿，正文保持原样」，不置 stale 不弹 toast，空应用率进埋点；字数异常 chip（>160%/<60% 警示不阻断），越界样本回喂提示词仓。
- **空态四套**：无存档/未配 Key（规则模式＋软引导）、未配模型（硬禁用＋去配置）、free/standard（锁＋升级，不展示流程细节防 bait-and-switch）。文案逐条见评审原文。
- **指标**：北极星＝周修稿轮次（MAX+PRO 周活人均 ≥1.5）；应用完成率 ≥60%；人味提升中位数 ≥+8pp（仅 MAX 有分母；朱雀是概率参考，营销不许写提升承诺）；7 日复用率 ≥40%；护栏空应用率 <25%。
- **上线检查清单 8 条**（门禁逐格/空应用路径/关闭保护/激活条件/额度文案/字数阈值/四空态/埋点）——全文见评审原文。
