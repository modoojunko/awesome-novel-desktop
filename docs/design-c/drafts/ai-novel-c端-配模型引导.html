    设计说明（评审用）

    配模型引导 · 草案 2026-10-08 · 未立项。视觉与组件词汇沿用 prototypes/CLAUDE.md。

    命题与判例

    内测反馈「配大模型不知道怎么配」。实锤判例：10-05 内测 405 定诊——测试同学把控制台网址（platform.deepseek.com/api_keys）当 Base URL 填，返回的是网页不是接口。作家缺的不是表单，是「我属于哪种情况」的分流，和填错时的修复路径。

    三个策略

    • 情况分流：入口四张情况卡＋兜底「帮我推荐」。A 没有 Key（教程＋推荐）/ B 已有 Key（选哪家）/ C 中转·自建（compat 形态）/ D 本地 Ollama（免 Key）。C、D 自动跳过「拿 Key」步。
    • 概念隐藏：新手主路径不出现 Base URL、接口格式、模型 id 起名——预填＋锁定收进「高级选项」折叠；compat 形态才把接口地址升为主字段。文案不出现「端点」「OpenAI 格式」等术语（高级选项与分诊卡除外）。
    • 错误带动作：测试失败不只给报错文案，每种错误配一个修复按钮——401「重新复制粘贴」；返回网页/405「恢复默认地址」；余额「去控制台充值」；429「稍后重试」。
    • 地址即点即开：教程步骤里凡是「打开 X」的域名都是真链接（新窗口直达），不要求用户复制粘贴网址；分诊卡的「去后台重建／去控制台充值」按当前厂商注入真实地址（compat 分支无已知控制台，只留本地动作）。实现上建议复用教程登记表的单源地址，勿散落硬编码。

    入口与并存（路由层）

    /config · 零配置同一路由，空态主体换成引导主卡；「我懂行，直接添加」仍走现有弹窗、不离页
    「带我开始」「帮我推荐」→
    /config/guide · 引导流独立一过性路由；去浏览器拿 Key 后回来状态不丢；刷新/返回键行为天然
    完成 / 返回 →
    /config · 有配置现行管理态（用量＋卡网格＋朱雀页签），零改动；视觉真值 model-config.html
    重入口：「添加 API Key」弹窗次入口、成功页「再配一个」、（可选）正文 AI 403 出口 → 都跳 /config/guide

    引导选独立路由而非 /config 内部状态机或大弹窗：引导中用户必然离窗（去浏览器拿 Key 数分钟），独立路由的刷新、shell 返回键、深链跳转都是现成行为；朱雀 Key 引导不受影响（仍是现行页签内面板）。演示条里的各场景即 /config 零配置与 /config/guide 两个页面内容的拼装，便于评审。

    入口

    • 与现有页面的关系：条件分流，不是常驻双 tab，也不是整体替换。零配置时空态主体换成引导卡（页头、「添加 API Key」按钮、notice 保留；被替换的只是虚线空态卡）；有配置后界面与现行完全一致（用量统计＋配置卡网格＋朱雀页签，零改动，视觉真值仍是 model-config.html）。引导流程本身是独立一过性流程，做完即走，重入口＝添加弹窗次入口＋成功页「再配一个备用模型」。同先例：书架新书 OnboardingCard 条件出现、可关闭，非常驻 tab。
    • 主入口：零配置空态把引导卡作为主体（本稿场景 0），保留「我懂行，直接添加」专家路径（现有 520px 弹窗原样不动）。
    • 次入口：「添加 API Key」弹窗底部「不知道怎么填？用引导模式」链接（本稿未画，实现时加一行）。
    • 可选出口：正文 AI 首次 403 时由 MemberBlockPrompt 类机制带一段「先去配模型」（不在本稿范围）。

    • Ollama 未安装时的引导深度：本稿只给三步命令行说明，是否要内嵌检测（GET localhost:11434 探活后给差异化文案）。
    • 空态改版后，原「先开始手动创作」空态卡是否保留双出口（本稿保留为顶部按钮＋底部 notice 文案）。
