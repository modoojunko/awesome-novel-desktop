# 角色列表：拖拽排序 + 搜索查找 — 方案草案（未立项）

> 原型：[ai-novel-c端-角色批量添加与拖拽排序-原型.html](ai-novel-c端-角色批量添加与拖拽排序-原型.html)（demo-bar ②③；重放 `python3 docs/design-c/drafts/build-chars-proto.py`）
> 2026-10-09 · 来源：作家反馈「角色太多，角色设定这里要能自由排序、搜索查找」
> 「自由排序」的定义（用户拍板）：**列表中数据的顺序，按住拖拽改变顺序**。
> 不做「按出场/按笔画」之类的排序方式切换器——作家要的是自己排。
> 搜索范围（用户拍板 2026-10-09）：**首版只做名字＋别名**，语义词扩容（人设/势力/背景）列二期。
> 姊妹篇：[批量添加角色](ai-novel-c端-批量添加角色-头脑风暴.md)（人多了才需要排和搜，两件配套）。

## 一、现状（事实盘点）

- 列表＝左栏，按角色类型分组（主角/配角/反派/路人，可折叠），**组内顺序固定为创建序**
  （后端 `order_by(Character.seq)`，`character_service.py:185`）。没有任何排序能力，
  创建序还带着建卡编号 `C-0001` 的语义，不能拿来当显示顺序改。
- 搜索框已有，但只搜**名字＋别名**（`CharacterManager.tsx:608-614`），纯前端过滤。
  两个短板：
  1. 覆盖面窄——想找「那个船家」搜不出来（人设里有，搜索不看）；
  2. **收起的分组搜到也看不见**——命中项在折叠组里，用户以为没搜到（隐藏缺陷）。
- 好消息：列表接口一次给全每张卡的**全部字段**（人设、八格、认知 30 格、别名、首次出场章号，
  `list_characters` → `card_to_dict`，`character_service.py:178-197`）——
  将来搜索扩容到语义词时**零后端改动**（首版不扩，见拍板）。
- 行内已显示：头像首字、名字、首次出场章号、主角「待立」徽标。

## 二、方案 A（推荐）：拖拽排序 + 搜索升级

### 1. 拖拽排序

- **交互**：列表行按住可拖（行内加一个拖拽把手 `⋮⋮`，鼠标按住把手或整行均可起拖；
  短按仍是选中角色，不冲突）。拖动中插入位置显示高亮线，松手落位。
- **顺序持久化**：新增一个显式顺序接口，一次提交整条新顺序：

  `PUT /api/novels/{pid}/characters/order`，body `{"ids": ["...", "..."]}`（全量有序 id 数组）。

  后端把 `sort_rank` 落到 characters 表（新增可空整数列，迁移按项目现行做法；
  旧书不迁移数据，读取时 `sort_rank IS NULL` 按 `seq` 兜底排在已排序的后面）。
  全量数组提交天然幂等，不需要 diff、不需要逐卡 PATCH，一次拖拽一个请求。
- **分组怎么处理**（推荐形态）：保留角色类型分组，但加一个「分组」开关（默认开）：
  - **分组开**（现状形态）：拖拽改的是**组内顺序**；
  - **分组关**：整条列表扁平一条线，拖拽＝从头排到尾，完全自由——这就是用户定义的自由排序。
    行内保留角色类型小标签（主角/反派…），信息不丢。
  顺序是全局一份（rank），两种视图共用；组内顺序＝组员按全局 rank 的相对次序。
- **边界**：
  - 新建角色（含批量添加）追加到**列表末尾**，规则简单可预期；
  - **搜索过滤中禁用拖拽**（拖拽把手置灰＋提示「清空搜索后可排序」）——过滤态下拖拽
    改的是可见子集，落位语义必错，直接禁掉最不坑；
  - 拖拽只改显示顺序，不碰角色类型、不碰 `seq`/编号 `C-0001`；
  - 键盘可达性顺手带上：行聚焦时 `Alt+↑/↓` 上下移动一位（免得纯鼠标功能进不了 a11y 门禁）。
- **并发/一致性**：order 接口带书级乐观锁或 last-write-wins？——**last-write-wins 就够**，
  同一本书很少两人同时拖；不必上 rev 那套。

### 2. 搜索查找（首版＝名字＋别名，用户拍板）

- **覆盖面**：维持现状的**名字＋别名**（`CharacterManager.tsx:608-614`，纯前端），不扩容。
  首版要补的是「搜得到的一定要看得见」：
- **修隐藏缺陷**：搜索时**自动展开所有有命中的分组**（离开搜索恢复原折叠状态）——
  现状收起的分组里搜到东西是看不见的，用户会以为没搜到，这是首版唯一必修的搜索项。
- **空态**：「没找到『xx』，换个词试试」＋一键清空搜索。
- 其余（语义词覆盖、命中高亮、快捷键）全部进二期，首版搜索面保持一行过滤逻辑不动。

## 三、刻意不做的

| 不做 | 理由 |
|---|---|
| 排序方式切换器（按出场/按名字/按最近编辑…） | 用户已明确要的是手动拖拽，切换器是另一套心智 |
| 拖到别的分组＝改角色类型 | 一个手势改语义数据太危险，还有「每书一位主角」的雷 |
| 搜索扩容到人设/势力/背景 | 用户拍板首版只做名字＋别名；数据都在载荷里，二期随时加 |
| 拼音/首字母搜索 | 要引拼音库，二期再说 |
| 搜索结果单独成"视图" | 就地过滤即可，多一层视图多一层乱 |
| 排序进 AI/门禁链路 | 显示层顺序，纯前端消费，不进提示词、不影响门禁 |

## 四、二期备忘

1. **搜索扩容**：人设、势力·身份、背景、剧情定位（纯前端，列表载荷已有）；
   命中关键词高亮＋行尾标「命中：人设」；`Cmd/Ctrl+K` 或 `/` 聚焦搜索框。
2. 拼音首字母搜索（`zsm`→赵捕头），引轻量拼音库或本地映射表。
3. 搜索命中后跳详情自动定位到命中那一格（点击搜索结果展开右栏对应手风琴层）。
4. 备份/恢复带上 `sort_rank`（`backup/importer.py` 的 characters.yaml 映射补一列；
   不带也不坏——恢复后退回创建序）。

## 五、验收口径

- 分组关：10 张卡任意拖到任意位置，刷新/重启后顺序保持；分组开：组内顺序与刚才拖的一致。
- 旧书（无 rank 数据）打开＝原创建序，拖一次后开始按新顺序。
- 搜名字/别名能命中；命中项即使在折叠分组里也**可见**（自动展开），清空搜索后折叠状态还原。
- 搜不到时空态文案＋一键清空；搜索过滤中拖拽把手置灰不可拖，清空后恢复。
- 拖拽不改角色类型、不改编号；新建角色落列表末尾。
- `Alt+↑/↓` 可移动行；order 接口全量提交，重复提交同一数组幂等。
