### 事实纠偏（立项文必须更正）

1. **segments 现状根本不进素材包**（后端 P1-7 / 架构 P1-1）：`chapter_writer.py` 两条产物路（material_markdown / to_prompt）均不消费 segments——「有链时 segments 不再注入（防双份）」空转；真实增量＝**首次把章内段级剧情指令送进正文提示词**（结构性分叉，prompt-crafting delta 按双态新 Requirement 写死）。回归钉反而更好钉：无链章两条路径逐字不变。
2. **scene_cards 是真子表不是 JSON 子表**（后端 P0-2）：`chapter_scene_cards` 表＋sort_order＋selectin relationship；plot_beats 应照此建 `chapter_plot_beats` 子表（列宽：event 150 / difficulty 150 / landing 300 / target_words Integer）。
3. **gate 必填是四项不是六项**（后端 P2-11 / 架构 P2-5）：「其余五项口径不变」计数错误，应余三项。
4. `write/router.py:176` 的 `outline.get("segments")` 是死检查（架构 P1-1c），顺手修掉。

## 附：四份原始报告

以下为四位评审的完整原文（未删改，保留全部 file:line 证据）。

### 一、产品经理

**总体判断**：值得做，设计骨架成立。现有动线从「章卡一句话」直接跳到「2500 字整章提示词」，中间只有薄段落规划，结构信息全靠模型自由发挥——剧情链补的是真实的中间层，且以「可选层」落地：无链章素材包与现状逐字一致，零回归面。放在拆章与写正文之间是顺的：链的前置恰好是拆章排上后已带入的字段，链的产出恰好闭合开写四项之一，首段承接复用拆章进场锚。四态语义大体自洽，免费/PRO 分档成立。但当前稿有 2 个 P0（末段落点强一致断言在字段预算上不可满足；中栏 AI 主按钮破坏「AI 只在右栏」口径并给免费用户埋了陷阱 CTA）和一组 P1 边界态破口，修完再恢复立项。

**P0-1 末段落点预算小于章末落点预算，「止」的强一致断言对一批章必然失败**——链段落点预算 ≤50 字，而 ladder_exit 的既有预算是 ≤80（拆章 AI 预算与手写 maxlength 同值，DB 列宽 300）。凡章末落点在 51–80 字的章，AI 要满足「末段落点 ≡ ladder_exit」就必须超预算，满足预算就过不了相等断言——两个结构性断言互斥，重试 3 次也必挂。改法（推荐 b）：a) 末段「落点」预算单独对齐 ladder_exit（80）；b) 采纳时服务端以章末落点原文覆写末段落点，断言降级为「存在末段落点字段」；c) 断言降级为包含/前缀一致。

**P0-2 中栏空链卡的「用 AI 拆这一章」主按钮同时破坏三条既有口径**——a) 违反「AI 入口只在右栏」；b) 空链卡由空链态与免费态共用，免费用户的主 CTA 直接打开 AI 弹窗，无拦截态；c) AI 是 primary、手写是 secondary，与「手写全档、AI 是 PRO 加成」分层叙事相反。改法：删除中栏 AI 按钮，或降级为指向右栏的 ghost 文字链；空链卡唯一主 CTA＝「手动加一段」。

**P1-1** 「有效段」与「有效链」两个有效性谓词冲突（「每段难非空」vs「各段事非空」），gate 闭合口径含糊。**P1-2** 剧情链与场景卡两套章内分段体系并存，提示词双头指挥（场景卡权重笔墨 vs 段字数可互相矛盾）——定单源：有链时场景卡不携带笔墨分配，段级字数只认链。**P1-3** 采纳＝整链替换无预告无撤销——预览脚注注明「将替换当前 N 段」＋回执附一步撤销。**P1-4** 删链入口缺失（只有逐段删）。**P1-5** 失败态缺「未配置模型」分支，且「3 次尝试」内部预算泄漏给用户。**P1-6** 手写链末段不一致时素材包同时注入两个「止」——裁定章末落点块为准。**P1-7** 空链态丢失手写段落规划出口，kicker 对已填章是假话。

**P2（13 条）**：英文序号 PLOT 01；同一动作四个名字；右栏「逐段落位」措辞；上移下移重排语义静默断裂；6 段上限 UI/AI 越界处置；字数偏差 warn 呈现位；双列重复展示收敛；「已落」改「已采纳」；链变更与章纲已确认态关系；已归档章只读；计量 operation 独立；chapter-plan-ai spec「4 项 vs 6 项」矛盾顺手修；三要素拦截态补 Scenario。

**认可点**：读侧投影不物化＋删链回落；无链逐字一致回归钉死；单次直出不做抽卡；进场锚复用；前置门槛三要素＝拆章已带入字段，动线无断点；免费锁定态给免费出路；越界警告不拦＋伏笔不入素材；「事·难·落点」与拆章词汇同族、三要素由链结构贯穿。

### 二、前端工程师

**总体判断**：方向可行，数据模型正确，但与现行裁定/代码有三处硬冲突（P0）。读侧派生、承接不落库、effective_segments 单源在 OgForm＋ogToPartial＋3s 自动保存架构上可干净落地，交互有现成先例（useChapterPlan 状态机/Modal wbStyle/LockedCard/flashField）。风险集中在：进场锚端点复用是错话、采纳与自动保存竞态、中栏 AI 按钮违反收口拍板。

**P0-1** 中栏空态「用 AI 拆这一章」违反收口拍板（OgPane.tsx:83 注释明文）且免费态未门控（data-states="empty free" 共卡）。**P0-2** 「复用拆章进场锚端点」拿到的是错误进场：`next-chapter-anchor`（ai_plan.py:437）硬编码 `len(rows)+1` 永远返回下一章进场；底层 `resolve_prev_chapter_ending`（ai_plan.py:65）支持任意章号，缺按章查询参数。**P0-3** 采纳落库与 3s 自动保存写入竞态：自动保存 effect（ChapterWorkspace.tsx:296-316）不检查 in-flight 状态，ogToPartial 恒带 plot_beats 后，旧 timer/在飞 PUT 用旧 ogForm 整表回传会覆盖刚采纳的新链——照 handleRewriteConfirm flush 前置先例：采纳前 quiesce＋采纳后只 merge plotBeats 并同步 ogSnapRef。

**P1-1** 投影呈现位置二义：真实 OgPane 有 details#wf-segs 段落规划区且缺口 chip 跳转依赖其 id（flashField），照稿会出现两个段落规划呈现面。**P1-2** 链完整性若进 ogFormIssues 会连坐冻结全部字段自动保存（issues 非空 effect 直接 return）——链完整性全走 warn。**P1-3** 生成中无显式取消钮，busy 态锁定语义未定义（locked 只该用于采纳在途）。**P1-4** 缺键清空三层面：ogToPartial 恒带 plot_beats；GET/PUT 同版本上线（旧 GET/新 PUT 组合旧前端照样清链）；useChapterData 降级路径已有 GET latest 安全，导入等旁路逐一排查；vitest 钉 round-trip 三条。**P1-5** 前置门槛读服务端值，开弹窗前先 flush 防误拦。**P1-6** 右栏复用现行门控词汇（ai-tool/LockedCard/rail-locked），不新造 .rail-new；接入 AiAssistPanel raActs（locked=!isPro 现成）。

**P2（9 条）**：右栏结构非基线（本章进度挪顶/删 ai-head）；pk-* 撞三方向卡家族；.notice 无定义；.bf input 自立门户重写 .input＋重复类名；80ch 内联覆盖；可访问性（24 输入无 aria-label/gen 态 aria-live/焦点去向）；边界（6 段上限禁用/1 段中间态提示/空段过滤/清空链 ghost/切章关弹窗/beat 稳定 key 勿用指数键）；删段图标统一 trash；OgBeat 短键命名 {e,d,p,w}。

**认可点**：读侧派生＋承接 O(1) 渲染期派生无性能问题；状态机照 useChapterPlan 同构（token 守卫/幂等/submitting 锁）；设计稿工程纪律好（真实 CSS 注入/全 token/复用 e-empty 四档/图标全在注册表）；校验分层与既有哲学一致；素材不带伏笔＋无链逐字不变。

### 三、后端工程师

**总体判断**：方向可行，纪律对齐度高，三个必须在立项规格里钉死的硬点。四根柱子（读侧投影/单次直出/结构性 sanitizer/同事务幂等）全部能在既有代码上落地且有先例（gate_chapter_ready 纯函数门、_sanitize_directions+MAX_ATTEMPTS=3、apply_chapter_data 不自行 commit、_ADOPT_TOKENS TTL 幂等）。读侧派生裁定尤其正确：物化副本在整表回传＋_fit 截断双重力下必然漂移。

**P0-1** 「末段落点 ≡ ladder_exit」存在不可满足域且列宽不对称会静默破坏不变量：ladder_exit 列 String(300)（models/chapter.py:103，_fit 300 截断 store.py:286），手写可存 300 字而落点预算 50——模型不可能产出 trim 相等；若 beats 落点列照预算建 String(50)，存 ladder_exit 原文时 _fit 截断，此后整表回传一轮「≡」就在库里静默断了。改法（推荐 A）：采纳路服务端覆写末段 landing 为 ladder_exit.strip()，模型值仅软校验 warn；landing 列宽 ≥300。**P0-2** 存储形制表述与代码事实不符：scene_cards 是独立关系子表 chapter_scene_cards（models/chapter.py:244-262），「JSON 子表」照字面实现会建 style_shadow 式 Text 列——裁定为独立子表 chapter_plot_beats，接入清单：models 新表＋relationship（cascade+selectin）、store.py _CHILD_ATTRS 追加、_replace_children_impl 增构行段、assemble_chapter 增非空直出；列宽 event 150/difficulty 150/landing 300/target_words Integer。

**P1-3** 整表回传缺键清空：apply_chapter_data 对子表先 clear 再 data.get(key) or [] 重建（store.py:604-607）——_replace_children_impl 对 plot_beats 做 presence-gate（"plot_beats" in data 才替换，[] 显式清空），测试钉「缺键保留/[]清空」。**P1-4** 字数和可行性域：段字数 [200,3000]×段数 [2,6]⇒[400,18000]，word_target 夹取下限 500 时 clamp 归一仍越 ±20% 无解——前置可行性判定＋归一算法钉死（scale→round→clamp→残差给最大段）＋归一失败 warn 不拦。**P1-5** 重试预算三条路径纠缠——结构性失败才进 ≤3；字数偏差一次定向重试→归一→warn；每次尝试记账（operation=chapter_plot_beats/_retry/_fail）。**P1-6** effective_segments 收敛点比设计列的多（gate 三调用面＋fill-gaps＋素材包）——派生收敛进函数内部（gate_chapter_ready 第一行改读 effective_segments），fill-gaps 端点内 drop segments 后端兜底。**P1-7** 「有链时 segments 不再注入」前提不成立：素材包今天不注入 segments（ChapterContext 无此字段，write/router.py:176 是死键）——条款改写为纯增量，回归钉两路径。**P1-8** 素材包「进场行」是新取数：与拆章进场锚同源但 build_chapter_context 只有 root_path——给 resolve_prev_chapter_ending 提供 root_path 版包装共用，ch_no 取本章 row.chapter_no。

**P2**：有效链谓词二义；采纳后链过期无读侧信号（建议 GET/装配时派生 warn「剧情链与章卡已不一致」，不新增标记）；手写路校验归属（validate_chapter_fields 扩 beats 预算 422 先于写入；「其余五项」计数有误，gate 实为四项）；采纳端点事务口径（同 session 取行→assemble→merge→apply 不自行 commit；幂等复用 _ADOPT_TOKENS；ref 解析 _parse_chapter_ref 400 不 500）。

**契约建议稿**：建表 SQL、ChapterData plot_beats 非空出场、effective_segments 派生规则、两端点（POST /chapters/{ref}/plot-beats/ai：PRO 门控＋422 三要素缺/不可行＋502 三次失败；POST …/plot-beats/adopt：登录态＋client_token 幂等）、sanitizer 八条断言清单、素材包块格式与插入位（章末落点块后、撞的墙块前；to_prompt 同步）、pytest 十条测试面（无链逐字不变最优先）。

**认可点**：读侧投影（segments 子表与 plot_beats 正交互不清空）；单次直出砍掉名次/字母机判面；承接不落库与进场锚先例同构；素材纪律逐条对上已付学费的先例；无链逐字不变兼容姿态；前置门槛三要素与卷纲空门槛同构（422 先例直接可抄）。

### 四、架构师

**总体判断**：架构上成立，分层职责划分正确（卷定边界、章定剧情、剧情段定节奏），取舍与既有裁定同构。两处 P0 必须先钉死：其一「末段落点 ≡ ladder_exit」只钉了写入时刻断言，没钉事实源与漂移后的消费侧行为（不定源则判别面扩散）；其二 AI 采纳写路径与整表回传/前端缓存的竞态——「缺键即清空」会以「采纳成功→下一次自动保存把链静默抹掉」的新形态复发，设计只给了测试没给机制。另有一个事实性纠偏：segments 根本不进素材包，本设计的真实增量是「第一次把章内段级剧情指令送进正文提示词」。

**P0-1** 「止」的单一事实源未定：ladder_exit 已有两个写入口（拆章排上/章纲表单）＋下游消费（下一章进场派生、stale 判定、素材包独立块）；链尾落点是子表字段。用户改章末落点→链尾漂移无联动；用户手改链尾→素材包同时注入两个矛盾结尾；原型 CSS 里 .ladder-fix 可点胶囊六态从未出现（修复交互只做一半）。改法：钉死 ladder_exit 是「止」的唯一事实源、链尾落点是结构性影子——素材包组装时链末段以 ladder_exit 原文覆盖呈现（读侧覆盖不回写）；前端链尾恒显锚定态＋漂移一键对齐。**P0-2** 采纳写路径未定形＋前端缓存失步：前端保存是「chaptersMap 缓存 merge→PUT 全量」，后端子表 clear+rebuild——采纳后任何一次自动保存 PUT 旧缓存全量 body，新链被整体清空；排上不踩此坑是因为排上后跳转重拉。改法：专用 POST 端点（只写 plot_beats＋幂等 token）；采纳回执后前端必须失效并重拉该章（场景级验收）；保全测试覆盖真实路径。

**P1-1** 事实纠偏：segments 现状不进素材包（两条产物路均不消费）——立项文如实陈述「首次注入」；有链/无链章正文生成输入结构性分叉，prompt-crafting delta 按新 Requirement 双态写死；增量价值主张更实（让从未被消费的段落规划第一次真正到达模型）。**P1-2** effective_segments 单源落点未钉且判别面实为五处（gate 三调用面/fill-gaps/表单投影/素材包/outline-ai-draft 基底 JSON——设计完全没提的一处盲区）——读侧派生进 GET（assemble 输出派生只读键），前端只渲染不计算，PUT 忽略该键。**P1-3** 末段落点断言失败退化路径太硬——服务端强制覆写不产生新语义（与「S/A/B 字母服务端算」裁定同构），不消耗重试预算；归一用 clip 进单段预算再二次分配，防重试放大。**P1-4** 有效段判定同文自相矛盾——结构有效性（事非空）与语义质量项（难）分开命名。**P1-5** 粗组兜底路径 to_prompt 未接线：只在 material_markdown 加块，跳过润色的章拿不到链——两段式两条产物路同步注入。

**P2**：进场锚「复用端点」字面不成立（复用的是派生函数，plan-card 端点已按 chapter_ref 调它 ai_plan.py:561）；手写中间态投影闪变（「无效链=无链」呈现口径）；已归档章链编辑权限未声明；链与场景卡同包调和措辞进提示词层；「其余五项」计数失准＋「JSON 子表」表述失准；右栏「逐段落位」措辞。

**认可点（8 条）**：读侧投影不物化可被论证（同表方案会毁掉回落源，独立表＋读侧派生是唯一同时满足单源/回落/无双写维护的形制）；单次直出识别准确；进场复用零冲突；素材不带伏笔＋末章正协同；预算严于列宽；gate 最小侵入；越界先例；Non-goals 划得准。
