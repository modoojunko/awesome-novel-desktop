## 1. 一句话

把「一发式生成整章＋顺/拗二选一＋收固定话术」翻转为**角色对话流推演**：
导演只触发开始，在场角色按各自的设定（角色卡人设）挨个响应、彼此互动——
每位角色一次模型调用（携带人设＋此前全部对话），全场说完算一个回合；
回合落点与好台词可改可收，走完总结成剧情条目与必写对白，一并收进章纲。

## 2. 参与口（对准三层诊断）

| 参与口 | 原型交互 | 治什么 |
|---|---|---|
| 看角色自己动 | 导演只触发，角色按人设＋场景挨个开口（说话/动作/旁白）——不再是顺/拗两个原型，也不必作者替角色编走法 | P1 假推进（每回合真生成）、P2 走法固定 |
| 导演插话 | 输入框随时下指令/代角色说一句；**反馈即注入**——对应回合就地按反馈重推（反馈气泡留在对话流，角色按反馈重新挨个响应；扫场中插话同样打断重扫）；走完可带令加场 | P2 不能自提走法 |
| 改落点＋收台词 | 每回合落点卡可改字，「收进章纲收的就是改后这句」；好台词/旁白一键「必写」 | P3 收进章纲零信息（`strategyLineOf` 固定话术退役） |

配套修正：

- **增删回合**：末回合完结卡上「还没到章尾？再加一回合」（可带导演令加场）（P2）。
- **可回退**：回合定格条上「重定」＝回到该回合重定，其后回合作废重推（P5）。
- **可中断**：每回合＝在场人数次短调用，加载态是逐角色的「按设定响应…」打字指示，
  可插话可关掉，不再「请勿关闭弹窗」——502 暴露窗从整章几十秒收到单次调用级（P4）。
- **兜底可见**：AI 不可用走确定性兜底时，落点卡挂「模板推演 · AI 不可用兜底」警告 pill
  ＋「重试一次」，模板句与 AI 产物不再同口径伪装（P6）。
- **场景边界**：每个场景在对话流里以开场分隔条开、收束线闭，起讫卡死（2026-10-15 补拍板）。
- **修正粒度到句（2026-10-15 补拍板）**：回合未定稿前，每条气泡/旁白可「✎ 改」（就地改词，
  改定带「已改」标，收必写标注「作者改定」）；每位角色的响应块可「↻ 重说」＝只重调这一位
  （备选演法对应响应替换，其余角色与前文不动）；回合级「重演」与定稿后「重定」不变。
  真机＝重说/改词都是单点操作：重说一次调用（人设＋多轮前文），改词纯前端、随总结落章纲。

## 3. 界面结构（弹窗壳不变，内部重做；2026-10-15 拍板只保留对话流，A/B 两变体已移除）

- 壳沿用真实 `.scrim/.modal/.mcard.wb-style`（920px 近全屏）；默认打开**不自动发请求**——
  先展示「起与收」卡＋「开始推演」，点击才调第一回合。
- 统计条 pills：起点 · 终点 · 回合（已定 N · 当前第 M）· 章纲条目已收数 · 必写对白数
  ——收进章纲的账全程可见。
- **角色对话流（定稿形态）**：顶部场景条（随推演自动切场景＋在场角色人设徽标，悬停看设定）；
  微信式聊天流——角色气泡（台词）＋居中旁白（动作/环境）＋**场景起讫分隔条/收束线**；
  每回合末尾一条**可编辑落点卡**（收进章纲收落点句）；底部**导演输入框**（可选定调/插话/
  带令加场）。页脚只剩触发开场的「开始推演」，开演后退役，动作全在落点卡与输入框。

## 3.1 变体 C（对话流）的机制定案（用户 2026-10-15 三轮拍板，已落原型）

1. **导演只触发开始**：点「开始推演」即开场——不写开场稿；章纲与角色设定就是语境。
   想先定调可选写一句（以导演气泡进对话流），走的过程中随时插话，走完可带令加场。
2. **角色按各自设定自主互动**：每回合按场景在场名单顺序，**每位角色一次模型调用**，
   提示词携带**该角色的设定（角色卡人设）**＋此前全部对话（多轮对话），只生成这一位的
   说话/动作/旁白；**全场响应完＝一回合**，回合末出可编辑落点卡（收进章纲收落点句）。
   场景条挂在场角色人设徽标（悬停看设定），响应中指示「按设定响应…」。
   原型演示每位 1.1s，真机每位一次短输出调用。
3. **代价清单（同意附带）**：调用次数＝章 6-12 次（回合 2-3 × 在场 2-3 人），单回合延迟
   ≈在场人数×单次延迟（真机估 10-45s/回合）——靠①每次只生成一句台词＋动作（max_tokens 小）
   ②等待期可插话/可关掉③落点卡前不算完，作者随时「重演」兜底来消化。
4. **群聊防漂**：模型仍被剧情条目拴住（每位响应落到当前条目），人设与条目路标双约束。
5. **场景起讫卡死边界（2026-10-15 补拍板）**：对话流里每个场景以「开场分隔条（场景N＋
   地点·时间·在场）」开、「收束线（场景N · 收——场景小结句）」闭；场景条同步切换。
6. **走完＝总结收进章纲**：本章走完后点「总结推演剧情 · 收进章纲」——把各场景各回合
   落点**总结成剧情条目拟稿（可改）**，确认后**写入中栏章纲的剧情条目**（替换原条目，
   原型里底座 OgPane 实时更新）；逐回合「收进章纲」保留为中途收单句的旁路。
   真机＝总结一次 AI 调用（素材＝各场景收束句＋回合落点链），写入走既有章纲保存链。
7. **对话/旁白可收为「必写对白」（2026-10-15 补拍板）**：聊天气泡与旁白条上一键「✑ 必写」
   （原地切换不重渲，统计条实时计数）；总结卡带「必写对白与旁白」拟稿（可改），确认后与
   剧情条目一并写入章纲。真机＝**章纲新增「必写对白」留存字段**（说话人＋原句，挂在对应
   场景/条目），正文生成的素材组装与 plot prompt 同批消费——正文必须写出这些话。
   注意过度约束：只收关键句（演示种子即 2 条量级），全收会让正文生成僵死。

「做成拆书那种通用功能」**缓做**：拆书是书级批处理、推演是章级交互排练，性质不同；
第一版入口仍锚章（章纲页签），交互内核做成形态无关，后续挂「推正文段」「拆书卡重演
验证」等入口不换引擎；独立导航级页面等对话流验证后再议。
- 时间线卡：回合号＋走法名＋落点原句＋「收进章纲 / 已收进 · 重定」。
- 页脚：关闭＋情境主按钮（开始推演 → 定下这条 · 推下一回合 → 把没收的 N 个回合收进章纲），
  说明行随状态换文案。

## 4. 与实现的联动点（立项时三处同步改）

1. **端点 step 式**：`POST .../simulate`（整章）拆为 `simulate/step`——入参＝上一章结尾＋章纲
   素材＋已定走法链，出参＝下一回合局势＋2-3 候选；「再加一回合」＝同端点追发；单回合
   `max_tokens` 预算远小于整章 1600。能力 key 仍挂 `ai-plot`（MAX）；记账契约沿用（调用发生
   即记账）。旧整章端点可保留一个版本期做兼容或直接退役（拍板点）。
2. **SimModal 重做**：本原型的状态机直译 React（对话流／逐角色响应／落点编辑／场景边界／
   总结收章纲）；收进章纲仍走既有 `handleSimAdopt` 保存链，但收的是**总结拟稿＋落点原句**
   （不再两句固定话术）；章纲需新增「必写对白」留存字段。
3. **plot_sim.prompt 重写**：v2 分层保留，输出契约从「整章 rounds 数组」改为「单角色响应
   （台词＋动作＋旁白，携带人设与前文多轮）」＋「场景标注」＋「回合落点」＋「整章总结」；
   fallback 模板保留但前端明示来源。
