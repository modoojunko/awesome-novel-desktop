# 开发日记 09-07，PRO 用户被当成了免费的

今天修掉了一个最不该存在的 bug。花钱买了 PRO 的用户，打开应用，被当成免费用户接待。

这个 bug 的性质比它的样子严重。界面上看，可能只是几行字显示得小气了些，功能入口藏得深了些。实际是付费买下的权益没有生效，按免费用户的规格在提供服务。收了 PRO 的钱，给的是免费的活，这种账迟早要跟用户算清楚。

拆开看，根子在一个老架构决定上。这个应用分两端，S端管账号和套餐，C端管写作和功能。谁是 PRO 这件事，S端心里一清二楚，但它没有在用户登录校验的时候把这件事一并告诉 C端。C端只好自己判断权益，判定的依据时对时错，于是出现了一种最伤人的断裂，钱付了，功能按没付的处理。

修法没有走补丁路线，直接立了一份权益契约。S端在套餐表里加了权益列，配上默认值，登录校验的响应里统一向下发放。C端改成快照优先的判定，权益内容拿得到就按契约走，拿不到就按设计好的异常分支提示，还把客服入口直接放在提示里。生产数据库动之前，先出了一份实施册，预检、加列、种子、四道验证全过，才发的版本。

结果，v0.18 全链发布，PRO 的权益按契约下发，两个 change 归档，四份规格入库。当天还抓到一笔连带回归，为了让用户看得见自己在用的版本和账号，改自愈逻辑的时候把本地存的用户名擦空了，账号显示跟着空了。定位到是登录校验少回传一个字段，当天修复上线。

顺手的事还有两件。选购页给正在生效中的付费用户加了换档引导，想升高档，三步走，先退再买，并且明说退款完成前下单会排队。两个藏了一阵的控制台报错也清了零，一个是书删掉之后残留标签页的循环报错，一个是设定页折叠箭头塞错了东西。
