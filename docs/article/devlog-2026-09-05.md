# 开发日记 09-05，测试全绿，打开就崩

今天的主题是一个最经典的 bug。新版本 v0.15 发出去，应用一启动就崩。而它所有的测试，都是绿的。

崩得干脆利落，主界面都见不着。图形界面崩溃的问题是屏幕上什么都来不及说，第一件有用的事是把打包好的 dmg 拖进终端里裸跑，让错误信息直接打在屏幕上。输出很短，说有一个名字没定义，bridge。顺手确认了 Windows 打包的 exe 同样中招。

问题本身寒酸得可笑。代码里用到了一个叫 bridge 的对象，从头到尾没有哪一行创建过它。往上翻记录，前一个 PR 给应用接了一个原生对话框桥，调用它的那些代码都写好了，唯独创建它的那一行漏了。源码里同样没有这一行，也就是说它从写下的第一天起就不存在。

【图1 文生图占位，提示词见 2026-09-05-devlog-images.md】

测试全绿也是真的，但要拆开看。平时跑的测试，测的是本地启动的前后端，前端起在本地的端口上，后端服务也起在本机，请求在两个本机进程之间来回。发到用户手里的却是另一个东西，封装好的 dmg 安装包，图形界面的启动入口只存在于这个包里。项目里的冒烟测试跑的还是无界面模式，bridge 这段代码一行都不会执行。环境换了，入口换了，测试的绿灯自然照不到它。

【图2 交付结构图，见 figT3-small.png】

修复本身一行就够，把对象创建出来。一行修完，后面跟了两步正经动作。第一步，发布 v0.15.1 顶回去，下载页同步换新。第二步，在打包入口加了一道静态检查，专门抓这种用了名字却没定义名字的编码错误，接进 CI，当天首跑通过。往后这一类 bug，在打包之前就会被拦在门外，轮不到用户。

【图3 门禁图，见 figT2-small.png】

结果，新版本启动正常，新门禁站了第一班岗。回头数，这个 bug 和前两天写过的透明遮罩是一家的，都住在测试照不到的地方。门禁一盏一盏装过去，灯就多一盏。

最后回答一个大家都想问的问题，这个 bug 是谁写的？就是那个万能的 AI，哈哈。
