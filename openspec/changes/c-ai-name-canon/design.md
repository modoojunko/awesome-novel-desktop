# Design — 主线专名口径

## Context

三处需要专名口径的产出（起草 fullstory、校准三问）此前只有一句手抄的「名字照设定原文写全」，而**主线链手里没有名册**——模型只能从世界块的自由文本里猜哪些是"设定的名字"，于是把作者旧稿里的派系词（豢养派这类）当设定用。用户要求通用框架，不许按个案打补丁。

## Goals / Non-Goals

**Goals:** 一条与题材/作者无关的口径，能覆盖任意书：规则单源、名册数据化、违规可检测、只提醒不越权改稿。

**Non-Goals:** 本批不动拆卷/拆章/章纲起草/写正文（用户明确）；不做自动改写（实测无效）；不做前端展示（`name_warnings` 留给后续 UI 或体检通道）。

## Decisions

**D1 框架＝规则×名册×检测 三件套，缺一不可**（真机三步对照得出）：
- 只有规则 → 无效（产出照旧带旧派系词）；
- 规则＋名册 → 有效（同书重跑：旧派系词消失、设定注记里写过的词保留）；
- 检测＋自动纠正 → 无效（点名要求改名，纠正轮照旧沿用，白烧一次调用）→ 砍掉，改**只提醒**。

**D2 规则与名册分离**：`prompts/name_canon.prompt`（措辞、单源，被 `{name_rules}` 引用）＋`settings/name_registry.py`（数据：`known_names`/`roster_text`）。原因：措辞要跨书稳定，名册必须按书生成；两者混在模板里没法同时满足。
备选（弃）：把名册拼进规则文本——那份文本会被缓存/对拍，掺数据后不可复用。

**D3 检测＝申报面＋确定性扫描**：模型自报（输出 `names` 字段）**会漏报真问题**（实测：旧派系词没申报，反倒把地点误报一串）→ 加与模型无关的扫描：以组织/派系词尾（派/会/团/教/议会/兄弟会…）为锚，向前取 2–6 字窗口，**从最短候选试起**，命中名册或"世界设定原文中出现过"即放行（这样「主战派」写在势力注记里就不会误报）。
精度取舍：候选须纯汉字、剔除粘连字（不/的/与/没…）、词尾去掉过泛的（局/署/门/社/队/家族）；**地点类不判**（世界里的地名是散文，提取面模糊，判必误报）。宁可漏报不误报——真机实测过误报代价：白跑纠正轮。

**D4 违规只提醒**：`value.name_warnings`（前端未知键，零影响）；体检第五条是既有的人读通道。SHALL NOT 自动改稿——改稿会把作者的叙事决定权拿掉，且实测无效。

## Risks / Trade-offs

- [名册把旧稿的合法自造名也"合法化"] → 名册只收**登记面**（角色卡/势力表/地点），不收散文；旧稿词天然不在册。
- [扫描漏报] → 词尾表可扩；漏报只影响提醒，不影响正文正确性。
- [长名册撑大提示词] → 名册是短清单（角色名+势力名+地点），与既有【人物档案】同量级。
- [与「关键词尽量吸收」的张力] → 起草要求句已写明「专名除外：人物/势力/地点的名字以设定为准」。

## Migration Plan

纯后端提示词与响应附加字段；无存储/接口形状变化。回滚＝回退 commit。改动后端需重建 client-backend 镜像才生效。

## Open Questions
