# c-kb-book-scope · 开书导入题材默认设定——作家的知识与书的知识分家

## Why

新人漏斗的关键一步：拆书把参考书拆进知识库（题材/手法/文风/文笔/世界全沉淀）→ 开新书选题材 → **此刻**应该自动把知识库里该题材的默认设定导入本书——AI 立刻有料可写，正文生成质量立刻可见，付费意愿随之而来。现状：开书后提示词近乎空起步（设定未填、写法块无库可挑、需要手动启用库＋填设定才能体验 AI 质量），是明确流失点。本变更把「作家的知识」（账号级知识库，经验母本）与「书的知识」（书级副本，开书时快照＋独立演化）分家：母本持续生长，每本书拿到开书当时的副本，书内演化互不串扰。

## What Changes

- **开书自动导入**：开书/建书选题材确认时（事务内）自动复制知识库中「题材命中＋跨题材通用」全部概念条目（手法/文风/文笔/世界设定/角色原型）进书级知识副本（新表 kb_book_entries，novel_id 域）；同时自动落**基线设定面**：题材默认库的文风/文笔基线 → writing-style KV、世界设定基线 → world KV（来源标注「知识库·题材」）——即自动启用题材默认库的快照面
- **选择器切源**：写法块选择器改读书级副本（不再扫账号库）；反馈权重（有用/没用）随副本条目 id 天然书级
- **双向隔离**：书内永不回写作家库；作家库后续新增不自动进老书——老书给「库有 N 条新增」差异预览＋一键增量导入（交互照批3 来源行）
- **复制即脱离**：作家库删条目不影响已复制副本（复制语义非引用）
- **空库零阻塞**：知识库无题材条目 → 复制零条，开书流程不报错（空态 CTA 引导拆书/手录）
- **存量书补平**：设定面板给「导入题材知识」入口（一键复制，幂等）
- **单书备份**：kb-book.yaml 扩书级知识段（兼容键不升 format_version）

## Capabilities

### New Capabilities

（无——落在既有能力上）

### Modified Capabilities

- `knowledge-base`: ADDED 书级知识副本／开书自动导入／选择器书级取数／反馈书级／存量书补平 需求组
- `backup-restore`: ADDED 单书备份书级知识段需求

## Design Impact

- 受影响端：**C端 only**（S端不动；无提示词包变更——复制是数据搬运，块文案仍是代码常量）
- 受影响屏/弹层：设定面板（新增「导入题材知识」入口＋「库有 N 条新增」差异行，照批3 来源行交互）；知识库页零改动；开书向导选题材确认步零 UI 变化（导入是后台事务，成功后 toast 一句）
- 对象状态：新表 kb_book_entries（无新全局组件状态）；写法块只读条不变
- 两端共享段：不触碰
- 是否需要原型先行：否（来源行交互复用批3 既有形态）
- 设计工件：实现侧自查

## Gazette

- 拍板依据：boss 2026-11-02「拆书→开新书，直接开新书选题材导入知识库内的默认设定——新人操作感受＋尽快体验正文生成＋付费意愿」（产品定位）
- 与批3（c-kb-snapshot 启用落设定）的关系：开书自动导入＝**自动启用题材默认库**（快照面＋知识面一次到位）；批3 的手动启用制保留（作者中途加库走老路）
- 与 c-kb-write-block 的关系：选择器切源（digest_candidates 读书范围）；text_snapshot/竞态复用/影子转写/回声闸等批F 语义全部不变
