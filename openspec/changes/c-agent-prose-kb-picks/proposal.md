# 提案：正文编排真正采纳知识库文笔/文风＋picks 参数不再静默吞掉（c-agent-prose-kb-picks）

## Why

2026-11-26 真机实测定诊（《我在夜晚打吸血鬼》第 7 章）：对话框编排生成正文时，`kb_search_craft` 只返回 3 条候选且全是手法（倒计时压迫／装弱反制／道具盘点否定法），文笔/文风零候选；本书文风三区为空；agent 只好把「文风与人味红线」六条**自编**进提示词。这不是模型偷懒，是三层结构性断点叠加：

1. **候选池结构上不含文笔/文风**：官方基线 8197 条里，文笔 1821＋文风 2003 全部是全书级（`scope=base`），场面级（`scope=scene`）**0 条**；而 `kb_search_craft` 的候选域 `digest_candidates` 只把 `scope=scene` 的文笔/文风放进 style 组——style 组恒空，候选池永远只有手法。
2. **全书级文笔/文风唯一的正门没走**：按规格，全书级文笔/文风走书级「文风三区」，本书三区全空，也没走「按题材从知识库填文风」——而西式奇幻现成有 31 条文风＋27 条文笔（全书级、`when_json` 全空，正是 kb-draft 口径）。
3. **picks 被静默吞掉**：agent 实际填了正确 id（`9462765e-…`＝道具盘点否定法，库里确认有效），但把 `picks` 传成 JSON 字符串；`draft_prose_plan` 只认 list，`isinstance(picks, list)` 为假直接清空，`invalid_entry_ids` 也为空，回执误报「写法条目未命中」。agent 自己都发现了矛盾，只能手写细则代偿。

同时工具文案（「匹配文风文笔条目」）与实现（只出场面级、恒空）错位，agent 与作家都无从知道「文笔/文风为什么没来、该去哪里配」。本次把这条链修直：让编排至少能拿到知识库的文笔/文风文本（书级草稿，只读），让 picks 不再被参数形态静默丢弃，让「未配置」变成可见状态而不是空承诺。

## What Changes

- **`draft_prose_plan` picks 参数契约**：接受 JSON 字符串形态的 picks（剥壳后按数组处理，与 chips/dict 剥壳同判例）；无法解析或非数组时**明确报错**，SHALL NOT 静默清空；回执区分「未带条目（picks 空）」「N 个 id 无效已剔除」「已解析 N 条」；picks 为空时回执点名「提示词里若写了知识库条目，请把 entry_id 放进 picks」。
- **`kb_search_craft` 候选分桶**：返回结果按概念分段——手法候选／场面级文笔文风候选分别取前 N；style 段为空时明确说「基线/库内没有场面级文笔文风条目（全书级不参与写章检索）」。
- **新增书级文风草稿出口（只读附注）**：当本书文风三区为空时，`kb_search_craft` 复用 `style_draft_from_kb` 的取数口径（同题材＋通用、`when_json` 空、文风/文笔），按本章剧情重合度取前 6 条（name＋how），以「本书文风三区未配置」段附在检索结果后；标注「非写章块条目、不进 picks；建议在设定·文风 → 按题材填文风采纳，长期生效」。agent 可据这段文本在提示词里引用，但工具 SHALL NOT 写设定。
- **文案对齐**：`kb_search_craft` 工具描述与正文页纪律（`scopes.py`）改为准确口径——写章候选＝手法＋场面级文笔/文风；全书级文笔/文风走书级三区，检索只给草稿提示。
- **回执可见化**：方案卡回执在本书文风三区为空时明说「本书文风三区未配置，正文将缺少书级文风基线」，并给出口（设定·文风 → 按题材填文风）；不再只说「按本书文风设定生成」。
- **书级通用与章级场景的裁决（2026-11-27 boss 口径）**：书级三区是全书通用基线；具体章节按剧情场景采用知识库或作者写的场景条目；重复做**语义去重**（同义/近义只留更具体、更贴本章的一条）；冲突**按本章剧情判断哪种更合适**（判据：贴场面节奏、贴人物声线、念读顺口、不与书级基调撕裂），不以书级无条件压章级；裁决与理由 SHALL 在方案卡可见（picks.reason / 本次写法要求），作者过目；作者章级显式覆盖（文风影子）高于自动裁决。
- **测试**：picks 字符串剥壳／非法形态报错／分桶候选／书级草稿附注／三区空提示／书级-场景去重与裁决纪律，全部进单测；不改前端组件。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `assistant-tools`：`kb_search_craft` 候选按概念分桶＋书级文风草稿只读附注；`draft_prose_plan` picks 形态兼容与失败可见回执。
- `knowledge-base`：「按题材取文风草稿（只读）」的消费面扩展——编排工具可在本书文风三区为空时读取同一份草稿作为提示词参考素材；SHALL NOT 写书设定，采纳仍走既有 `PUT /settings/style`。
- `prose-writing`：新增「书级通用与章级场景的语义去重与剧情裁决」Requirement——书级基线默认生效、章级按场景选材、重复语义去重、冲突按本章剧情判断（顺口判据）、裁决在方案卡可见。

## Impact

- 后端：`client/backend/assistant/tools_kb.py`（kb_search_craft 分桶＋草稿附注）、`assistant/tools_cards.py`（draft_prose_plan picks 剥壳与回执）、`assistant/scopes.py`（正文纪律文案）；复用 `settings/style_kb.py` 的 `style_draft_from_kb`（只读，不改其存储语义）。
- 测试：`client/backend/tests/` 下 assistant 工具/编排相关用例新增与回归。
- 无前端组件改动、无新端点、无数据库迁移；方案卡结构不变（仅工具回执文本变化）。
- 挂账（不在本次）：`c-agent-dialog-prose` 规格归档时同步「按剧情动态匹配」条款的分桶措辞；拆书产出 `when`＋存量回标＋基线 v6 由 `c-kb-scene-tagging` 负责（本变更只做消费面与草稿提示）。

## Design Impact

无用户可见界面改动：不新增/修改任何屏、弹层、组件或状态语言；方案卡既有渲染结构不变。仅工具回执与 agent 转述文本变化，不触碰两端共享段，无需原型先行，无 Design Impact 门禁项。
