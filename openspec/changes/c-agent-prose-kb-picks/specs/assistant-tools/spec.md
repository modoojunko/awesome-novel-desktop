## ADDED Requirements

### Requirement: 写法候选按概念分桶并附书级文风草稿

`kb_search_craft` 的检索结果 SHALL 按概念分段返回：手法候选段、场面级文笔/文风候选段；两段各自按既有确定性打分排序取前 N（N 为调用方 limit）。某段零候选时 SHALL 明确说明原因——场面级文笔/文风段为零时 SHALL 说明「库内没有场面级文笔/文风条目；全书级文笔/文风不参与写章检索」，SHALL NOT 静默省略该段或让调用方误以为知识库只有手法。

当本书文风三区为空（`style.role/rules/craft/few_shot_examples` 全空）时，检索结果 SHALL 追加「本书文风三区未配置」段：按本书题材取知识库**全书级**文风/文笔草稿（与 `GET /settings/style/kb-draft` 同一取数口径：同题材＋跨题材通用、`when_json` 为空、用户条目＋官方基线 merged），按与本章剧情的词重合度取前 6 条（名称＋写法短句）。该段 SHALL 标注「非写章块条目、不进 picks；建议在设定·文风 → 按题材填文风采纳，长期生效」。工具 SHALL NOT 写任何书设定或 KV。

当本书文风三区已配置时，SHALL NOT 追加该草稿段（避免与书级文风重复）。

#### Scenario: 候选按概念分桶

- **WHEN** 本书题材内同时存在手法条目与场面级文笔/文风条目，且均与本章剧情有词重合
- **THEN** 结果分「手法」「场面级文笔/文风」两段返回，各自排序取前 N，调用方可分别挑选

#### Scenario: 场面级文笔/文风为零时说明原因

- **WHEN** 候选域内文笔/文风条目全部是全书级（`scope=base`），场面级为 0
- **THEN** 场面级段 SHALL 明确显示「无场面级文笔/文风条目；全书级不参与写章检索」，SHALL NOT 只返回手法段而不解释

#### Scenario: 三区为空时附书级草稿

- **WHEN** 本书 `style` 三区全空，且知识库存在本书题材的全书级文风/文笔条目
- **THEN** 检索结果追加「本书文风三区未配置」段，列出至多 6 条草稿（名称＋写法短句）与采纳出口；书设定与 KV 均不发生写入

#### Scenario: 三区已配置不附草稿

- **WHEN** 本书 `style` 三区已配置且存在书级文风基线
- **THEN** 检索结果不出现草稿段（书级文风由 system 层 `{style_block}` 承载）

### Requirement: 方案卡 picks 参数形态兼容与失败可见

`draft_prose_plan` 的 `picks` 参数 SHALL 同时接受数组形态与 JSON 字符串形态（字符串先按 JSON 解析，解析结果为数组则按数组处理）。解析失败或结果非数组时 SHALL 返回失败回执并说明原因，SHALL NOT 静默按空数组处理。

回执 SHALL 区分三种状态并如实呈现：未带条目（picks 为空）、N 个条目 id 无效已剔除（逐个点名）、已解析 N 条（列条目名）。picks 为空时回执 SHALL 提示「提示词里若引用了知识库条目，请把对应 entry_id 放进 picks」，避免「对话里说选中、卡上却零条目」的自相矛盾。

#### Scenario: JSON 字符串形态成功解析

- **WHEN** agent 以 `picks: "[{\"entry_id\":\"e1\",\"reason\":\"…\"}]"` 字符串形态提交
- **THEN** 方案卡 picks 解析为 1 条有效条目，生成时写法块按该条目注入；回执显示「已解析 1 条」而非「未命中」

#### Scenario: 非法形态明确报错

- **WHEN** `picks` 是既非数组也非合法 JSON 数组的形态（如纯文本、对象、坏 JSON）
- **THEN** 工具返回失败回执并说明期望形态，SHALL NOT 出卡、SHALL NOT 静默清空

#### Scenario: 空数组如实说未带条目

- **WHEN** `picks` 为 `[]`
- **THEN** 方案卡正常出卡，回执明确「未带写法条目」并提示核对提示词里是否引用了未登记的条目

#### Scenario: 无效 id 剔除并点名

- **WHEN** `picks` 含一个库内不存在的 entry_id
- **THEN** 回执显示「1 个条目 id 无效已剔除」并带出该 id；有效条目照常进卡
