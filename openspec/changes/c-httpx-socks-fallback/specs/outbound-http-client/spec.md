## Purpose

C 端后端全部出网 HTTP 调用（S 端 API、更新检查、设备激活、提示词包同步、朱雀检测、
连接探针、AI 供应商）对本机代理配置的韧性契约：代理可用则走代理，代理配置异常则
降级直连，代理配置问题绝不把业务端点打成 500；无代理路径行为不变。

## ADDED Requirements

### Requirement: 本机代理下的出网连通

当用户本机配置了代理（Windows/macOS 系统代理，或 HTTP(S)_PROXY/ALL_PROXY 等环境
变量，形态含 HTTP 与 SOCKS），桌面端出网调用 SHALL 能经该代理正常完成，与系统浏览器
同路径。发布产物 SHALL 内置 SOCKS 代理运行时支持，使 SOCKS 形态系统代理下出网调用
不依赖降级路径。

#### Scenario: SOCKS 系统代理下登录检测可用（人工验收——Windows 注册表路径 CI 不可复现；CI 自动化等价口径＝代理环境变量形态）

- **WHEN** 用户 VPN 客户端把 SOCKS 代理注册为系统代理，且桌面端已打开登录页轮询
- **THEN** 登录检测对 S 端的出网调用经该代理正常完成，不再出现构造期异常导致的端点 500

#### Scenario: HTTP 系统代理行为守恒

- **WHEN** 用户本机系统代理为 HTTP 形态
- **THEN** 出网调用行为与本改动前一致（走该代理，无新增分支介入）

#### Scenario: 发布产物内置 SOCKS 支持（构建验收——解包特征串，见 tasks 3.2）

- **WHEN** 对发布产物解包做特征串检查
- **THEN** 可检出 SOCKS 代理运行时支持组件存在（自证「修了」且「带上了」）

### Requirement: 代理配置异常降级直连

代理配置导致 HTTP 客户端无法构造时（典型：SOCKS 代理已注册但运行时支持缺失），
出网调用 SHALL 降级为无代理直连并完成本次调用——返回业务结果，或在网络确实不可达时
返回既有的结构化网络错误形态；MUST NOT 以未捕获异常把业务端点打成 500。

#### Scenario: SOCKS 支持缺失时降级不 500

- **WHEN** 系统代理为 SOCKS 形态但发布产物缺失对应运行时支持（如依赖被裁剪）
- **THEN** 出网调用降级直连完成，业务端点返回业务结果或结构化网络错误，HTTP 状态
  不为 500

#### Scenario: 降级留痕可诊断

- **WHEN** 发生降级直连
- **THEN** 留痕日志含降级原因与代理形态（scheme＋host:port），可据此定位「哪个用户
  的哪种代理配置触发了降级」；日志 MUST NOT 含代理 userinfo/凭据

### Requirement: 无代理路径行为不变

用户本机未配置任何代理时，出网调用 SHALL 与直连现状行为相同：不引入代理协商、
不触发降级分支、超时与错误语义不变。

#### Scenario: 干净环境直连

- **WHEN** 无系统代理、无代理环境变量的机器发起出网调用
- **THEN** 直连完成，行为与本改动前相同（降级分支不进入、无代理相关日志）
