# c-chars-confirm-scope — 设计

## 一句话

角色面板里同时存在两个粒度：**卡级**（自动保存、卡头状态）与**整项级**（确认门禁、设定进度）。本 change 让两者在**措辞、位置、命名**三处各归其位，不改任何判据。

## 页脚提示：按"这次会走哪档"出（文案冻结）

提示行的数据源＝列表响应既有字段：`items[].gaps`（后端 `card_gaps`：非路人卡六项、路人卡只 `剧情定位`）、`gate.no_protagonist`、以及页脚已有的 `confirmed`（决定按钮这次走哪一档，与后端 `!confirmed → first=true` 的分派同源）。

| 情形 | 文案 | 语气 |
| --- | --- | --- |
| 书里没有主角卡 | 确认「角色」要先有一位主角——在人物卡上把谁点成主角 | warn |
| 未确认（第一次确认档）且主角缺项 | 还差：主角《{名}》缺 {角色名称/一句话人设}（第一次确认只看主角） | warn |
| 未确认且主角写全 | 主角写全了——第一次确认只看主角；配角、反派后补也行，改动会自动保存 | note |
| 已确认且存在缺口卡 | 还差 {N} 张卡：{类型}《{名}》缺 {≤3 项，多则缀「等」}（N=1 时为「还差：…」） | warn |
| 已确认且无缺口 | 已确认 · 改动自动保存，可随时重新确认 | note |

- **为什么不恒按完整档列举**（原型 `syncFoot()` 的口径）：第一次确认档只看主角，若脚注此时就报配角的六项缺口，会把"点了能过"说成"过不去"。提示必须与按钮这次的实际判据一致；原型 demo 未分档（其 gate 演示不分档），故此处为**实现侧对原型的口径补正**，登记 ADJUSTMENTS。
- **为什么点名首张卡而不列全**：`.settings-v .panel-foot .warnline` 是 `nowrap + ellipsis`，长列表会被截断；"首张卡 + 张数"信息密度最高，完整清单仍由点击后的后端回执（「还差：X 缺 …（共 N 张卡）」）兜底。
- 数据来源坚持**列表响应**而非新端点：`gaps` 早就在响应里（前端此前零消费），单卡补写后 `flushQueue` 已重取列表，摘要天然新鲜。

## 按钮与回执：按保存模型分派

| 面板 | 保存模型 | 未确认 | 已确认 | 成功回执 |
| --- | --- | --- | --- | --- |
| 角色 / 伏笔 | 自动保存（字段级防抖落库） | 确认完成 | **重新确认** | 「X」已重新确认 |
| 简介 / 题材 / 世界 / 主线 / 文风 | 表单制（脚部提交） | 确认完成 | 保存修改（不变） | 「X」已保存（不变） |

「保存修改」对自动保存制面板名不副实：改动在编辑瞬间就已落库，按钮真正做的是重新跑门禁并把内容指纹基线前移（伏笔＝快照指纹、角色＝strict 档门禁＋落 `character_gate`）。故改名并同步回执词，避免"点它才算保存"的误读。

## 卡头保存态

四态文案加对象限定词（模板：`这张卡{saving/saved/dirty/failed}`），并把整个 `char-save-state` 从卡区上方独立一行**移回** `.char-side`（原型 `ch-side`：保存态 / 主角徽标 / 合并·删除 同列）——位置与限定词共同承担"这是这张卡的状态，不是整项"。四态词汇本身不变（saving/saved/dirty/failed 与既有 CSS 档位同源）。

## 取舍与不做

- **不新增后端端点/字段**：`gaps`/`no_protagonist`/`confirmed` 三样都已在手，加端点会把"一句话提示"变成接口契约。
- **不改成"每张卡都要单独确认"**：那是产品语义变更（门禁两档是 character-settings-v2 拍板），超出"分家"范围。
- **不动「确认即前进」**：确认后跳下一项是设定引导的既有节奏；脚注把"确认的是整项"讲清后，跳转不再是意外。
- **不给列表行加缺口角标**：数据够做，但属功能扩展，留待单独立项（本轮以"说清楚"为目标）。

## 差异与登记（`ADJUSTMENTS.md`）

1. 页脚提示按档位（原型 `syncFoot` 恒按完整档）＋五态文案。
2. 已确认态主按钮「重新确认」（原型主按钮恒为「确认完成」，无已确认态文案；实现侧原为「保存修改」）。
3. 卡头保存态加限定词「这张卡…」（原型为无主语「已自动保存」）。
