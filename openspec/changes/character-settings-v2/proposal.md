# character-settings-v2

> 本稿已过第二轮三方评审（架构师 / 后端 / 提示词）。评审补正已并入下列各节；仍未定的口径集中在文末「待拍板」。

## Why

「设定 · 角色」现在的实现撑不起它真正的职责——写每一章时告诉 AI「谁在场、谁想干什么」：14 个平铺字符串字段没有结构、关系只是一格自由文本、AI 只有一条死路径（前端零调用）、作者无法删除或合并角色。更根本的是**身份问题**：角色卡的存储键是"文件名"（派生字符串），而卡内 `name` 可以独立编辑，章纲又按**显示名**引用角色——键名与卡名一旦分离，改名或合并就让写章读卡**静默落空**（今天只靠"前端改名时不改键"侥幸活着）。

设计侧已出 v4 原型并完成两轮评审，本次一次做到位：角色从「KV 派生键 + 大 JSON」升级为**真表 + id 主键 + 关系型设计**，章节出场引用改存 id，并按原型落地中栏面板与右栏 AI 四能力。

## What Changes

**存储与身份（BREAKING）**
- 新增 `characters`（id／novel_id／seq／name／aliases／role／persona／dossier／cog／legacy／rev）与 `character_relations`（owner_id／other_id／类型／立场／说明／记录章节）；`dossier` 与 `cog` 用 JSON 列（**理由：schema 指纹一变就全量留档，拆列等于"以后每加一格就再留档一次"**）。
- **章节出场引用改存 id**：`chapter_characters.character_id`（可空，`ON DELETE SET NULL`）＋ 保留 `character_name` 作快照；**API 契约 `outline.characters` 仍是名字数组，只在存储层做"名字 ↔ id"解析**——这样写章、辅助、归档、版本快照等消费方零改动。
- **出场角色的写入口要一并换控件**：章纲「出场角色」现在是自由文本（一行一个名字），不改控件就必然出现未命中名字。
- **同批退役 KV 读写路径**（`character:` 前缀的键与 `CHARACTER_DIR` 若干调用点）——注意不是"迁移淘汰数据"：老库按单轨政策被留档、新库生来没有这些键。
- 升级走单轨：**导入**把老包角色段按映射搬进新格（下表），**导出**角色段改走新布局并升 `format_version`，保留 N-1 读窗（只能是"新版读老包"；降级不可用 ⇒ 升级引导必须前置"先导出备份"）。
- **老字段映射（14 老键 + 2 隐藏键）**：`appearance→dossier.look`、`background→dossier.background`、`speech→dossier.speech`、`world_view→cog.w3`、`self_image→cog.s2`、`values→cog.v2`、`abilities→cog.p2`、`skills→cog.p6`、`environment→cog.e1`；`possessions`／`experiences`／`relationships`／`state_history`／`personality` **五个无归宿字段只留原文**（`legacy` 列，不上界面）；映射有歧义的键（`self_image`／`environment`）两侧原文一并留档作回滚基准。导入后门禁会报缺口（老包没有 `persona`／`剧情定位`／`p3`／`p4`）——这是诚实行为，导入回执要说明。

**行为**
- 中栏面板：角色列表按主角／配角／反派／路人分组折叠 + 搜索 + 添加置顶；人物卡 ＝ 身份头／一句话人设／基础档案 6 行／认知六层 30 格（技能入 ④ 能力层、语言特征入基础档案）／人物关系；**角色可删除、可合并**，两者走同一份回执。
- **人物关系改单向**：只保存「这个角色怎么看别人」，同一对方一条，可编辑可删除；合并时把两边记录归到目标卡并按对端去重（自己对自己的记录自然消掉）。
- **撤销**：删除 / 合并 / 删关系三类破坏性操作可一步撤销。评审结论：合并的"去重"会删掉关系行，前像不在任何当前状态里 ⇒ **落地需要一张单行前像表 `character_ops`**（会话内一步撤销、可 TTL）。这与"不建留底表"冲突，见待拍板。
- 右栏 AI 四行只对当前角色：人设补充（唯一"覆盖型"，保留最近 5 稿）／基础信息补充／认知补充（**只补空格**：以"服务端此刻的空值"为唯一判据；性别、年龄不进候选、不进白名单、采纳时再挡一次，且**不做成 400**）／一致性体检（角色 × 简介／题材／世界／主线，逐项给 **`ok`／`warn`／`conflict`／`miss`** 四态 + 一句依据 + 可跳转，**只提醒不拦确认**；项名与跳转目标由服务端常量出，并**按现实向／角色类型出变体**；**绝不扩世界页的 `_CHECK_STATUS`**，否则会把"矛盾"在世界页显示成"缺失"）；四行全锁 PRO。
- 改动自动保存（单格提交 + 乐观锁），设定页不再有「存草稿」；**保存态复用既有四态阶梯**，失败态要给可点击重试。
- **写章侧的「角色初始状态」块换供给源**：今天它恒空（段级 `characters` 没有生产者 + 写读键名不一致 + `personality` 键不存在），改为由**六层主格（w1／s1／v1／p2／b1／e3）＋ `dossier.speech`** 供给（每格 ≤40 字、每人 ≤120 字、块 ≤5 人），并同批修正 `prompt-crafting` 里"起点→转折→落点"的旧口径与把该块纳入校验锚词。
- **确认门禁两档**：首次确认（该项尚未确认过）只要主角卡完整；此后确认 ＝ 主角 ＋ 每个配角／反派的六项（名称／一句话人设／剧情定位／核心认知盲区／能力上限／能力代价）齐，路人只要基础档案。内容变动**会打回**，徽标进第三态「内容有变 · 待重新确认」（**不含"已确认"字样**——设计语言硬规则要求"凡含『已确认』必须绿色"）；第三态落 `character_gate`（确认时存 `protagonist_id` + 门禁摘要指纹），由 `GET /settings/status` 以**加键**方式下发，**不能塞进 `settings-status.yaml`**（那里是纯 bool 字典，对象恒真会把"未确认"判成"已确认"）。
- 顺手退役死路径：`/ai/{stype}/{field}` 的 characters 分支、`prompts/settings_characters.prompt`、孤儿 `CharacterCreateModal.tsx`（同批删注册表项，否则顺序敏感的查表会 KeyError）。

## Capabilities

**New Capabilities**
- `character-settings` — 角色面板的行为契约：字段与六层认知、单向关系、删除 / 合并 / 撤销、AI 四行与体检四态、门禁两档与退回、免费 / PRO 两态、写章状态块供给。

**Modified Capabilities**
- `creation-flow` — 「角色」不再属于「无 AI 能力的设定项」；内嵌子双栏补「分组折叠 + 搜索 + 大列表」场景。
- `readiness` — 角色判据升为两档 + 退回（第三态由 `character_gate` 派生）；顺手校正 spec 与代码的既有漂移（项数与 genre 判据）。
- `design-system` — 状态语言补第三态与 `conflict`；角色类型 / 关系类型的词汇**用既有 `.chip` / `.pill`**（不新增胶囊形态）；保存态复用既有四态；原型登记进 lint 白名单。
- `backup-restore` — 角色段布局变化：`format_version` 升版 + N-1 读窗（新版读老包）+ 老字段映射规则 + 导入改道（否则角色写进无人读的 KV ⇒ 静默丢）。
- `intro-genre-settings` — 回执单行 / 截断规则、`.ai-sink` 是唯一结果渲染面、右栏能力行结构三条，角色面板都要碰（本轮明确按"面板级差异"处理或豁免）。

**Explicitly not in this change**：`world-settings` / `storyline-settings` 的 AI 信封与响应形状；`chapter-data`；`volume_character_voices` 与 `chapter_knowledge_states` 的名字引用（登记为已知债务）。

## Design Impact

- **受影响端**：仅 **C端**。
- **受影响屏 / 弹层**：设定页 · 角色（中栏面板、人物卡、人物关系区、删除 / 合并面板、右栏 AI 卡与体检结果区）；章纲「出场角色」控件（随 id 化换选择器）；导入 / 导出对话框（角色段契约）。
- **对象状态**（§5）：角色类型＝常态属性；「草稿」沿用 warn；「已确认」绿色；**新增第三态「内容有变 · 待重新确认」（warn，不含"已确认"）**；体检新增 `conflict` 值，**渲染走 err 色**（值名与颜色分开，避免与传输失败态撞名）；AI 在途 / 失败沿用既有 info／err。
- **删除分级**：现役把「删角色」列为 L3（名称输入确认），而原型是卡内联面板无名称输入 ⇒ 二者必须择一并登记（若降级则需"撤销可跨刷新"兜底，见待拍板）。
- **两端共享段**：不触碰；但需登记"角色类型用 `.chip`、关系类型用 `.pill`、删除类按钮的 err 语义、体检两行排用新类名（不改共享 `.chk-line` 作用域）"。
- **原型先行**：需要。v4 原型落 `docs/design-c/prototypes/`、登记 ADJUSTMENTS（含 `.badge` 家族口径、`book.html` 的旧角色面板由本文件取代），并把原型修到能被 design-lint 通过（当前两处类名拼接会被判未登记任意值）。
- **设计工件产出方**：设计侧（本稿）。

## Impact

- **后端**：新表与模型注册；角色 CRUD（列表**聚合端点一次给全**，含编号 / 首次出场 / 更新于 / 缺口；单格 `PATCH` + `rev` 409）；role 唯一主角（服务层单事务先降后升 + 部分唯一索引兜底）；关系 CRUD（`PUT` 幂等 upsert）；merge / delete / undo（单事务）；`chapter_characters` id 化与 10 个写入口、6 处消费方改造；导入映射与导出升版；门禁两档与 `character_gate`；AI 两条端点 + 4 个新提示词 + 1 个死提示词删除；写章状态块换源。
- **前端**：`CharacterManager` 重写为面板（复用 `AiWriterAssistant`／`AiSink`／`ChangeReceipt`，不自造）；章纲出场角色换控件；保存态接入既有四态；e2e 与 parity 基线同步。
- **测试与门禁**：现有 **801 passed** 为基线；已知会破的用例集中在 `test_db_storage`（路由 / list_dir / VALID_TYPES）、`test_readiness`（角色端点与确认）、`test_volume_chapter_crud`（若一并改卷纲发声）。新增覆盖：表约束、PATCH 冲突、关系唯一、merge / delete / undo 精确还原、只补空格与性别年龄不出参、体检四态归一端到端（含"不污染 world"回归锁）、id 化五条回写路径、导入导出九条断言（含 `character:%` 计数为 0）。
- **前置**：`backup-restore` 的 roundtrip 底座（八层断言）在仓库里**缺失**，本 change 开工前必须先补建，否则角色段改动没有回归网。
- **风险 Top5**：① 老库留档重建不可逆（用户从未导出 ⇒ 角色不可自助找回；缓解＝升级引导强制先导出 + 全链演练用旧版造的真库）；② 导入静默丢角色（缓解＝改道 + `character:` 前缀显式报错 + KV 计数断言）；③ id 化期间引用一致性（缓解＝写入口只收 id、未命中落快照并告警、不得静默跳过）；④ 真表后的读-改-写并发（缓解＝单格 PATCH + `rev` 409、归档不再回写角色卡）；⑤ 列表查询放大（缓解＝聚合端点一次给全）。

## 已由设计定稿（v5 已落地，实现照此）

- **删除 / 合并 = L3 名称输入确认**：面板内输入角色名才解锁确认按钮（与现役删除族同档），并写清后果与撤销窗口。
- **体检结果落卡片内**：与人设 / 档案 / 认知共用同一套 sink 语言（`.ai-sink`），右栏只放按钮；「去改」只开合那一层、**不整卡重绘**（否则结果会被抹掉，作者没法边改边对照）。
- **第三态文案 =「内容有变 · 待重新确认」**（不含"已确认"字样，守设计语言硬规则），说明文字补「这一项之前确认过」。
- **状态词汇对回现役词表**：角色类型＝可点击胶囊 `.chip`、关系类型＝状态胶囊 `.pill`、徽标 `ok / warn / prog / empty`、保存态复用既有四态、体检行用新类名 `.chk-row`（不覆盖共享 `.chk-line`）、第四态值名 `conflict`（渲染走 err 色）。
- **体检项名按服务端变体**（力量向 / 现实向两套），`goto` 由服务端常量出。
- 撤销窗口的**文案底线**：会话内 + 明示"保留到继续编辑或刷新之前"；是否落 `character_ops` 前像表把窗口延长，属实现选择（不落表也不违反本文案）。

## 待拍板（审批口需定）

1. **生成类温度**：人设 0.6 ／ 档案与认知 0.4 ／ 体检 0.3（建议），需在 spec 里冻结数字。
2. **人设 5 稿落不落库**：建议不落库（会话内、客户端持有，对齐既有 `AiSink`）。
3. **`volume_character_voices` 是否本批一并 id 化**：建议否，登记已知债务。
4. **`AIClient` 超时与失败记账**：建议单开一个 change，但必须在角色四行之前完成（现在最坏一次点击要 ~20 分钟才落 502，且 502 路径记零账）。
