# prose-writing Delta — 生成按次选择模型（跨配置/供应商，仅本次生效）

## ADDED Requirements

### Requirement: 生成按次选择模型

- 「AI 生成正文」弹窗 SHALL 提供「生成模型」选择位，选项 SHALL 覆盖**全部可用 API 配置（跨供应商）× 各自模型清单**（朱雀检测配置除外），并 SHALL 默认选中本书模型（`project.ai_config_id` + `project.ai_model`）；可选模型（含默认项）少于 2 个时 SHALL NOT 渲染该行——弹窗保持今日形态。
- 选择结果 SHALL 仅作用于**本次生成**：SHALL NOT 写回 `project.ai_config_id`/`ai_model`，SHALL NOT 影响规划类 AI（章纲/大纲/设定/推演）与其他 AI 功能的模型；弹窗每次打开 SHALL 回到本书模型（按次语义：不记忆、不持久）。
- 确认生成时，请求 SHALL 携带所选模型对（`api_config_id` + `model`）**当且仅当**它与本书模型不同；与本书模型相同时 SHALL 走既有本书模型路径，请求与行为逐字不变。
- 服务端 SHALL 在接受生成请求时校验模型对：配置存在且未删除、属于本书用户、`vendor != "zhuque"`、**Key 可用（与本书就绪同一谓词：非空＋可解密＋最近一次连接测试非失败态）**、`model ∈ config.models`；任一不满足 SHALL 在**开流前**以可读错因拒绝——不产生流式响应、不发起模型调用、不落任何正文，且 SHALL NOT 改写本书绑定。**宽严 SHALL 与本书模型路径一致**：同一状态（如 Key 已吊销但清单仍在）挡得住本书配置时，SHALL NOT 被按次覆盖对放行到流内才失败。
- 拒绝文案 SHALL 带可行动出口（换一个模型 / 去「模型配置」补模型），SHALL NOT 只给内部术语。
- 生成记账 SHALL 记**实际生效模型 id** 与该次调用使用的配置 id：本书模型路径记本书绑定对，按次覆盖路径记覆盖对；成功、超时、失败三处记账同口径。

#### Scenario: 默认本书模型

- **WHEN** 作家打开生成弹窗且未改「生成模型」
- **THEN** 确认生成使用本书模型，请求不携带按次模型对（与今日链路逐字一致）

#### Scenario: 跨配置换模型并按次生效

- **WHEN** 作家在弹窗中把「生成模型」换成另一个 API 配置下的模型并点「生成正文」
- **THEN** 本次生成使用所选配置与模型、正文照常流式落库；本书模型与规划类 AI 保持原样（`GET /novels/{id}/ai-model` 不变）

#### Scenario: 单选不渲染选择位

- **WHEN** 全部配置合计只有一个可选模型（或本书绑定的模型是唯一可选项）
- **THEN** 弹窗不出现「生成模型」行，确认生成照常可用

#### Scenario: 非法模型对被拦在开流前

- **WHEN** 请求携带的模型对不可用（配置不存在/已删除 / 模型不在该配置清单 / 配置无可用 Key 或**最近连接测试失败** / 朱雀检测配置 / 只有半对）
- **THEN** 服务端在开流前拒绝并给出可读错因（可换模型或按引导去「模型配置」处理后重试）；无流式响应、无模型调用、无正文落库、本书绑定不变

#### Scenario: 用量记实际模型

- **WHEN** 一次生成完成（或超时/失败）
- **THEN** 用量行记录本次实际使用的模型 id 与配置 id，同一本书里不同模型生成的用量可分辨
