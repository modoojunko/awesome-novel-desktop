# c-scene-density 设计

## Context

字数链横跨三个信号层：抽卡素材（服务端拼装）、写章 user 素材（`to_user_material`）、prompt 最末字节收尾行（代码常量）。仓规分层教义决定 system＝恒定层（本批不动，前缀缓存逐章一致）、凡随章变→代码拼装 user 层；因此四路评审认定的病灶两处都在 C端代码侧、一处上游在提示词模板，修复天然跨两仓。

## Goals / Non-Goals

**Goals:** 抽卡条数与本章字数联动；停笔信号与字数信号互为仲裁不互相折价；「页面显示什么，模型收到什么」在未保存窗口下仍成立。
**Non-Goals:** 不动 system 恒定层文案；不做超限压缩（上不封顶口径不变）；不引入按条数硬约束的服务端拒收（条数仍属模型行为，产品兜＝可见提示＋换一批）；写侧 max_tokens 8192×thinking 截断余量本批不动（观察项）。

## Decisions

1. **档位用锚点不用线性比率**（`plot_count_hint`）：比率「每 300–400 字一条」×条数上限在 >3200 字自相矛盾；先版上限 8 在 2500 即饱和（2500 与 4000 同档，用户否掉）。定档四段 4–6/6–8/8–10/10–12，上限钉存储单源 `PLOT_MAX_ITEMS=12`——全域单调、字数有区分度、永不过存储预算。数字表只住这一个函数：模板写「照素材建议拆」不复制数字（无重复硬要求），前端镜像经**读 TS 源交叉对拍**（`TestPlotCountHintParity`，先例 c-chapter-default-words；两侧各自锁各自的测试拦不住漂移）。
2. **clamp 语义「越界同落 default」而非逐层回落**：body 7000＋存值 4000 → 结果 default。与写章侧同函数同行为优先于链条直觉，已在取值点注释钉死；函数整体迁 `settings/book_prefs_model`——数值单源本家，顺带消掉 chapters→write 跨域边（`chapter_writer` re-export 保兼容）。
3. **16384 拒绝降级仿 thinking-rejection 判据**：max_tokens 字样与上限语义**同现**才降 8192 重打一次；判不准宁可不降——错降使高档截 JSON，把确定性 400 变成难排查的质量劣化。无按模型查表：仓内无模型能力元数据（评审确认），查表数据源不存在。
4. **收尾行三件语义＋防回声**：最末字节是全链最硬信号，扩「场景写足」句对冲只催停；与素材分量行同词不同句（机械判据 <8 字，钉子两枚：分量行、整节），「章末落点」「动作、台词或声响」等字段名与直接管辖枚举短语按跨层同词教义豁免——豁免条已写入提示词仓 AGENTS 治理口径。
5. **存稿代际守卫扩锚**（先例 previous_tail）：老章 write-prompt 存量行缺「字数与场景分量」锚而本轮会出 → 回落重组，否则字数链对存量章打五折；润色三锚资产同罩豁免。均摊 <200 不发分量行（防条数×200 超写），守卫复用同一判定函数（不发不白重组）。
6. **双仓劈叉窗口机制性收敛**：C端 #843 先合→提示词包后翻、`min_client_version` 抬版本闸——新模板×旧代码＝旧条数上限静默截中段（体验差、不坏数据），旧模板×新代码＝素材建议被 system 条数压住（展示失真、可容忍）；顺序反了两种失真都更重。

## Risks / Trade-offs

- 模型不照档位出条数＝不自动纠（判读类不重抽纪律）——先遥测「档内命中率」，低再议卡面角标；均摊行按实存条数现算是天然收敛器（作者删条自动恢复分量行）。
- 小目标章（<1200 字）建议 4–6 条的观感密度偏疏：档位文档如实限定「≥2000 字档密度 330–500 字/条」；观察项，数据触发再补低档。
- 8k 输出模型用户：降级路径每次抽卡多一发失败调用（502 前拦截、留 fail 痕），比整功能不可用可接受。
