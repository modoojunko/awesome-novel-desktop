# c-scene-density — 章正文写不满字数：条数联动与场景分量链

> 补录型 change：实现已随 PR #843（本仓）＋提示词仓 PR #7 落地，本 change 供评审与归档。tasks 全项以实际完成状态回填。

## Why

内测作者实拍：2500 字/章的目标，AI 整章只写 1284 字。诊断＝三处信号互斥：①抽剧情条与字数目标脱钩（每版 2–6 条上限，供给端天花板≈1500 字）；②字数线挂在「章级红线（**优先于字数**与写法）」节内，字面上被降到最低优先级；③prompt 最末字节收尾重申行只催停（「落点之后不写一个字」），全文最硬位置信号在教模型交卷。

## What Changes

- **抽卡（chapter-plot-items）**：素材恒带【本章字数】＋按章字数直给的建议条数档位（锚点制 <2000→4–6、2000→6–8、3000→8–10、≥4000→10–12，上限钉存储单源 12）；每版 2–6→4–12 条（中段 0–4→2–10）、三版预算 4000→9000 字；请求体 `PlotDrawBody.word_target` 携带章纲表单现值（优先于存值）；生成预算 8192→16384、被端点按输出上限打回时降 8192 重打一次；超发剪条出 warning（判读类不重抽口径不变）。
- **写章（prose-writing）**：字数线从红线节拆出独立「字数与场景分量」节（节名仲裁双向：红线照守、字数照达），按实存条数均摊「每条约 N 字、写足一条再进下一条」（均摊<200 不发防超写）；收尾重申行补「每个场景写足」句（与分量行同词不同句防回声）；存稿代际守卫扩「场景分量」锚——老章存量行不再绕过新链。
- **章纲页（workbench）**：字数输入框旁、剧情区标题、查看态三处显示「按本章 N 字，建议拆 X–Y 条场景（现 n 条）」；抽卡请求随表单现值。
- **单源**：`clamp_word_target` 迁 `settings/book_prefs_model`（消 chapters→write 跨域边，re-export 兼容）；档位表住 `ai_plot.plot_count_hint` 单源，模板与前端不重复维护数字（前端镜像有读源交叉对拍闸）。
- 配套提示词仓：`chapter_plot_draw` v3（条数照素材建议拆、「一场戏」口径），见该仓 change 同批。

## Design Impact

- 受影响端：C端（工作台章纲页签一处，三态位：编辑态字数框下、编辑态剧情区标题、查看态剧情区）。
- 用户可见文案：「按本章 N 字，建议拆 X–Y 条场景（现 n 条）」——纯说明行，复用既有 `field>opt` 与 `hint-inline` 版式；无新按钮、无新增语气词（不动 info/ok/warn/err 词表），不涉两端共享段。设计工件＝实现侧自查（文案口径已在四路评审中过产品经理与前端审）。
- 「场景」一词沿用剧情条目既有用户语言（占位文案「是场景不是正文」），非内部术语。
