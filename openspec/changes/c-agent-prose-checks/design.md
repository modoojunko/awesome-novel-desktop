## 决策

### 正文源优先级（为什么上行屏上文本）
- 屏上标注＝编辑器当前文本（含未保存）现算；工具要复现同一批行，必须拿到同一份文本。
- `page_state.prose_text` 在发送时刻由 `ProseHandle.getProse()`（`docToProse(editor.getJSON())`，与 onUpdate/自动保存同一序列化单源）取值；只进 `ToolContext.page_prose`，不进提示词（c-agent-page-ops/#1123 判例：页面真值按需查、不自动注入）。
- 跨章保护：仅当 `chapter_ref == ctx.focus_ref` 时允许用屏上文本；否则一律读已保存正文——屏上文本只属于当前打开的那章。
- 拿不到屏上文本而 `page_unsaved` 含「正文未保存」：结果头如实标注「可能与屏上标注不一致」（read_page_fields 同款如实标注判例）。

### 朱雀存档：过期就不出原句
- 存档是「检测时刻」的结论；正文改过（`fingerprint(所用正文) != prose_hash`）段号与原句都可能对不上。
- 过期只列「第N段〔AI/疑似〕（过期档）」并提示重检，不出原句——防止模型按旧句改新文。

### 为什么不把标注落库
- 人味 findings 是确定性现算（毫秒级、0 额度）；工具每次现算＝永远回答「现在还剩什么」，不存在过期清单问题，落库反而是新的失真源。
- 与 c-renwei-chapter-reset 的语义一致：切章即重新检测，标注是章作用域的内存态。

### 域与触发
- 挂 `ch:prose`＋`ch:style`（两页签都有检测入口）；不搞窄正则 prime，描述即契约（boss 拍板 2026-11-19）；非正文域由 switch_tab 引导。

## 风险
- `page_state` 每消息携带正文全文（一章几千字～几十 KB）：本机进程内 HTTP，可接受；router 设 50000 字上限，超限丢弃并回落已保存正文。
- 工具结果含正文原句（明细预算 2000 字＋朱雀段若干）：仅进本会话转写，不外发、不耗额度。
