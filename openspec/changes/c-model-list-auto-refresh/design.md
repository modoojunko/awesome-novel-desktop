# c-model-list-auto-refresh — 设计

## 背景与约束

- 全系统没有独立「模型表」：唯一持久化的候选清单是 `ApiConfig.models`（`models_updated_at`
  只写不读）。书籍模型、助手底栏、拆书创建/详情全部读 `GET /api-configs` 的快照。
- 2026-10-09 `c-api-config-edit-model` 把编辑态「获取模型」保持为 raw 轻探针（需明文 Key），
  Key 未重填时禁用，并明记挂账：等后续做「已存密钥刷新清单」再立项。
  2026-10-07 `c-api-config-auto-models` 决定 `refresh-models` stub 不动。
- 用户口径（2026-11-27）：**使用前清单就得是最新的**——不接受「打开选择器才拉、等两秒」；
  新模型上线后要在打开列表之前出现。

## 分层

```
供应商 /models
   ↑ 只拉清单轻探针（零生成）
后端 ensure-models-fresh（TTL 10min / 失败退避 5min / 单飞 / 并发 3 / 超时 5s）
   ↑ POST（可指定 config_ids / force）
前端 ModelCatalog 模块级 store（单一数据源，订阅式更新）
   ↑ 调度：启动 / 5min 定时 / 回焦 / 进页面 / 选择器打开（30s 节流）
所有模型选择器（配置页 / 本书模型 / 助手底栏 / 拆书创建 / 拆书详情）
```

## 决策

### D1 保鲜策略住服务端，调度住前端

服务端按 `models_updated_at` 判断是否真出网（TTL 10 分钟），失败退避 5 分钟；
前端只负责在「用户可能用到清单之前」触发 ensure（启动、进页面、定时、回焦、选择器打开），
客户端 30 秒节流防止页面切换连打本地接口。这样「什么时候真的打供应商」只有一处判据，
前端不需要知道 TTL，也不会因为多点触发而放大出网量。

为什么不用服务端常驻定时器：桌面应用关窗即停，后台定时会在无人使用时也出网、且与
「用户使用前」无关；前端生命周期触发更贴合。

### D2 零生成、失败不清快照、不动连接测试结果

ensure/refresh 复用 `fetch_models`（GET 清单端点），不发起任何对话探针；成功且清单
**非空**才写库（已选首项保头、归一/截断），空清单与失败原样透传——
轻探针失败不能把用户可用的快照清空。`last_test_*` 只由真实生成探针写（轻探针不证对话可用）。

### D3 全局单一数据源，而不是每个选择器各拉一次

`lib/modelCatalog` 持有 `configs` 与清单，`useApiConfigs` 改为 store 适配层：
- 配置加载单飞、CRUD 写穿 store、status/test 局部回填；
- ensure 响应按 id 合并清单与 `models_updated_at`，清单内容变化才递增 `version`；
- 启动竞态：清单结果先于配置列表到达时暂存，`load` 完成后并入（否则冷启动的首次
  ensure 会被丢掉）。

所有消费方（`useModelStatus` → 本书模型/助手底栏、拆书页按 `version` 重取）自动拿到新清单。
不这么做的话，同名清单在 N 个组件里各存一份，任何刷新都要逐个接线，漏一个就回到旧快照。

### D4 触发面：使用前而不是使用时

- 应用启动（登录后）——用户从书架走到第一个选择器之前完成；
- 前台每 5 分钟——长驻页面兜底（pywebview 的 focus 事件不可靠，定时是主力）；
- 窗口回焦/可见——尽力补一刀（沿用 LicenseProvider 的 focus 监听先例）；
- 进入含选择器的页面/面板（模型配置页、本书模型、工作台助手、拆书创建/详情）；
- 选择器打开——兜底触发，**不阻塞**：弹层立即显示缓存，若在途显示「正在更新清单…」，
  回来后列表就地合并（不重置搜索/光标/选择）。
- 手动「获取模型」保留，force 绕过 TTL；未登录不触网。

### D5 失效选中：保留 + 标记，不自动改选

清单按供应商返回结果替换（供应商不再返回的模型从清单消失），但**不改用户的选中值**：
- 配置编辑弹窗/共享选择器/本书模型面板显示「已不在最新清单」；
- 书内 `ai_model ∈ config.models` 的既有就绪判据会把它标成 invalid 并引导重选；
- 生成仍按绑定模型走，失败按真实错误提示。不静默换首项（会改掉用户刻意选择/书绑定）。

### D6 失败轻提示，不打断

ensure 失败不弹 toast；选择器弹层与模型面板显示一行「清单可能不是最新」；
配置页/卡片不额外加噪音。退避期内不反复重试。选择器打开时的在途提示同样是这一行位置。

### D7 保存与卡片不吞新清单

编辑弹窗打开期间后台清单更新：store → 页面同步 `editConfig` → 弹窗内 `modelList` 就地
刷新（不动已选模型名）；保存时 models 由刷新后的 `editConfig.models` 拼装。漏掉这条会把
刚拉到的新模型按打开弹窗时的旧快照覆盖回去（实测路径：刷新 → 直接保存 → chips 回退）。

### D8 编辑态手动刷新与自动保鲜共用执行体

`refresh_models_with_stored_key` 同时服务单配置手动刷新和 ensure；ensure 只额外加
TTL/退避/单飞/并发/超时。手动刷新不经过 TTL（用户显式动作），ensure 默认经过。

## 端点契约

`POST /api/v1/api-configs/ensure-models-fresh`（body：`{config_ids?: string[], force?: boolean}`）

- 仅当前用户的活跃写作配置（排除 deleted / zhuque）；`config_ids` 可选收窄（缺省＝全部；
  空数组＝不刷新任何配置）。
- 每个配置：TTL 内 → 跳过（`refreshed:false, ok:true`）；过期 → 已存密钥轻探针；
  失败 → 记退避并回 `ok:false, error`；空清单（端点不提供）→ 记「已检查」（同一 TTL
  内不再出网）并回 `ok:true, refreshed:false`；非 active / 无 Key 非 ollama → 跳过并说明。
- 200：`{configs:[{id, models, models_updated_at, refreshed, ok, error}]}`。
- 同一配置单飞；跨配置并发 ≤3；单次出网超时 5 秒；`force` 绕过 TTL/退避/空清单检查。

`POST /api/v1/api-configs/{id}/refresh-models`

- 404 配置不存在（含不属于当前用户）、400 已禁用；成功非空才落库并回显清单与时间戳；
  空清单/失败不覆盖已存清单、不动连接测试结果。

## 边界与不做

- 不在每次生成正文前同步清单（延迟/成本）；生成用绑定模型不变。
- 不做自动改选、自动切书绑定；不自动删除用户手填的清单外模型（清单以供应商返回为准，
  手填值若仍在清单里保留）。
- 图像模型（独立 `image_configs`）不接入本机制。
- 不做服务端常驻定时器/推送；关窗不刷新。
- S 端零改动。
