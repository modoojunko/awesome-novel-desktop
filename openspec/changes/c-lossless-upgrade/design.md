## Context

现状约束（详见 proposal.md 的 Why）：

- 库文件按 C端 版本命名（`schema_version.db_filename_for`），首启状态机在建库/分流，搬运引擎为「六步＋预检」（副本列交集 `INSERT OR IGNORE`、源只读、单事务写入目标）。
- 引擎 `EXCLUDED_TABLES={"app_meta"}`：源库 `fernet_key` 行不随行，新库启动期自生钥匙 → 密文死文（新装机器必现；旧 `.fernet_key` 文件仍在的老机器因新库复用同钥而幸免）。
- 目标库写入为**一次事务**（长写锁）、`busy_timeout=5000`；前端无 locked 实现。
- 候选载荷只回 `book_count` 等元数据；`preview` 只回表行数与书数，无清单字段。
- 既有「壳层单点弹窗 + 自定义事件」模式已有两处先例（`legacy-migrate:open`、`pack-modal:open`）；`packProbe` 有内存缓存与 StrictMode 双挂载去重。
- 书架有 `AuthGuard`；`candidates` 端点免登（`loginless-data-exit` 防护面），当前被书架与账户菜单各挂一次。
- 前端 e2e 有请求预算门禁（`shelf-request-budget.spec.ts`：空闲 3s ≤8–10 请求）。

## Goals / Non-Goals

**Goals:**

- 把「带回」从角落入口升级为**首屏告知卡四步闭环**：告知 → 同意（唯一操作）→ 锁定进度 → 完成确认；同意覆盖「作品 + 模型配置」两类对象。
- 让**等价判据**可验收：搬完后的用户可见状态与升级前一致；已知损失（Key 死文、预置题材编辑被覆盖）在本 change 修掉；不完整搬运必须可见且持续提醒。
- 弹窗呈现收敛为**一个宿主 + 一条队列**，数据类优先，队列只延迟呈现不延迟后台动作。

**Non-Goals:**

- **不改库文件命名轴**（「兼容代」＝同代不轮换）——另立 change；本 change 后用户仍会每版见到一次卡片。
- 不改备份包契约、不改安装器目录搬迁、S端 零改动。
- 不做「自动搬运」（产品红线：动用户数据必须用户知晓并点头）。
- 不把搬运改成可后台继续（分表提交/写锁重构）——本 change 保持单事务 + 进度期锁定。

## Decisions

**D1 · 触发面＝登录后的书架。** 书架在 `AuthGuard` 内，未登录本就看不到书架；把卡放在书架即天然只在登录后出现（用户拍板「就是要登录后才执行」）。代价：未登录/断网用户暂不提示、也搬不了——旧文件原位保留，登录后随时能带。
替代：免登登录页面（否决：用户拍板收紧；且会把登录页变成数据操作面）。

**D2 · 进度期锁定，不让离开。** 引擎为单事务长写锁，收回后台后用户去写作会撞 `database is locked`；且前端无 locked 实现。锁定＝最省且不引入并发风险（现有实现即此形态，只补文案与「关窗＝中断」语义）。
替代：分表提交 + 写入口锁（否决：动引擎核心、第一刀变大，留待将来确有「边搬边写」需求时再评估）。

**D3 · 密钥转接放在引擎的收尾修正 pass。** 在搬运同一次目标库连接内（commit 前、DETACH 前），对**按当前钥匙不可解**的 `api_configs` 行，依次尝试源库 `app_meta.fernet_key` 行（staged 副本内 `mig_src.app_meta` 可读——`EXCLUDED_TABLES` 只影响 INSERT 计划，不影响 ATTACH 读取）与数据目录旧 `.fernet_key` 文件（按本次搬运的 `data_root` 解析，不依赖 import 期常量）解密，成功者按目标钥匙重加密后原地改写；两把都解不开的行保持原样并按条计数进报告（`dead_keys`＝搬后目标库全部不可解 `enc:` 行数，含目标既有死文，文案只报事实）。当前钥匙经 `crypto` 模块取（`init_crypto` 已在 lifespan 先行；Fernet 无共享可变态，后台线程使用安全）。仅本次 `api_configs` 有迁入行时执行；源钥行内容非法按「不可得」降级不失败。源钥只读，`app_meta` 仍不搬入目标。
替代：把源钥匙行搬入目标（否决：`crypto` 的 Fernet 为进程内缓存，搬钥行会让运行期与库行脱钩——重启前后行为不一致；且与「app_meta 不搬」纪律冲突）。替代：迁移前先 `init` 目标库不生成钥匙（否决：启动期已初始化，改序牵连面大）。
只修不可解行 ⇒ 天然幂等、绝不伤目标原生密文、无需判断哪行是新插。

**D4 · 预置题材「源行胜出」以「源库有行即覆盖」实现。** 种子表清单固定为 `genres` + `genre_vocab`（即 `ensure_seed_*` 播种表；新增播种表须同批登记）；覆盖机制＝同一事务内 `DELETE` 目标表中源库同 PK 行后 `INSERT OR IGNORE` 源行（不用 `OR REPLACE`，避开替换触发器语义差异）。不引入逐字比较（会把「旧版出厂文本」误判为用户编辑，且需版本化种子快照）；`ensure_seed_genres` 只插缺失、不覆盖（lifespan 先播种 → 搬运覆盖 → 下次启动播种只补缺），语义单点。
代价：旧版出厂文案会覆盖新版对**已有**题材的改进（新用户看新文案、老用户看旧文本）；新版**新增**题材仍会补上。发布说明写明。

**D5 · 候选载荷增只读清单字段。** 作品（书名＋字数）、模型配置（条数＋名称）；**密钥材料永不返回**；字段缺失时前端降级为只报数量，不阻塞搬运。清单在 `preview`/`candidates` 只读连接上取，不额外打开源库。

**D6 · 多候选只针对 `recommended`（最接近当前版本）那一份。** 卡上不列候选、不做选择；其余候选在卡上留一行提示并在「设置 › 本机旧版本数据」可达（沿用既有候选列表/排序/白名单，选择步仅存于设置路径）。

**D7 · 弹窗宿主＝扩展既有「壳层单点 + 事件」模式。** 新 host 组件挂载于壳层，业务方以事件入队（沿用 `legacy-migrate:open` / `pack-modal:open` 先例）；同一时刻只渲染队首，优先级 数据 > 能力 > 提示。**放行条件＝带回条目由用户点「完成确认」收尾**（job 结束不放行）；**队列只延迟呈现，不延迟探测与下载**。
替代：把带回卡做成页内卡（不占弹窗位；不否决其价值，但不采纳——用户拍板复用同一个弹窗，且页内卡会与既有 notice 层叠）。

**D8 · 完整性判定单源、三处消费。** 抽出「完整达成」判定（无整表跳过 ∧ 无 FK 违规 ∧ `book_count_source == book_count_migrated`），契约＝**吃搬运 report dict**（`migration.last` 内嵌完整 report），history/演练侧经适配器归一后消费；同时供：① 告知卡/常驻行的抑制与继续提醒 ② 清理白名单 ③ 演练对拍结论。现状是 stamp 相等即抑制、完整性只用于清理白名单——必须收口。

**D9 · 「稍后带」为新状态，不复用 `migration.dismissed`。** 现有 dismiss 语义为「永久静默直到 stamp 变化」，会让「未达成」永久不可见。新状态：常驻行 + 次级出口「本版不再提醒」＋「设置 › 本机旧版本数据」永久入口。抑制键与 `migration.*` 同存于**当前版本库 `app_meta`**、绑候选 stamp——下一版建新库时键天然不存在＝自动重开（无需把客户端版本号编入键名；SHALL NOT 落数据目录文件，防装回旧版读到泄漏的抑制态）。候选载荷以「完成态 + 抑制态」两个独立字段取代单布尔 `suppressed`。

**D10 · 前端数据层抽书架级单例。** 候选探测与进度轮询收敛到一处（现状：书架 + 账户菜单各挂一次 + 向导内轮询），并限定「有 running 任务才轮询」，以通过请求预算门禁。

## Risks / Trade-offs

- [锁定期间用户没法写作] → 搬运通常几秒（库为几 MB～几十 MB）；文案明示「请保持窗口开启」；关窗＝中断（单事务无半成品），下次重新提示。
- [密钥转接误伤目标库密文] → 只修不可解行、幂等、不覆盖目标钥匙行；演练含「目标库先有自加密文」样例。
- [两把源钥匙都不可得] → 按条计数提示（条件文案），不写「不用重新粘贴」；运行期走既有 503 引导。
- [预置题材文案分叉] → 发布说明写明；这是一次性取舍，好过「用户编辑被覆盖」。
- [队列让位使能力包提示延后] → 下载不延迟；未收尾则下次进入页面重新评估——用户不会拿到「没装能力」的状态，只可能晚看到提示。
- [只读清单字段扩大免登端点的返回面] → 只回书名/字数/配置名；端点仍免登 + 回环防护；密钥永不返回并加断言。清单仅对 `recommended` 候选取、逐本封顶（50，超出「等 N 项」）——避免 1213 本级候选全量重扫与返回面放大。
- [常驻行与既有 notice 叠层] → 实现期落实「模态 1 + 常驻行 1 + notice ≤2」并给 notice 仲裁。
- [请求预算门禁被轮询打爆] → D10 单例 + 仅 running 时轮询；e2e 预算用例纳入验收。

## Migration Plan

1. 原型先行：`docs/design-c/drafts/ai-novel-c端-首次升级带回卡.html` → 移入 `prototypes/` 并登记 `ADJUSTMENTS.md`（含本版新增入口「设置 › 本机旧版本数据」）。
2. 后端：候选只读清单 → 完整性单源判定 → 密钥转接 → 预置题材源行胜出 → 演练对拍阶段。
3. 前端：数据层单例 → 宿主与队列 → 带回卡四步 → 常驻行（稍后带/不完整）→ 设置入口。
4. 回归：pytest / vitest / e2e（含请求预算与四步链路）/ upgrade_drill（version-chain + parity）。
5. 发布：更新说明写明「升级后会把上一版的作品与模型配置一起带过来；旧文件原位保留、可装回旧版；预置题材文案以你机器上的为准」。
6. 回滚：本 change 不改库结构与命名；装回旧版即可继续用旧库（既有回滚语义不变）。
