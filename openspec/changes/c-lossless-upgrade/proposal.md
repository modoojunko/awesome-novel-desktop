## Why

C端 库文件按版本轮换（`novel-v{版本}.db`，每版首启新建自己的库），升级后用户必须把上一版的作品「带过来」。现状有两处硬伤：**入口藏在空书架角落一行小字**——用户容易错过，也容易把空书架误读成「书没了」；**搬运会把模型配置的 API Key 搬成解不开的死文**——密文随表迁入而钥匙行（`app_meta`）按既有纪律不搬，用户升级后要逐条重贴 Key。此外搬运不完整（整表跳过 / FK 违规 / 少书）时结果页不明确告知，用户以为一切正常。

产品口径（2026-10-08 拍板）：**动用户数据必须让用户知晓并点头**（不做后台自动搬运），且**升级前啥样、升级后就应该啥样**（等价判据，逐项可验收）。因此这一版把「带回」从角落一行字升级为**首屏告知卡 + 四步闭环**，并把等价判据下要求的已知损失（Key 死文、预置题材编辑被新版覆盖）同批修掉。

## What Changes

- **带回告知卡取代角落入口**：登录后进书架、存在可搬运候选时首屏出现告知卡，四步走完——① 告知（卡上列清单）→ ② 用户点「把作品和模型配置带过来」（全程唯一操作）→ ③ 进度（**锁定，不让离开**；关窗＝中断，下次重来，无半成品）→ ④ 完成点确认收尾。
- **卡片内容＝作品 + 模型配置两块平级清单**（作品名+字数 / 配置条数+名称·含 API Key 与用量统计）；一次点击覆盖两样，配置不是搭便车。「Key 不用重新粘贴」为条件承诺：源钥匙不可得时才提示「N 条需重新粘贴」。
- **只带「最接近当前版本」的那一份候选**（后端 `recommended` 单源）；更早的候选只在卡上留一行提示，带不带在「设置 › 本机旧版本数据」里决定。
- **模型配置随迁**：搬运收尾做钥匙转接——对目标库中按当前钥匙不可解的密文行，依次用源库钥匙行与旧 `.fernet_key` 文件解密后按目标钥匙重加密；正常态用户无需任何重填。
- **预置题材：源行胜出**（用户编辑优先级高于新版出厂文案；新版新增题材仍会补上）。
- **搬运不完整必须提示用户**：结果卡出「不完整」变体（警示块 + 重新带一次），确认后顶部常驻行持续提醒且**不提供静默出口**，直到重搬完整。
- **「稍后带」出口**：常驻行 + 次级出口「本版不再提醒」+ 设置永久入口；**替换**现有 `dismiss` 的「永久静默直到源变化」语义（未完整达成不得永久不可见）。
- **弹窗复用同一个壳层单点宿主 + 队列**（优先级：数据 > 能力 > 提示）：带回未收尾（用户未点完成确认）写作能力包弹窗不入场；**一次点击 ≠ 一次同意**（搬本地数据与下网络包两次同意分开）。
- **后端补只读清单字段**（candidates/preview：作品名+字数、配置条数+名称），**密钥永不返回**。
- 首次安装（无候选）本流程完全不出现，只有既有的写作能力包提醒。

**BREAKING（对既有规格语义）**：`db-generation` 的「单次确认/五步向导 + dismiss 永久静默 + 空态出口行」升级仪式被四步告知卡与「稍后带」语义取代；`model-api-config` 的「库间迁入只提示死文」被「重加密同迁」取代。

## Capabilities

### New Capabilities
- `shell-dialog-queue`: 壳层单点弹窗宿主的排队与放行规则（同一时刻只渲染队首、优先级、放行条件、一次点击≠一次同意、进度类不占弹窗位）。

### Modified Capabilities
- `db-generation`: 升级仪式改四步告知卡（触发面＝登录后书架、首次安装不出现）；候选载荷增只读清单字段；「稍后带」取代 dismiss；多候选只带最接近的一份；不完整搬运的提示与持续提醒；迁入引擎增密钥转接与预置题材源行胜出；完整性判定三处同源；演练增「等价对拍」阶段。
- `model-api-config`: 「库间迁入链路的死文提示」改为「密钥转接同迁」——源钥可读时逐行重加密，用户无感；仅源钥不可得时才提示重填。
- `prompt-pack-delivery`: 「登录后进我的作品页且未装包 → 立即弹窗下载」的引导弹窗 SHALL 走壳层队列，带回流程未收尾时不得入场（探测与下载本身不延迟）。
- `backup-restore`: 「旧库留档与升级演练」的 additive/tolerant 旧表述改为引用 db-generation 现行口径（版本治理＋version-chain 演练＋带回四步），消除与 db-generation 主 spec 的互相矛盾；「一键迁入」措辞统一为「带回」。

## Impact

- **后端（C端）**：`migration/engine.py`（密钥转接 pass、预置题材源行胜出、不完整判定入报告）、`migration/router.py`（候选只读清单、稍后带状态、完整性判定单源）、`db_lifecycle.py`（候选载荷字段）、`api_configs/crypto.py`（暴露按指定钥匙加解密的能力）、`scripts/upgrade_drill.py`（新增等价对拍阶段）、`tests/*`。
- **前端（C端）**：新宿主组件与带回卡（收编 `useLegacyDb`/`LegacyMigrateModal` 的数据层，抽书架级单例避免三处轮询）；`NovelListPage`（首屏卡与常驻行、既有 notice 叠层控制、e2e 请求预算）；`packProbe`/`PromptPackModal`（接入队列）；「设置 › 本机旧版本数据」入口（本版新增页）。
- **数据兼容**：不改库命名轴（`novel-v{版本}.db` 维持）；不改备份包契约；S端 零改动。用户机上已有旧库不受影响（源只读纪律不变）。
- **发布**：版本更新说明须写明「升级后首启会把上一版的作品与模型配置一起带过来」及「旧文件原位保留、可装回旧版」。

## Design Impact

- **受影响端**：仅 C端（S端 零改动，不触两端共享段）。
- **受影响的屏/弹层**：书架（首屏告知卡四步、完成常驻行、稍后带常驻行、不完整常驻行）、写作能力包弹窗（让位规则）、设置 › 本机旧版本数据（本版新增入口）。
- **对象状态**：仅用既有语气词——进度＝info、完成＝ok、待带/不完整＝warn、搬运失败＝err；不新增第四种胶囊形态，不引入 success/danger 语气。
- **共享段**：不触碰 `base.css` 令牌与 `pill`/`notice`/`sk`/`panel`/`f-err` 家族 → 无需 `design-cross`。
- **原型先行**：需要。原型已产出（`docs/design-c/drafts/ai-novel-c端-首次升级带回卡.html`，含 7 个演示态与「排入能力包弹窗」队列演示）；落地前须移入 `docs/design-c/prototypes/` 并按规范登记 `ADJUSTMENTS.md`（本版新增入口「设置 › 本机旧版本数据」一并登记）。
- **设计工件产出方**：实现侧自查（复用既有 `.mcard`/`notice`/`mv-list` 模式，不新造视觉）。
