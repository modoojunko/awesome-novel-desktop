## Context

见 `proposal.md - Why`。影响实现方式的现状约束：

- 工具结果进模型只有 `ToolResult.summary` 一条通道；`card.payload` 只进事件流/前端卡，模型没有回读工具（`loop.py` 只回填 summary）。
- 设定域产卡工具的摘要现状两极化：`settings_intro` / 题材四问 / 伏笔把整个结果 `str(dict)` 硬切 300~400 字；世界观起草/体检、主线四能力、卷级体检、命名、两个发散只回「已出卡」零内容。
- `read_settings` 按分区整块返回且没有 offset/续读参数——超出预算就永远拿不到后半段。
- 工具步折叠行取 `" ".join(summary.split())[:220]`，多行摘要会被硬切成半句。
- `lore_suggest` 调必填 `chapter_ref` 的端点却传空 body，必 400；pick 卡渲染契约是 `{name,rationale}`，直接映射会丢 `{key,value,set}`。

## Goals / Non-Goals

**Goals:**

- 产卡摘要＝卡内容的人话提炼，模型能直接比较/推荐/回答追问；任何截断都显式标注。
- 单卡摘要成本有硬上限（1500 字），不因个别长文卡顶爆一轮。
- 报告类摘要把注意力放在问题项上，达标项只计数。
- `lore_suggest` 可实际调用且不丢候选数据。

**Non-Goals:**

- 不做「回读产物卡」工具（新的上下文预算与模型反复读卡的循环风险，收益低于摘要给全）。
- 不改前端卡片契约、不改 DB/API；伏笔体检卡只换 `draft` 文本内容。
- 不做 lore 一键采纳的前端交互（现有 pick 卡无 lore-apply 适配）——卡片作为过目参考，写回仍走世界面板手工填写。
- 不把 `read_settings` 做成可分页续读（本期先放大预算；续读留待真正撞上长文书的证据）。

## Decisions

### D1 摘要由「回执」改为「卡内容的提炼」

- 方案：新增 `assistant/card_digest.py`，提供候选逐条、报告、长文三种渲染，各工具按自己的出参形状调用。
- 备选：给模型全量 `card.payload`——token 与窗口不可控，且卡片里含前端元数据（origin、id 等）对模型是噪声。
- 备选：加回读工具——多一条模型要学的协议，且每次回读又是一笔预算；非目标。

### D2 单卡 1500 字上限，超限按条截并标注

- 方案：`_assemble` 统一装箱，放不下的整条/半条都写明「其余 N 条在卡上看」/「本条续在卡上」，收口句保留。
- 理由：1500 字能装下三条简介候选（真机 884 字）；再长会挤占后续轮次窗口，而长会话压缩时工具结果本来就会被压到 400 字（compact.py），长摘要只是「晚一点被砍」。
- 备选：不设上限——单次返回过大可能顶爆一轮；备选：每条均分——长候选被压碎，尾部钩子丢失。

### D3 报告类：问题全给、达标只计数

- 理由：模型被追问的总是问题项；达标项逐条列只占字数。
- 备选：只给计数＋前 3 条——模型答不了「第 7 条是什么」。

### D4 工具步折叠行取摘要首行＋首条开头作区分位

- 理由：摘要改多行后，硬切正文会把候选切半，界面与会话存档都像坏了；首行天然是标题/计数行，信息密度最高。
- 区分位（评审 P3 补）：折叠行的持久化文本同时是历史回放去重的签名。只留标题时，同工具两次不同产出的 note 完全相同，回放会把它们并成「同样步骤 ×N」。因此多行摘要带首个条目开头（≤60 字）——既恢复区分度，也让折叠行更有信息量。
- 保留 220 字上限，对整行生效（补省略号）。

### D5 `read_settings` 预算 800→2000

- 理由：800 字读世界/主线长文必截半，且没有续读通道；2000 覆盖多数书的单块设定。
- 备选：加 offset 续读——更彻底，但要教模型用、防反复读，改动面大；留作后备。

### D6 `lore_suggest` 参数化章引用，卡面保留原字段

- 方案：`chapter_ref` 可选，缺省用 `frontier_info` 的当前章 ref；无章或正文为空回人话失败语。卡 candidates 同时带 `name/rationale`（满足 pick 渲染）与 `key/value/set/origin`（保数据）。
- 备选：要求模型显式传 ref——作家说「这章」时模型未必知道 ref，且缺省可从上下文推导，多问一轮反而差。

## Risks / Trade-offs

- [摘要变长占窗口] → 1500 硬上限＋收口句固定；实测一张简介卡约 900 字（~600 tokens），远低于一次重跑的调用成本。
- [各核出参形状不一，渲染漏字段] → 每个工具配归一函数＋兜底（`flatten_fields` 不 `str(dict)`）；单测逐个形状钉住。
- [截断标注被模型忽略] → 收口语义与「其余在卡上看」写在摘要内（spec 场景钉住），不是仅注释。
- [文案变化打破既有测试断言] → 已更新 `test_assistant_draft_arc.py` 依赖的「还没写进书里」收口句；新增 21 个用例覆盖。
- [lore 卡无采纳入口] → 明确 Non-Goal：卡片是过目参考，写回走世界面板；若要做一键采纳，另立 change（需前端 pick 卡 lore-apply 适配）。

## Migration Plan

无 DB/API/前端契约迁移。摘要与折叠行都是按次生成的文本，旧会话存档不受影响。回滚＝回退代码（不涉及数据）。

## Open Questions

- lore 一键采纳（前端 pick 卡 → `/settings/world/lore-apply`）是否要做，取决于产品是否希望设定域的产出都能在卡上直接落库；本期不做，不影响本 change 的规格与任务。
