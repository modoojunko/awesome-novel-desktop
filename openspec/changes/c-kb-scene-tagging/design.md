## Context

见 proposal.md「Why」。实现面现状：

- 源条目 `knowledge/*/*.jsonl`：文风 1604 / 文笔 1464，`when` 100% 为空；`deconstruct_batch.py` 的 `_entry()` 已有 `when` 参数，`if clean_when:` 才写入。
- 提示词仓三条拆书模板（`deconstruct_style` / `deconstruct_techniques` / `deconstruct_condense`）输出契约无 `when` 字段。
- C 端入库 `kb/deconstruct_import.py:46` 原样透传 `when_json`；条目创建闸 `kb/gates.py` 只拒世界/角色设定带 `when`，写法类放行。
- `scope` 是读时推导（`kb/router.py:477`）：`when_json` 空 → base；基线构建继承源 `when_json`。
- 消费端 `digest_candidates` 的 style 组要求 `scope=scene`（`kb/match.py:174`、`kb/merged.py:330`）。
- 前端知识详情只有只读「适用：…」展示，没有编辑入口。

## Goals / Non-Goals

**Goals：**
- 拆书新增条目能产出适用条件，并贯通到入库与基线。
- 存量写法条目一次性回标，使基线 scene 文笔/文风 > 0。
- 回标只动写法类条目，不碰世界/角色；不硬填默认场景。

**Non-Goals：**
- 不放开全书级文笔/文风进写章块（消费口径不变）。
- 不做前端「适用场景」编辑器（作者手写场景条目另行立项）。
- 不改书级三区、写法块、章级文风影子的既有逻辑。
- 不改世界/角色条目的产出与入库。

## Decisions

### D1｜在生产端补 `when`，不放宽消费端
保持「全书级走书级三区、场面级进写章候选」的既有规格；修生产端，而不是让 base 层混进章级候选。替代方案（消费端放开 base）会造成每章临时声音与书级三区重复，且违反已拍板边界。

### D2｜只标 `rules`/`craft`，`role`/`sample` 保持 base
叙事身份与示范段是全书恒定；只有规则与描写手法可能随场面变化。回标与拆书产出同此口径，避免把「叙事身份」错标成某场面专用。

### D3｜存量回标＝LLM 分类＋封闭词表校验＋人工抽检
只读 `instruction`（已是写法提炼，不读原文，规避版权），输出 `scene`/`emotion`/`chapter_pos` 或空；空结果不写。低置信不标。抽检按题材抽样，标准＝判定可复述、无明显错标；不过阈值该题材不发布。

### D4｜三仓顺序与兼容
`prompts` 契约与包先发（新增可选字段，旧客户端兼容）→ 本仓入库接线 → `knowledge` 回标、`build --version 6`、发布。基线版本目录只增不改，v5 保留可回滚；老客户端读不懂的条目按既有向前兼容跳过。

### D5｜回标脚本幂等且不覆盖已有值
只对 `when_json` 为空的写法条目补标；已有 `when` 的条目跳过。重复执行结果一致（同输入同输出），不因重跑改变已发布版本内容。

## Risks / Trade-offs

- [场景误标] → 判不出留空＋低置信不标＋按题材抽检；错标率超阈值不发布。
- [合规] → 回标只读 `instruction`（提炼文本），不读原书正文、不写原句；世界/角色直接跳过。
- [跨仓版本漂移] → 提示词仓与内容仓的 `when` 形状以本 change 的 spec 为准；内容仓 build 对未知键拒绝。
- [成本] → 回标分批按题材跑，先用西式奇幻样本验证质量再全量；单条输入只有 instruction（≤240 字）。
- [基线回滚] → v5 保留；发布走既有签名与版本目录只增不改。

## Migration Plan

1. 提示词仓改三模板并验证产出（样本几本书）。
2. 本仓入库接线并回归拆书链。
3. 内容仓回标脚本先跑西式奇幻样本 → 抽检 → 全量 → build v6。
4. 发布 v6，C 端同步后验证 `kb_search_craft` style 段出现候选。
5. 回滚：CDN 指针回 v5（既有版本目录保留）；回标脚本不删旧数据。
