# c-thinking-display — Design

## Context

c-inline-think-strip 已把 openai 内联思考从交付文本剥离（状态机边剥边弃）；`reasoning_content`（DeepSeek/Qwen/Kimi）与 `thinking_delta`（anthropic）已在客户端层到达但被静默丢弃。本 change 把三路材料统一为思考事件通道，并按 **2026-10-20 获作者认可的思考呈现原型**（`docs/design-c/drafts/ai-novel-c端-思考呈现-原型.html`＋设计说明）在正文工作台呈现。依赖 c-inline-think-strip 先合入（状态机是内联思考的透出来源）。

**决策基线**：2026-10-16 初版（90748fcc）与本稿冲突处，以 10-20 认可定稿为准——初版「无框行内禁边框」「退场即销毁禁回看」「2000 字符滚动截断」三条按定稿修订（初版成稿早于原型评审四天，定稿代表作者最新拍板：占位行让位、思考转收起条保留、回看抽屉、超时保留已产思考）。

## Goals / Non-Goals

**Goals**
- 作者在等待期看得到模型在思考（三供应商形态通吃），失败/判死前不再是黑箱；等不到正文，至少等得到「它想了什么」。
- 四态呈现：思考面板（占位行让位）→ 写作期收起条 → 完成/阅读回看 → 超时终局保留，全部以认可稿为准。
- 思考呈现严格非文档：不进正文、不计数、不送检（回看内容同口径）。
- 可观测：llm.log 单行账能回答「首字什么时间到的、思考了多久」（thinking_ms / first_char_ms / thinking_chars）。
- 不消费思考事件的调用方（章纲/判定/拆书等全部既有 op）零行为变化。

**Non-Goals**
- 非流式调用的思考透出（本期非流式照旧丢弃）。
- 首字守卫语义调整（沿用「正文首字才撤守卫」；正文路径宽限仍 600s）。
- AI 助手对话面板的思考呈现（仅正文生成链路；助手侧后续按需另议）。
- 思考的跨会话持久化（回看保留在章的当前内容上；重开应用后的回看随实现按存储成本另议，本期不承诺）。

## Decisions

1. **事件通道＝`StreamEvent` 增类别字段，而非新增事件类型**。正文事件 `text` 口径不动，思考走同结构新类别——消费方按需过滤，未升级的调用方天然忽略（向后兼容零成本）。备选「独立 StreamEvent 子类」拒绝（isinstance 分支扩散）。

2. **内联思考透出点＝剥离状态机 STRIPPING 态回调**。c-inline-think-strip 的 STRIPPING 目前「即攒即弃」，改为滑窗外增量以思考事件透出（滑窗保留逻辑不变——透出与滑窗正交）。首字守卫撤点仍只认正文放行，不变。

3. **SSE 形态＝单一事件流内增 `event: thinking`（data 为增量文本）**，正文沿用既有事件名。前端按事件名分流缓冲。阶段事件、完成/失败事件形态不变；**失败/停止事件需携带已收思考缓冲的可用性标记**（思考内容本就缓存在前端，超时卡据此保留——无需服务端回传全文）。

4. **思考期呈现＝版心同列思考面板＋占位行让位**（定稿拍板）。首个思考增量到达，思考面板替换既有「模型思考中，等待首字」占位行（阶段行整体退场——秒表、活着、停止（顶条常驻）都在面板与顶条上，同信息不在两处）；面板＝模型名＋「已思考 N 秒」（延续等待计时，切换不重置）＋弱化样式思考全文＋「不会写进正文」说明。**宽度相对**：`width:100% + max-width 680px` 与正文版心同列，宽度与思考文字量无关（流式全程不变，已程序化验证）。**内容全量保留、限高滚动**（滚动到尾部）——取代初版「2000 字符滚动截断丢弃」：截断与回看互斥。无思考增量的生成维持既有阶段行＋计时（不出现空白面板）。备选「无框行内＋固定 px 定宽」均拒绝（初版形态被定稿推翻；定宽在窄窗溢出）。

5. **首字到达＝收起条转场，不销毁**（定稿拍板，取代初版「退场即销毁」）。首个正文片段到达，思考面板收起为正文列上的收起条（账目行：思考 N 秒 · 生成 N 秒 · 正文 N 字），可展开为回看抽屉（限高滚动）；收起条本次编辑会话内常驻，阅读视图同样保留。等待呈现（阶段行）退场口径不变：不留痕。备选「销毁不回看」拒绝——作者认可的定稿以「思考是章的属性」为准；回看是评审时的核心诉求（模型怎么想的，对作者有参考价值）。

6. **超时终局＝超时卡保留思考**（定稿拍板）。首字守卫判死（600s 无正文）以超时卡收尾：正文保持原样、已到达思考内容保留可回看、「重新生成」入口；顶条生成指示同步退场。实现关键：思考增量本就缓存在前端，失败事件到达即转卡，无需服务端回传。

7. **思考文本不清洗**：原样透出（含换行与模型自带的标记），弱化呈现降低干扰；仅在渲染层做纯文本化防注入。

8. **可观测补账（llm.log 元数据）**：ai_call 行增加 `thinking_ms`（流开始至首个正文片段）、`first_char_ms`（生成确认起至首个正文片段，含拒参重试）、`thinking_chars`（思考增量字符数）；**思考全文不落日志**（正文/Key 不落日志纪律同理）。当前 MiniMax 一次生成一行账即可回答「首字什么时间到的」，不再靠 DevTools 抓流。

9. **顺手修 MiniMax anthropic 用量解析**：2026-10-20 实测 `tokens_in`（message_start）解析正常、`tokens_out=0` 失真——`message_delta.usage.output_tokens` 未取到；属既有「用量记账」要求的实现缺陷修复，不改 requirement。

10. **渲染节流**：前端按 ~100ms 节流合批渲染思考流（rAF 或定时器），不追求逐字实时；面板滚动锚定尾部。

## Risks / Trade-offs

- [回看内容与「等待呈现 SHALL NOT 残留」既有口径相抵] → 口径已按定稿拆分：等待呈现（阶段行）退场不留痕不变；思考以收起条**转场保留**，属新的保留态而非等待残留（spec 已改写）。
- [长思考每字符一次 DOM 更新卡顿] → ~100ms 节流合批（同初版）。
- [全量保留的 DOM 体量（M3.1 实测思考约 4 分钟、数千字）] → 限高滚动＋纯文本节点，数千字符量级无压力；超长思考（>5 万字符）按滚动窗口截断最旧可视节点但保留全文数据（回看数据不受截断）。
- [M3 思考为英文，作者阅读门槛] → 如实呈现不翻译（翻译是幻觉风险面）；弱化样式定位为「进度信号＋可选参考」。
- [SSE 事件名新增被旧前端忽略] → 旧前端行为与今日完全一致（思考被丢弃）；无兼容性破坏。
- [思考与正文事件交错的边界毛刺] → 状态机保证正文事件自闭标签后才放行；测试覆盖 think→prose→think 交错形态（M2 系交错思考官方口径）。

## Migration Plan

无数据迁移。SSE 新事件名对旧前端无害（忽略即今日行为）。回滚＝还原代码。

- 超长思考（>5 万字符）可视节点截断的具体窗口（实现期按性能实测定；数据层全量保留）。
