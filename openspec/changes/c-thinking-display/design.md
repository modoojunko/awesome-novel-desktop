# c-thinking-display — Design

## Context

c-inline-think-strip 已把 openai 内联思考从交付文本剥离（状态机边剥边弃）；`reasoning_content`（DeepSeek/Qwen/Kimi）与 `thinking_delta`（anthropic）已在客户端层到达但被静默丢弃。本 change 把三路材料统一为思考事件通道，并在生成区「首字前」等待呈现中流式显示。依赖 c-inline-think-strip 先合入（状态机是内联思考的透出来源）。

## Goals / Non-Goals

**Goals**
- 作者在等待期看得到模型在思考（三供应商形态通吃），失败/判死前不再是黑箱。
- 思考呈现严格非文档：不进正文、不计数、不送检、不留痕。
- 不消费思考事件的调用方（章纲/判定/拆书等全部既有 op）零行为变化。

**Non-Goals**
- 思考的持久化与历史回看（退场即消失；生成完成后不提供回看入口）。
- 非流式调用的思考透出（本期非流式照旧丢弃）。
- 首字守卫语义调整（沿用「正文首字才撤守卫」）。
- AI 助手对话面板的思考呈现（仅正文生成链路；助手侧后续按需另议）。

## Decisions

1. **事件通道＝`StreamEvent` 增类别字段，而非新增事件类型**。正文事件 `text` 口径不动，思考走同结构新类别——消费方按需过滤，未升级的调用方天然忽略（向后兼容零成本）。备选「独立 StreamEvent 子类」拒绝（isinstance 分支扩散）。

2. **内联思考透出点＝剥离状态机 STRIPPING 态回调**。c-inline-think-strip 的 STRIPPING 目前「即攒即弃」，改为滑窗外增量以思考事件透出（滑窗保留逻辑不变——透出与滑窗正交）。首字守卫撤点仍只认正文放行，不变。

3. **SSE 形态＝单一事件流内增 `event: thinking`（data 为增量文本）**，正文沿用既有事件名。前端按事件名分流缓冲。阶段事件、完成/失败事件形态不变。

4. **前端呈现＝「模型思考中」阶段行内弱化流式区**：与正文同字体弱化色，随增量自动滚动；**呈现区设滚动上限**（超限丢弃最旧的可视内容，防长思考把版心撑成无底洞——M3 实测思考可达数千字）；DOM 只保留窗口内文本，不整段累积。备选「固定高度可滚动块」拒绝（边框容器违反无框行内呈现口径）。

5. **退场即销毁**：首个正文片段到达/失败/停止，思考区随等待呈现一并卸载，不提供生成后回看。备选「收起为可展开行」拒绝——与「SHALL NOT 残留」的既有退场口径相抵，且回看价值低（正文已到，思考使命结束）。

6. **思考文本不清洗**：原样透出（含换行与模型自带的标记），弱化呈现降低干扰；仅在渲染层做纯文本化防注入。

## Risks / Trade-offs

- [长思考每字符一次 DOM 更新卡顿] → 前端按 ~100ms 节流合批渲染（rAF 或定时器），思考流不追求逐字实时。
- [M3 思考为英文，作者阅读门槛] → 如实呈现不翻译（翻译是幻觉风险面）；弱化样式定位为「进度信号」而非阅读材料。
- [SSE 事件名新增被旧前端忽略] → 旧前端行为与今日完全一致（思考被丢弃）；无兼容性破坏。
- [思考与正文事件交错的边界毛刺] → 状态机保证正文事件自闭标签后才放行；测试覆盖 think→prose→think 交错形态（M2 系交错思考官方口径）。

## Migration Plan

无数据迁移。SSE 新事件名对旧前端无害（忽略即今日行为）。回滚＝还原代码。
