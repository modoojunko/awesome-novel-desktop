## ADDED Requirements

### Requirement: 收尾产出输出契约与解析兜底

- 世界要素（lore）收尾的提示词 SHALL 声明唯一输出形状：JSON 对象 `{"items": [...]}`；本章无新世界要素时 SHALL 指示输出 `{"items": []}`；SHALL NOT 出现与对象形状冲突的数组指示（如「JSON 数组输出」「没有则输出空数组」）。伏笔登记（hooks）收尾的提示词同口径：整体输出为 JSON 对象（resolved/advanced/planted 三键），SHALL NOT 声明整体为「JSON 数组输出」。
- 收尾产出解析 SHALL 对合法 JSON 裸数组做兜底：世界要素类按 `{"items": <数组>}` 处理——空数组（如 `[]`）视为无提案内容照常成功，SHALL NOT 落「失败」行；含条目的裸数组按对应条目产出待确认行。伏笔登记类的裸数组无对账语义，SHALL 按解析失败落「失败」行（可重试）。
- 解析失败落「失败」行时，「输出疑似被输出预算截断」诊断 SHALL 仅在输出结尾既非 `}` 也非 `]` 时给出（截断特征：无收尾括号、常断在半句）；完整短输出（如 `[]`）SHALL NOT 被误报为截断。

#### Scenario: 模型回空数组按无提案成功处理

- **WHEN** 世界要素收尾模型输出为字面 `[]`
- **THEN** 按世界要素空 items 处理照常成功，SHALL NOT 落「失败」行；同章同类的旧失败行照常被清（防永久挂列表）

#### Scenario: 含条目的裸数组按 items 处理

- **WHEN** 世界要素收尾模型输出为不含 `{"items": …}` 包装的合法 JSON 数组（如 `[{"key": …, "value": …, "set": …}]`）
- **THEN** 按世界要素 items 对应条目产出待确认行，条目在「设定」页签可见可采纳

#### Scenario: 失败诊断不误报截断

- **WHEN** 收尾输出不可解析且为完整短输出（如 `[]`）
- **THEN** 失败行的原因含「模型输出不是可解析的 JSON」与输出摘录，SHALL NOT 含「疑似被输出预算截断」

#### Scenario: 真截断诊断保留

- **WHEN** 收尾输出不可解析且断在半句、结尾无收尾括号
- **THEN** 失败行的原因含「疑似被输出预算截断」提示（既有诊断口径不变）

#### Scenario: lore 提示词输出形状唯一

- **WHEN** 触发世界要素收尾
- **THEN** 提示词以 `{"items": [...]}` 为唯一输出形状示例，无新要素时指示输出 `{"items": []}`，不含「JSON 数组输出」「没有则输出空数组」字样；e2e 桩依赖的匹配短语「识别新出现或变化的世界要素」保留
