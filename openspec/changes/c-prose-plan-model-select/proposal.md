# 提案：正文方案卡按次选择生成模型（c-prose-plan-model-select）

## Why

`c-agent-dialog-prose`（#1131 已合）把生成正文整个挪进对话框方案卡后，原「AI 生成正文」
弹窗里的「生成模型」选择位没有搬过来：作家在对话编排里点「开始生成」只能用本书模型，
换不了大模型（真机反馈「没有选择大模型了」）。同时方案卡「展开全部」被 320px 限高＋内滚动
裁着——近 3000 字的长提示词仍然看不全（真机反馈「用户提示词看不全」）。

`c-retire-prose-aimodal`（#1134，在途）退役 AiModal 后，主规格「生成按次选择模型」将没有
任何承载面——本变更把该能力落到方案卡上。

## What Changes

- **方案卡新增「生成模型」选择位**（`prose_plan` 卡草稿/旧版态）：复用既有 `.mp-*`
  组合框＋弹层（跨配置×供应商、顶搜索、键盘、本书模型旗标），默认本书模型；候选少于
  2 个或本书模型未就绪时 SHALL NOT 渲染选择位。
- **按次模型对贯通**：卡上所选仅在「≠ 本书模型」时随「开始生成」下发
  （`api_config_id`＋`model`），经宿主桥（归档拦截／再生成确认）进入 write 请求；
  与本书模型相同＝不带，行为与今日一致。
- **提示词展开看全文**：方案卡「展开全部」不再限高 320px 内滚动——展开即完整全文。
- **不动**：后端 write 链（按次模型对校验与记账已具备）、本书绑定、助手模型 pill
  （仍只作用于对话）。

## Capabilities

### 修改
- `prose-writing`：MODIFIED「生成按次选择模型」——承载面从「AI 生成正文」弹窗改为
  对话框方案卡；其余语义（默认本书模型、仅本次生效、搜索/键盘、服务端校验、记账口径）
  原样保留，新增「再生成确认后仍按所选模型生成」场景。

## Impact

- 前端：`components/novel/chat/Aui2Dock.tsx`（卡面选择位＋宿主桥第三参）、
  `NovelWorkspace.tsx`（pendingStart 携带 modelSelection）、`chat.css`（展开全文＋
  选择位样式）、`__tests__/dialogProse.test.tsx`。
- 后端：零改动（`POST /write` 按次模型对通道既有）。
