# frontend-auth-heal

## MODIFIED Requirements

### Requirement: 壳层会话翻转不重挂无关组件

- 登录态在会话存续期间发生翻转时，壳层 SHALL 只切换权益上下文与路由区域：更新提示条/到期提示条/状态条组件实例保持挂载（各自挂载请求不重复触发），SHALL NOT 出现整棵 app-shell 重挂。
- **书架空闲期请求预算（c-shelf-request-budget）**：书架页完成加载后进入静止 3 秒，该窗口内 `/api` 请求总数 SHALL ≤ **诊断校准值**（e2e 守卫用例固化此口径）。校准值与依据来自本 change 的请求时间线诊断：每一个计入预算的请求 SHALL 能指认发起调用点；预算 SHALL 保留风暴判别力——壳层重挂风暴态（实测 ~20 请求/3 秒）MUST 仍然必红。测试注释 SHALL 记录校准依据（哪些启动请求为合法新增、来源 change 是哪个）。
- 诊断插桩（发起方标记/时间线）SHALL 属开发与 e2e 手段，SHALL NOT 进入生产构建的行为路径。

#### Scenario: 翻转不重挂壳层组件

- **WHEN** 登录态在会话存续期间发生一次翻转（如凭据写入或清除）
- **THEN** 更新提示条/到期提示条/状态条组件实例保持挂载（各自挂载请求不重复触发），仅权益上下文与路由区域按新状态渲染

#### Scenario: 书架空闲期请求预算

- **WHEN** 书架页完成加载后进入静止 3 秒
- **THEN** 该窗口内 `/api` 请求总数 ≤ 诊断校准值（e2e 守卫用例固化此口径；校准依据＝本 change 的时间线证据，记录在用例注释）；壳层重挂风暴态 MUST 仍然必红

#### Scenario: 每个预算内请求可指认发起方

- **WHEN** 按 Phase A 诊断插桩采集书架启动链时间线
- **THEN** 窗口内每个 `/api` 请求都能指认发起调用点与相对首屏 ready 的偏移；无法指认发起方的请求视为诊断缺口，SHALL NOT 直接以调预算收场
