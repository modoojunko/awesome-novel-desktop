## Context

四个红例的漂移是全页级的（差异像素铺满 y 0-900、x 17-1424），根因是 book.html 工作台屏基线停在多个 change 之前。历史包袱清单（均为已合入、已登记 ADJUSTMENTS 的改动）：#465 三页签回默认主页＋书主页卡、卷右栏、抽卡「上接」；#464 出口行；storyline 卷纲屏迁移；信息差块（ADJUSTMENTS #14）；c-og-slim-v2 章纲 13 格。#465 已把这批红按存量漂移登记（4.501/2.642/2.558/2.559%），本 change 是对这批登记的集中清偿。

## Goals / Non-Goals

**Goals**
- 4 例 parity 转绿（阈值 0.2%），且重录后的基线具备「抓未来工作台屏回归」的判别力。
- 每个差异区都有明确的裁决记录（以谁为准、为什么）。

**Non-Goals**
- 不做新的视觉设计（对齐对象＝当前实现的真实形态）。
- 不动 `design-parity.spec.ts`（书架屏，8/0）与 preview 基线。
- 不追求 100% 逐像素——沿用 0.2% 阈值与既有「裁剪原型稿头/窗体标题栏」的口径。

## Decisions

**D1 默认以实现为准重刷原型。** 理由：这批漂移的来源是「实现已按已合入 change 演进、原型没跟上」，实现即当前产品意图，且每笔都有 ADJUSTMENTS/PR 记录可回溯。备选（以原型为准改实现）被否：等于把已合入的产品决策回滚，工作量大且与用户已验收的界面冲突。

**D2 裁决按差异区清单走，不逐像素猜。** 流程：对 4 例的 diff 图做分带统计（y/x 带差异密度）→ 密集区逐一打开原型与实现的 DOM 对比 → 每区登记「以谁为准＋依据」→ 再动 book.html。裁决清单是本 change 的第一个交付物，先出后改。
**默认翻转规则**：差异区能找到对应 change/ADJUSTMENTS 记录 → 以实现为准（该记录即产品意图的凭证）；**找不到记录 → 默认翻向「原型为准」**（先查实现侧是否漂移，而不是把实现 bug 焊进基线）。

**D3 基线重录走 spec 既有机制。** `design-parity-book.spec.ts` 在本地资产缺失时自动跳过、运行时生成三图——重录＝改完 book.html 后以 `DESIGN_PARITY=1` 重跑即得新三图，不手绘 PNG。

**D4 弹窗三例（modal-delete/prefs/upgrade）随工作台屏主例一起重刷**：三例的漂移主体与主例同源（弹窗背后的整页差异），主例对齐后弹窗例的页面部分即对齐，弹窗本体（确认/偏好/升级卡）如仍有差按同流程单独裁决。

## Risks / Trade-offs

- [裁决清单漏区] → 重录后跑 4 例，仍有差即回 D2 流程迭代；以「4 例全绿」为完成定义。
- [原型改动引发 book.html 内其他引用断裂] → book.html 是自包含演示页，改版后以 Playwright 打开冒烟（无 console 错误）兜底。
- [与未来 change 的基线竞争] → 本 change 合入后，后续改工作台屏的 change 恢复「先改原型再改实现」的既有纪律。

## Migration Plan

裁决清单 → 改 book.html（分例推进，每例改完即重录核验）→ 4 例全绿 → ADJUSTMENTS 汇总登记 → 归档。回滚＝revert 对 book.html 的改动（基线三图随跑随生成，无状态残留）。
