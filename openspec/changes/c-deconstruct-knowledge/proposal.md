# c-deconstruct-knowledge · 拆书升级：全书拆／智能拆书双模式（作家发派时可选）

## Why

写法块（c-kb-write-block，已合 main）的取数源＝知识库，而真实用户的库是空的——冷启动缺内容。拆书是内容量产机（PRO），但现有拆书对千万字大书要全书进管线（贵且慢），且产出以「学这本书」为主。本变更给拆书加**发派时可选的双模式**：

- **全书拆**（现有行为零改动）：完整报告＋建书灌设定，更费 token
- **智能拆书**（新增）：选章器只采样「前 3 章＋各场面类型代表章」，8-10 万字跑出**写法知识向**产物（手法/文风/文笔/世界/角色＋节奏档），迅速省 token——产出经 collect-to-kb 直灌知识库，写法块从此有货

boss 口径：肯定要拆书补内容；千万字书不全书过模型——前 1-3 章固定拆＋中途按类型规则选代表；**基于现有拆书功能升级，不重建**。

## What Changes

- **选章器**（新模块，纯代码零模型）：第 1-3 章固定入选；第 4 章起逐章跑代码分类器打标（七类场面关键词命中＋对话密度＋短句率＋情绪词密度 → 类型标签＋信号强度分）；每类取信号最强 Top 3-4 章（同卷≤2 章＋章长过滤），采样集 ≤31 章
- **智能拆书模式**：任务发派新增拆法选项（全书拆/智能拆书，默认智能）；smart 模式采样集固化进任务（断点续拆/重跑一致），管线仅吃采样集；维度适配提示（主线剧情/伏笔类维度建议全书拆）
- **节奏统计档**（新产物，纯代码统计）：章字数分布/每章场景数估计/爽点间隔（情绪峰间章距）/卷章数配比 → products_json 新 key，报告页呈现，后续接卷节奏/字数线默认值
- **知识出口**：smart 产物经既有 collect-to-kb 五类映射直灌知识库（链路已通，零改动）

## Capabilities

### New Capabilities

（无——全部落在 deconstruct-book 既有能力上）

### Modified Capabilities

- `deconstruct-book`: ADDED 拆解模式选择（全书/智能）＋智能选章器＋节奏统计档需求；MODIFIED 十维度管线 requirement（smart 模式采样集进合批＋断点用固化采样集）

## Design Impact

- 受影响端：**C端 only**（S端零接触；提示词包零改动——提炼模板全是既有十维度模板）
- 受影响屏/弹层：拆书发派卡片（新增拆法选项字段＋token/速度提示行）；任务详情/监控面板（新增模式标记）；报告页（智能模式标注采样范围＋新增节奏档页）
- 对象状态：DeconstructJob 新增 mode/selected_chapters_json 两列（nullable/server_default，列交集搬运口径）
- 两端共享段：不触碰
- 是否需要原型先行：否——发派卡片是既有表单加一个选项字段，实现侧自查
- 设计工件：实现侧自查（文案过 design-language 口径）

## Gazette

- 选章规则已与 boss 对齐锁定（前 3 章固定＋打标选型＋≤31 章封顶＋预算 8-10 万字）
- 书源口径：用户自己上传 txt（平台不供书源）
- 千万字成本口径：智能拆书 ≈ 8-10 万字模型调用量，与书厚解耦
