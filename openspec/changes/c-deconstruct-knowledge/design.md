# c-deconstruct-knowledge · Design

设计原则＝boss 拍板「基于现有拆书功能升级，不重建」。全部改动为插装件，拆书主管线（切分/合批/提炼/归并/韧性/队列）一行不动。

## D1 三件升级点

1. **选章器**（`deconstruct/sampler.py` 新模块，纯代码）：
   - 输入＝切分产物（章清单＋文本＋字数——切分本来就有，零新解析）
   - 打标：七类场面关键词词族（复用 kb/concepts 别名表口径，自带副本避免 deconstruct→kb 反向依赖）＋对话行占比＋短句率＋情绪词密度
   - 选型：每类 Top 3-4（信号分降序），同卷 ≤2 章，章长过滤（<800 或 >P95 跳过），「未分类」章只作均匀兜底
   - 输出：selected_chapters 有序清单 → 固化 `selected_chapters_json`（断点/重跑一致）
   - **打标准确率校准**（boss 定的工作流，2026-11-02）：算法选章打标后，用大模型
     独立读选中章（读原文判主导场面），与算法标签对表算命中率——分类型命中率
     ＋混淆对（打斗↔对峙类）＋总体命中率。校准是**开发期一次性工具**
     （`python -m deconstruct.calibrate`，需真 Key，不进 CI 不进运行时）；
     命中率低于 70% → 调词族/阈值/加成项再测，≥70% 锁定零模型选章上线。
     校准报告落档（分类型数据指导词族调优方向）。
2. **管线插装**（`pipeline.py` 合批前一个分支）：mode=smart 时以采样集过滤合批输入；mode=full 走现路径零改动。断点续拆读落档采样集，不重选
3. **节奏统计器**（`deconstruct/rhythm.py` 新模块，纯代码）：打标数据上算四指标（章字数分布/每章场景数估计/爽点间隔＝情绪峰间章距/卷章数配比）→ products_json 新 key `rhythm`

## D2 任务模型与 UI

- DeconstructJob 加 `mode`（full|smart，default smart，server_default 保列交集）＋`selected_chapters_json`
- 发派卡片：拆法选项（radio 两项）＋提示行「智能拆书 · 约 X 章/Y 字 · 省token更迅速」；维度联动提示（主线剧情/伏笔建议全书拆——不发硬约束，提示即可）
- 任务清单/详情/监控面板：模式徽标
- 报告页：智能模式标注「基于采样集统计」＋节奏档页

## D3 韧性与记账

- 采样集流程自动被既有韧性覆盖（熔断/断点/看门狗/专属队列）
- token 记账走既有 per-维度账（采样集自然省，账行照实）
- 全书拆路径零改动（回归由既有拆书测试背书）

## D4 明确不做

- 不做增量拆（同书新章补拆）——P2 记账；不做多书批量知识拆；不改 collect-to-kb 映射（五类照旧）；节奏档的消费集成（卷节奏/字数线默认值）属后续变更
