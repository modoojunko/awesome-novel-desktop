# Design: c-og-hooks-projection

## 决策

1. **投影不落库（单源）**：台账是伏笔事实唯一源；章纲两格＝作者显式红线（勾选/手填才落格）。投影只解决「空格观感」与「一键承接」，不在章纲里造第二事实源（09-28 单源原则拍板的延伸）。
2. **口径三处同源**：
   - 回收投影/「该收了」＝`planned_chapter_id` 解析章号 ≤ 本章章号（与 HooksPane `dueBaseChNo` 判定同法）；
   - 维持投影＝`status==active` 且 `introduced_chapter_id` ≠ 本章 id（与写作注入「排除本章引入」同口径；无埋点的开书设定条目计入维持）；
   - 起草素材块＝`render_hooks_block` 同字段（编号/优先级/类型/due_now）。
3. **勾选落格格式 `[H-####] 描述`**：编号进红线条目，与对账制「兑现/推进按编号引用」衔接；写入后走既有保存链，无新契约。
4. **理由句代替裸「未填」**：投影为空时按台账实况给三种理由（无悬置伏笔／计划收不在本章或未设／均本章埋设），把「计划收是 author intent、在设定·伏笔里设」的杠杆讲在页面上。
5. **取数共享**：`useHooksLedger` 从 HooksPane 抽出（同端点同容错），HooksPane 改消费不改行为；章当前 DB id 取 `store.chapter.id`，免再拉卷章树解析当前章。

## 非目标

- 台账「计划收」自动赋值（作者意图；AI 登记链产它会回到降噪前的噪音）。
- fill-gaps 白名单扩两格（gaps 门禁只有两项必填，缺口清单永不含两格，扩了也是死路径）。
- 写作链注入/红线组装改动（台账全量注入＋该收了标记已在；两格空不丢约束）。
- 已归档章回填两格（语义相反——两格是写作前约束；归档产物按对账制进台账）。

## 风险

- HooksPane 重构回归：取数逻辑原样搬运，e2e 伏笔页签用例（foreshadow/storyline 系列）兜底。
- 投影与章纲格双显混淆：投影仅在本格为空时出现，且带来源标注；格非空时投影不渲染。
