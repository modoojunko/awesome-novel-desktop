# Design: c-relicense-agpl

## D1 · 许可选择：AGPL-3.0-only，与血统仓同族

- 候选 AGPL-3.0-only / AGPL-3.0-or-later，取 **-only**：不把未来 AGPL 版本条款自动引入（版本可控），且不影响与血统仓（AGPL-3.0）的声明一致性；如后续要翻 `or-later`，只改 README/元数据的 SPDX 串一处。
- 版权行：星纬（海口）投资有限公司——与 `brand/brand.json` 的 `company`、installer `MyAppPublisher`、build.spec 版本资源同源。
- LICENSE 文件本体＝GNU 标准全文，**不改一字、不加项目抬头**：GitHub 识别、与血统仓逐字同源、无自造条款风险。项目侧声明（版权人／SPDX 串／源码地址）只落在 README 与元数据，不进 LICENSE 正文。
- 编码：旧 EULA 为 UTF-8 带 BOM（Inno 显示中文的兼容措施）；AGPL 全 ASCII，改回**无 BOM**。随包复制与官网构建期复制链路均不受影响。

## D2 · 安装器撤「点击接受」页（删 `LicenseFile`），不退化为无告知

- AGPL 是授权声明而非接受式合同：安装期「我接受」门槛无法律依据（#498 加此页是为 EULA 服务）。
- 34KB 英文许可全文作为中文安装向导的门槛页，体验差且不产生法律效果——撤销而非替换为 AGPL 版门槛页。
- 许可告知保留三条通道：随包文本（Windows `{app}` 根／macOS .app 内／DMG 根）、README、官网公示页。
- 静默安装本就不弹许可页（原「视同接受」条款随 EULA 消失），行为不变；`[Files]` 两条随包条目与 CI 烘焙断言原样保留。
- 备选被否：① 换 `InfoBeforeFile` 展示 AGPL 全文（无接受语义，但仍是 34KB 英文页，收益低）；② 保留 `LicenseFile` 换 AGPL 文本（把开源许可包装成 EULA 语义，误导）。将来若要中文引导页，另行立项。

## D3 · 依赖许可证门禁保留白名单制（行为零改动）

- AGPL 分发面本可容纳 AGPL 兼容的 copyleft 依赖（GPLv3/LGPL/Apache 组合），但保留「宽松许可白名单」是更严的主动收敛：保住未来再许可自由、不引入额外源码义务面，且 CI/单测零改动。
- 门禁脚本、白名单、CI step 一行不动。脚本注释里的 `relicense-proprietary` 是「引入时的出处处标注」，不是现行政策陈述——按仓库惯例保留，不追改。

## D4 · 跨仓同批：S端 侧不在本仓实现

- 口径先定（2026-10-06 用户明确）：**AGPL 只覆盖 C端 代码；S端 私有仓为私有专有服务，不换协议、不改其仓库许可口径**。S端 侧要动的只是「官网作为下载渠道公示 C端 许可」这条链的文本与文案——该仓根 `LICENSE` 是 C端 许可文本的公示用副本（`copy-eula.mjs` 的输入与已入库 `public/legal/eula.html` 的兜底源），不是 S端 代码的许可声明。
- 公开面口径（2026-10-07 用户明确）：**本仓一切公开材料（README／change 文件／PR）不点名 S端 私有仓**——需要指代时一律用「S端 私有仓」。
- 两仓约定（compose 注释与两仓 CLAUDE.md）：「LICENSE 双仓各持一份、改动两端同批」。S端 仓的改动清单见 tasks 第 4 节（公示用 LICENSE 副本＋落地页 5 件）。
- 官网 `/legal/eula.html` 由 S端 frontend 构建期从注入的根 LICENSE 生成：本仓 LICENSE 一换，下一次 S端 构建即产出 AGPL 文本——**页面命名与周边微文案必须先改**，否则「下载即表示同意《最终用户许可协议》」会与 AGPL 页并存（口径事故）。故 tasks 把 S端 批列为发布门禁。
- 本仓 `docker-compose.yml` 的 `repo=.` 注入链机制不变，仅在 S端 侧同步改注释文字（第 4 节）。

## D5 · 存量用户与待审面

- AGPL 只增不减权利：已按 EULA v2026.09 安装的存量用户不受损，无需重新同意。
- #498 设的「首个付费用户产生前完成 EULA 法律审校」硬门槛随 EULA 退役而消失；待审面转移为：AI 生成代码的权属说明、`docs/reference/天父*.md` 第三方小说文本不得入包（原纪律保留）、v2026.10 协议批次的真人终审（另线）。

## 风险与未决

- 血统仓与本仓同一版权人，无论历史代码是否共享，许可口径统一后无遗留问题；本次同时消除「公开仓挂禁止复制的专有协议」的自相矛盾状态。
- README/官网的开源表述与《付费须知》「增值功能」口径，建议随 v2026.10 协议批次一并过真人审阅（不阻塞本次落码）。
