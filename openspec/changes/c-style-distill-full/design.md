## Context

文风三层（数字/描述/样本）与既有机制：量化蒸馏三步流（step1 逐段标注 → step2 统计 → step3 归纳九维＋画像＋禁用词候选 → commit 落正式区＋history）住在 style-quant，样本三路（novel-samples 文件/归档章/粘贴文本）与 3,000–10,000 字区间校验、draft 续跑、进度复位语义均已定型；示范段 `style_samples`（≤6 条×500 字）与正文恒定层注入由 c-deconstruct-style-transfer（#949）落地，唯一来源是拆书建书。prompt 模板在 prompts 仓纳管（sync.py 生成注释头，本机 publish.py 发四档包）。

## Goals / Non-Goals

**Goals:**
- 同一份参考样本一次蒸馏学全三层：数字（现有）＋描述（三区草稿）＋样本（成段示范段），全部经作者过目落当前书。
- 既有三步/commit/门控/续跑语义零破坏，step4 作为增量步挂入。

**Non-Goals:**
- 不改量化段在提示词中的地位（A/B 实证挂账后再议）。
- 不做「灌入已有书」拆书出口；不动例句提炼；不新增设定页入口（复用蒸馏入口）。

## Decisions

- **step4 独立端点而非并入 step3**：draft 按步续跑的语义天然兼容（存量 draft 缺 step4 产物→补跑）；step3 的 LLM 调用面与测试钉不动；step4 失败可单独重试，不拖累基线路径。
- **提取走独立新模板 `style_learn_extract`（TIER max）**：契约从 deconstruct_style 派生（role/rules/craft/taboo→rules/成段 examples），但**去证据章号与 confidence**——单样本无章号语义，作者过目即人肉置信度。上限收敛：rules ≤10 条、craft ≤8 条、examples 0–6 条×≤200 字（与 style_samples 容量对齐）。
- **三段独立采纳、文字层走前端 PUT**：基线 commit 是服务端写（既有），文字层采纳沿例句提炼先例——前端 put_style 白名单 PUT＋ChangeReceipt 回执撤销。理由：三区/示范段是"作者文风文档"，前端统一出口才能做"采纳前回读合并"（D4 防丢词同款），且回执撤销天然住前端。
- **三区采纳＝替换、示范段采纳＝替换**：学习场景的意图就是"换成参考书的写法"，追加会让新旧规则互相打架；回执撤销兜底误采纳。确认卡上草稿可编辑后再采纳，已经给了折中空间。
- **taboo 在草稿阶段就转「避免…」行**：复用 settings_map.style_body 的投影口径，作者在确认卡看到的就是落卡形态，不见第二语义。
- **量化副产品零新增**：六行基线是现有 step1–3 程序统计的产物，本 change 不为它写一行新逻辑；它在确认卡的地位不变。
- **样本供给＝前端重供**：draft 不存原文（step1 只落标注产物），step4 所需原文由前端随请求重供——既有链路本就把同一 body 传给每个 step（`distillStep(projectId, next, body)`），零新机制；代价是 step4 的 `text` 与 step1 的 `text` 同名不同义（供给 vs 清空重启），相异点进钉子测试。
- **包版本斜坡降级**：`prompts.load` 缺模板抛 `PromptPackMissing`（裸调即 500），step4 捕获转结构化错误＋更新文案；斜坡窗口只存在于「客户端已更新、包未更新」的离线/滞后态，三步基线路径不受牵连。
- **发包**：max 档 77→78 模板，其余档不变；min_client 0.39 不 bump（纯新增模板，旧客户端不加载新模板无碍——step4 端点在旧客户端代码里不存在，不会被调用）。

## Risks / Trade-offs

- **三区替换覆盖作者手写文风**：确认卡可编辑＋回执撤销＋分段采纳三重缓冲；最坏情况一键恢复。
- **3k–10k 样本的全书代表性弱于拆书**：这是本方案对拆书的自觉取舍（轻、即时、贴蒸馏心智）；样本上限提示文案引导"挑最有代表性的几章"（既有文案复用）。
- **MAX 门外用户无感**：step4 与三步同门，无新权益面。
- **progress UI 步数三→四**：进度复位/续跑语义的既有钉子测试需扩一位，注意「复位不拦重试」「关弹窗保留草稿」两条既有语义不得回归。
