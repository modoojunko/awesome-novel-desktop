# C端 一键升级（silent-upgrade）

## Why

C端 升级至今是全手动链：检测到新版本后用户须自行去官网下载安装包、再跑一遍安装向导——
长会话写作者的实际升级率因此趋近于零，且每次发版的修复与新能力触达不了存量用户。
免 UAC 静默覆盖安装的机制承重柱已在真机验证（silent-upgrade-lab 分支，五判据全绿：
零弹窗／覆盖成功／per-user 落键／装完自动回／数据逐字节不动），生产化条件成熟。

## What Changes

- **自动升级链（Windows 先行）**：检测到新版本后后台自动下载（单飞＋取消＋失败退避
  矩阵＋实时进度）→「已就绪」通知 → 用户点「重启更新」→ 静默安装（零弹窗零 UAC）→
  自动回到新版。全程用户可见（百分比横幅、即时文案），不点「重启更新」永不生效。
- **应用内「检查更新」入口**：控制中心菜单项，绕过小时节流做一次真实外呼取真相。
- **更新提示条三态与双轨收敛**：下载中（百分比）/已就绪（重启更新＋暂不）/手动兜底
  （自动链停摆 90 秒后才亮「去下载」）。
- **Windows 安装器扩展**：`PrivilegesRequiredOverridesAllowed=commandline`（手动双击
  路径零变化）＋ `/AUTOLAUNCH=1` 装后自动拉起。
- **发布链**：latest.json v2（platforms url/sha256/size，顶层 Ed25519 签名）＋打包卫生
  闸（iscc 前清冒烟运行时残留——存量正式包同洞，必修）＋版本号烘焙语义。
- **数据面零接触**：安装器不装 `data\`、卸载不清 `data\`；升级后首启的无损带回告知卡
  照旧（文案补一句「模型配置与密钥随迁移」）。

**非目标（本期不做）**：macOS 自动链（保持现有手动引导）；增量/差分包；强制更新
（服务端强制最低版本）；便携版自动升级。

## Capabilities

### New Capabilities

- `client-auto-update`: 自动升级链——后台下载状态机（闸门/单飞/取消/失败矩阵/进度）、
  「重启更新」apply 契约（闸门＋秒回＋一次性 pending）、壳层退出链静默安装（TTL/sha/
  平台四闸＋AUTOLAUNCH＋数据不变式）、applied 记账语义（marker 不得压制新 staged）、
  服务端总闸、可见性要求、平台与构建形态边界（mac 与 dev/smoke 降级）。

### Modified Capabilities

- `client-update`: 检测载荷扩展（manifest v2：platforms/auto_enabled 可选透传）、
  「检查更新」手动入口（绕节流真外呼；dev 手动照答；不查 dismissed）、更新提示条交互
  扩展（三态＋双轨收敛——手动兜底入口仅在自动链停摆时出现）、渠道自报日志。

## Design Impact

- 受影响端：**C端 only**（S端 无界面改动；发布脚本两侧各自在既有流水线内扩展）。
- 受影响屏/弹层：全局更新提示条（三态，挂位不变＝顶栏之下）；控制中心面板
  （新增「检查更新」菜单项与「重启更新」确认弹窗——原生 `window.confirm`）。
- 对象状态（对照状态语言总表）：提示条维持 info 语气；进度百分比用 `.tabular-nums`；
  失败/停摆转 warn 语气（「自动准备不可用，可手动下载」），不新增第四种胶囊形态。
- 两端共享段：不触碰（提示条沿用既有 `notice`/`btn` 家族）。
- 原型先行：横幅三态与菜单项系既有组件的文案/按钮态扩展，**需在
  `prototypes/ADJUSTMENTS.md` 补登记**（实现先行于原型，任务清单内补录——真机验收
  已先行完成，原型补录作为发版前收尾项）。
- 设计工件：实现侧自查（已随 silent-upgrade-lab 分支完成并由 boss 真机验收）。

## 对外契约兼容

- 生产 latest.json v2 键增量对既有消费方（落地页弹窗、旧客户端）零影响；v2 签名
  （update-k1）就位前过渡期仅 sha256 双验＋可信域出站校验，配钥后客户端强制验签。
- 实验渠道（`download/lab/latest.json`）与生产渠道物理隔离，互不相指。
