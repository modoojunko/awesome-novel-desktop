## 第一阶段：建库（当前）

### ① c-knowledge-base · 底座＋浏览（第一个动工）

**目标**：知识库能存、能看、能手动录

- [ ] 11 张表建齐（账号 8 + 书内 3，全列 nullable/server_default）
- [ ] 六概念注册表（概念定义＋属性 schema＋场面/情绪词表＋别名表）
- [ ] 六概念 payload 校验（Pydantic 强校验＋槽位闸＋when 白名单）
- [ ] 入库闸门（长度/原文/幂等/题材归一 normalize_theme）
- [ ] 标签物化索引（user_id 冗余列，选择器/列表不走 JSON 扫描）
- [ ] 默认库自动生成（首条目入库→同事务建库，partial unique index 兜并发）
- [ ] 知识库首页（题材栏只显有内容+全部+通用+更多折叠、概念页签带白话说明、条目按题材×概念分组标题行组织——不做独立库卡）
- [ ] 全部面向作家的文案用日常用语（不用"基线/场景/槽位/句末断"）
- [ ] 条目列表＋搜索＋分页（游标「加载更多」）
- [ ] 条目详情抽屉（字段/正反例/证据只读/被圈库/Esc 关闭）
- [ ] 手录表单（空态 CTA「记第一条」）
- [ ] kb 依赖方向钉死（kb SHALL NOT import write/deconstruct，配断言测试）
- [ ] 单测＋e2e（原型 60 项断言转译）＋10 万级性能回归

## 第二阶段：动态拼装提示词＋AI 维护（建完再看）

> 以下不开工，等第一阶段完成后另立计划。

### ⑥ c-kb-write-block · 写法块选择器＋注入

**要解决的问题**：写章时根据剧情从知识库挑知识，拼进提示词

- [ ] 章纲信号抽取（场面/情绪别名归类、实体直取，不跑模型）
- [ ] 选择器（标签短名单→内存打分，优先级＋打分公式）
- [ ] 写法块注入（write/router.py，收尾行前，不持久化）
- [ ] 留痕反馈（match_runs/items、有用/没用回权重）
- [ ] **冲突仲裁（此阶段定方案）**：
  - 红线仲裁：拆书手法含禁令词族时块首声明"红线优先"
  - 影子并轨：量化维度走影子通道，写法块只收定性句式
  - 同槽覆盖：场景条目覆盖基线的具体渲染方式
- [ ] 续写/补足路径复用当章 run
- [ ] golden 集回归＋选择器指标进 CI

### ⑦ c-kb-organize · AI 持续维护知识（ontology 全量）

**要解决的问题**：知识库不是一次建完就不动了——AI 持续整理、合并同类、纠偏概念、维持关系正确，让知识库越用越准

- [ ] **关系整理**：补新关系、验证旧关系、移除失效关系（KB 整理已有设计）
- [ ] **同类合并**：AI 发现两条知识表达同一概念（表述不同），建议合并，作家确认后保留一条、其余归档
- [ ] **概念纠偏**：AI 发现条目挂错概念（如"打斗句法"挂在"世界设定"下），建议挪，作家确认
- [ ] **子概念建议**：AI 发现多条条目共享一个新模式，建议新增子概念，作家确认
- [ ] **质量标记**：AI 标记低质量条目（指令含糊、无正例、长期未被选），作家可清理
- [ ] kb_organize 模板（PRO）
- [ ] 触发：拆书入库后/闲置 7 天/手动
- [ ] 置信度分流（≥0.75 生效、0.5-0.75 待确认、<0.5 丢弃）
- [ ] 全局图/详情展示关系＋「这条不对」反馈
- [ ] 关系上限（active ≤5×条目）

**安全原则**：AI 自动做关系（可逆），内容变更（合并/纠偏/子概念/清理）一律 AI 建议＋作家确认后才执行。
- [ ] **全局图 2D 上线**（npm force-graph 动态 import、聚合＋下钻＋面包屑返回、悬停邻域高亮、关系边展示"这条手法依赖那条铁律"、六色 oklch token、同屏 ≤500）——关系数据和视图同批到位，第一印象有"关联"可看
