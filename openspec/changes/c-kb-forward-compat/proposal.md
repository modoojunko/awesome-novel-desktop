# c-kb-forward-compat · 基线包向前兼容

## 为什么

基线包由官方持续迭代，客户端版本却长期并存（用户不一定会立刻升级）。当前同步端把
「本端看不懂的内容」当成整包损坏：任意一条不入闸 → 条目数不等于 `entry_count` → 整个包
拒收、保持旧层。结果是**新包里的新东西会冻住老客户端**，只能靠 `min_client_version` 把人
挡在外面——这与「内容可持续演进、客户端渐进升级」的目标相反。

## 做什么

把同步判据从「包级严格」改为「条目级宽松」：

- 本端不认识的条目（新概念、新适用维度等）→ **只跳过该条**，其余照常落层；
- 包级新增字段（manifest/条目的未知顶层键）→ 忽略即可，不影响解析；
- 只有**整包一条都认不出**才判定为代际不兼容 → 保持旧层（绝不落空层）；
- `format_version` 仍是结构性不兼容的唯一硬闸；`min_client_version` 降级为产品级可选要求。

## 影响面

- 代码：`kb/baseline.py` 同步端的条目数校验；`kb/gates.py` 判据语义注释（判据＝「本端看得懂
  的边界」，不再承担「包是否合法」的职责）。
- 内容仓：发布口径补一句——新增概念/维度不必抬 `min-client`，老客户端会跳过该条。
- 用户侧：老客户端能继续吃到新包中它支持的部分；不会被整包挡住，也不会被清空基线。
