## MODIFIED Requirements

### Requirement: 更新提示条交互

检测判定有更新时，C端 MUST 在所有屏（含工作台沉浸模式）呈现一条 info 语气提示条：说明文案含新版本号与本机当前版本号的对照（「发现新版本 v{latest}（当前 v{current}）」，`notes` 摘要有值时附一句更新说明），并附动词主按钮「去下载」与次级动作「查看更新内容」。提示条 MUST 呈现在所在屏顶栏的正下方（常规屏：壳层顶栏之下、页面内容之上；工作台沉浸态：书内应用栏之下、模块导航之上），所在屏顶栏 MUST 保持窗口顶端不被提示条推移。点击「去下载」MUST 唤起系统浏览器直达官网下载页；点击「查看更新内容」MUST 唤起系统浏览器打开该版本的更新说明页（URL 由烘入下载域拼接版本号构造，不依赖额外线上字段）。提示条 MUST 可关闭：关闭后对该版本不再出现，后续新版本再判定为有更新时重新出现。无更新、检测失败或 dev 环境时 MUST NOT 呈现提示条。对照文案中的当前版本号直接取自同一次检测响应，MUST NOT 发出额外请求；当前版本号异常缺失时退回仅含新版本号的文案。

#### Scenario: 有更新时提示并直达下载页

- **WHEN** 线上最新版 `0.13` 高于本机 `0.11` 且检测成功
- **THEN** 所有屏顶栏正下方出现 info 提示条（文案为「发现新版本 v0.13（当前 v0.11）」，有 `notes` 时含一句更新说明），顶栏保持窗口顶端未被推移
- **WHEN** 用户点击「去下载」
- **THEN** 系统浏览器打开官网下载页，应用内不嵌套加载外部页面

#### Scenario: 查看新版本变化

- **WHEN** 提示条呈现且用户点击次级动作「查看更新内容」
- **THEN** 系统浏览器打开该版本的更新说明页（`download/v<VER>/notes.html`），应用内不嵌套加载外部页面

#### Scenario: 工作台沉浸态提示条不推移书内顶栏

- **WHEN** 用户在书内工作台（/novel/*）且检测判定有更新
- **THEN** 提示条呈现在书内应用栏（48px 行头）正下方、模块导航之上，书内顶栏保持窗口顶端未被推移

#### Scenario: 关闭后按版本记忆

- **WHEN** 用户对 `v0.13` 的提示条点击关闭，应用重启后线上仍为 `0.13`
- **THEN** 提示条不再出现；待线上出现 `0.14` 时提示条重新出现

#### Scenario: 无更新时不打扰

- **WHEN** 检测结果为无更新、失败或 dev 环境
- **THEN** 界面不出现任何更新相关元素
