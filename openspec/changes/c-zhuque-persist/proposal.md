# c-zhuque-persist：朱雀检测结果落库

## Why

检测结果当前只在应用会话内存存活（c-zhuque-ai-detect 拍板「不落库、重启即弃」），重启/刷新即丢——而一次检测消耗真实额度（真机一章约 2.5k tokens），结论白白蒸发。检测结论绑定 prose_hash 指纹后陈旧问题有现成 stale 机制兜底，它是有保留价值的**作者资产**。用户拍板（2026-10-01）：落库保存；**备份＝完整资料迁移**（翻转原「备份不含检测数据」）；结果条**显示检测时间**。

## What Changes

- **章粒度旁表落库**：新表 `zhuque_results`（chapter_id 主键＋FK CASCADE、prose_hash、result JSON、checked_at）；检测成功即 upsert（重检覆盖），删章级联删。
- **载入恢复**：进章时无会话缓存则读库水合——存档指纹＝当前指纹 → 彩色恢复标注与结果条；≠ → 现有 stale 机制整体置灰＋「重检」出口（重检后覆盖存档）。
- **备份＝完整迁移**：书级/整库备份包含每章检测结果（`zhuque/{ref}.json`）；导入按 ref→chapter_id 重映射落库（坏 JSON 跳过＋warning），翻转原「备份不含检测数据」。
- **结果条显示检测时间**：「MM-DD 检测」（muted，接在免责小字旁）；检测响应契约增 `checked_at`（服务端落库时间为准）。

## Capabilities

- **zhuque-detection**：REMOVED「不落库与负载护栏」＋ADDED「结果落库与负载护栏」（上限/取消/护栏保留，落库语义替换）；MODIFIED「唯一执行端点」（响应增 `checked_at`）。
- **zhuque-workbench**：MODIFIED「正文段落标注覆盖层」（存续条款：会话级 → 落库＋指纹失效恢复）＋MODIFIED「标题区结果条三态」（增检测时间条款与场景）。

## 不动项

- 门禁/额度/对齐制/分段上限（30000）/同章并发拒绝/取消——全部不动。
- 会话内存仓保留（水合仅发生在仓内无该章状态时），标注渲染链零改动。
- 建表走 Base.metadata（create_all 新代建表，指纹门禁既有语义；**不做带外 DDL**）。

## Risks

- dev 哨兵库（novel-dev.db）加表后指纹失配 → 下次启动按既有 dev 分流语义重建（候选可带回）；打包版本随下一代库自然携带。
- 版本换代新库起始为空表——旧代检测结果不随代迁移（列交集语义，旧代本无此表），可接受。
- 备份包体积略增（每章一 JSON，数百字节级）。
