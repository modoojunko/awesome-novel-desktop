## Context

现状（`client/backend/chapters/ai_plan.py`，与 origin/main 逐字节一致的运行栈实测）：

- 出卡端点一次请求内最多跑 3 次串行模型调用（`MAX_ATTEMPTS=3`）；其中「不足 2 张」是结构性触发，而「名次依据不可寻」（`_reasons_verifiable`）是等级质量触发——后者把等级问题升级成了整批重抽。
- 判死率实测：四维里稳定 3–4 维不通过。模型按提示词前半句（「≤20 字的一句话」）写成概括句（如 `旧宅拖痕汇线，猎物越变猎场。`），而校验要求它是得胜卡字段里的逐字片段。
- 实测一次抽卡 17.00 秒 / 3 次、19.09 秒 / 3 次；dev 库记账 7 次出卡配 14 次重试（100% 跑满阶梯），单次生成 5.3–6.6 秒、出词约 1100–1300 tokens。
- 连带结果：`grades = [] if bad_reasons`，三次尝试后仍判不合法 ⇒ 出卡不带 S/A/B，前端角标渲染为空白（`.pk-corner` 无条件渲染）＋一行「名次依据在得胜卡字段里找不到，本次不出等级」。
- 第二处结构性耦合：名次按模型输出的三张卡给，校验却拿 `sanitize` **保留后**的卡数比对；丢一张卡（同质复核）即判名次不合法 → 必然重抽。而「只出了 2 个方向」在 spec 里本就是合法结局。
- 前端并未渲染 `reasons`（`chapterPlanApi.ts` 只有类型声明），依据目前唯一作用是给等级当地基。

## Goals / Non-Goals

**Goals:**

- 常态一次抽卡只发起一次模型调用（实测目标 ≈6 秒），出词 tokens 回到单次量级。
- S/A/B 必然随卡面一起返回；等级不得再因依据／名次软性瑕疵缺席。
- 保住两条硬性质：字母由服务端按名次算（不接受模型给字母）、至多一张卡为 S。

**Non-Goals:**

- 不改四维判据字段与评分口径本身（反转／递增／推进／拉力 与 S/A/B 换算规则不变）。
- 不改前端契约字段名与卡面结构，不新增视觉形态，不动原型与 parity 基线。
- 不做「依据上屏」（存量缺口，另立话题）。
- 不改自检端点、越纲对拍、入口门控与「最多 3 次尝试」预算本身。

## Decisions

**D1 依据从「机判要件」降为「参考文本」。** 判死代价是整批重抽（3× 时间与 tokens），而它的收益只是给等级做地基——收益远小于代价。保留 ≤20 字长度预算与字段位置，删掉「必须逐字可寻」的全部判定与触发。
备选与取舍：① 拆成 `quote`（机读逐字）＋`why`（人读）双字段——能通过校验，但多一个格式遵循负担，而 quote 的价值仍只是「证明等级有据」，不如把等级直接按名次给出；② 让模型直接输出 S/A/B——被否，见 D2；③ 并行 fan-out 取第一份合格——被判死率 100% 的现状否掉（tokens ×N 且第一份本就可用）。

**D2 字母仍由服务端按名次计算，不交给模型。** 字母是绝对刻度，模型会全给 S；名次是相对刻度，「每维唯一第一名才计分」这条结构性质天然保证至多一张 S。这是 spec 已立的硬口径，本 change 不动。

**D3 名次与丢弃卡解耦：以「模型输出卡序」为索引基准。** `_sanitize_directions` 增返保留卡的原始下标（keep_map），名次与依据按该映射投影后再计分。丢一张卡是 spec 允许的合法结局，不该再罚一次生成。

**D4 名次形态校验保留但降级为「不计该维」，不再升级为整批不合法。** 形态判据：每维名次个数与模型输出卡数一致、取值 1–3、不跳档。任一不满足 ⇒ 该维不计第一名（等级少一维），卡面照常出；SHALL NOT 触发重抽。

**D5 重抽触发面收窄为结构性失败**：三轴重复、剩余可用卡不足 2 张、输出不可解析。等级质量与依据可寻性从触发条件与 `grades` 门槛两处摘除。

**D6 提示词只改冲突的那一处**：删「系统会逐字查找／摘一段 4–12 字连续原文」，依据改述为「一句话说清这一维为什么是它最好（≤20 字，供作者参考）」；其余规则（差异声明、互斥、字段预算）逐字不动。

**D7 契约字段不删**：`reasons`／`ranks` 仍随响应返回（前端已声明类型，未来上屏可用），只是不再参与判定。

## Risks / Trade-offs

- [等级失去文本支撑，S 的含义变为「模型横向比较下的最优」] → 结构性质仍在（唯一第一名、≤1 S）；若实战反馈等级离谱，回退点是「第二次廉价判定调用（收卡面 → 只回名次，输出极小）」或「quote 只上屏不上闸」，两者都不改动本 change 的 spec 主体。
- [映射错位：名次个数与卡数不一致时投影到错误卡] → D4 把不一致归为「该维不计分」而不是硬猜；e2e／单测覆盖 3 卡 → 2 卡的映射路径。
- [慢模型下单次生成仍可能顶到 90 秒读超时] → 本次把常态降到 1 次调用，超时面从「最坏 3 次」收敛为 1 次；结构性失败罕见，保留既有 502 可重试文案。
- [提示词改动引来其他字段漂移] → 只改依据一句，其余原文不动；既有 t3 契约用例守卫字段与闭集。

## Migration Plan

无数据库迁移（评分与理由本就不落库），无前端契约破坏（字段保留），无门控变化。上线即生效；回滚 = 还原 `chapters/ai_plan.py` 与 `prompts/chapter_split.prompt` 两处，无数据副作用。验证顺序：单测（阶梯用例改写）→ 真机同一本书连抽 5 次，记录调用次数（期望恒为 1）与等级分布（期望每次三张卡各带 S/A/B）。
