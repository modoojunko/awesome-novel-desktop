# workbench-ai-check-refine — 设计

## Context

见 proposal.md（Why）。当前实现事实：

- 右栏面板（`AiAssistPanel.tsx`）已按 ⑧ 建成「引导语＋统计卡＋动作清单」，动作渲染分「有 `onClick`
  ＝真按钮 / 无 `onClick`＝禁用＋规划中」，本批把占位全部补齐后该分支成为死代码。
- 已有同类「只读、不落库」AI 端点范式：选区变换族（polish/expand/compress：`write/auxiliary.py`
  组系统提示词 → `client.chat(model="haiku")` → 记账 → 返回文本）与章纲 AI 起草
  （`chapters/ai_draft.py`：JSON 解析＋白名单收敛＋记账先于解析）。
- 提案制先例：`style_shadow`/`plot_sim` 的 AI 建议都是「产出只读、作者确认后走既有保存链」，
  本批的精修沿用同一口径（写回走 `PUT …/prompts/write`，与提示词页签手工保存同端点）。
- 计量守则（源码守卫 `test_ai_prompt_and_boundary.py`）：`record_usage` 必须记真实模型
  （`effective_model(project)`），符号别名 `haiku` 只允许出现在 `client.chat(model=…)` 位。

## Goals / Non-Goals

- Goals：三类新端点（六类检查 / 缺项补全 / 提示词精修）落在既有 AI 链路上（同一门控、同一计量、
  同一超时口径）；右栏面板「零占位」；产物一律不落库（弹窗/表单承接）。
- Non-Goals：不做多轮对话式检查；不做「检查结果一键修复」（改稿仍走作者）；不把 findings 落库
  （如需留档，未来走归档摘要族另立 change）；不改原型（文案取 storyline.html 既有 aiActs）。

## Decisions

1. **检查族单端点＋类别参数，而不是六个端点**。六类共享「章纲/正文＋按类别附加素材 → findings」
   同一管线，差异只在指令与素材装配；单端点让前端只有一个弹窗组件、后端只有一套门控/计量/解析。
   备选：六端点（路由与前端各自成对，重复度高，弃）。
2. **findings 用「{title, detail} 数组 + 上限 8 + 空数组合法」的宽松契约**。模型输出不稳，
   严格式（缺字段即失败）会把「一次有内容的检查」变成 502；宽松契约下解析失败＝空数组（用户看到
   「没有发现明显问题」），比报错更接近真实（模型没检出事也常回自然语言）。代价：模型彻底不守格式时
   静默为空——由提示词强约束（「只输出 JSON」）+ 有内容时逐条过滤（title/detail 均非空）。
3. **素材按类别裁剪，关系类走真表**（`character_relations`），不走 `ctx`。理由：`ChapterContext`
   不含关系面（关系是全书统一台账、非章投影），在端点内查一次比扩上下文类更小、更快见效；
   代价是端点内多一次 DB 查询（可接受，单章检查非高频）。
4. **缺项补全的键集合＝前端章纲表单可承接的键**（后端 `_FILLABLE_KEYS` 与 `chapterForm` 的补丁映射
   同口径）。备选「模型自有键」会在前端丢失（无处安放），弃。`segments` 特殊处理为结构化数组
   （旧通用分支会把 dict 字符串化——本次修正），目标字数钳 100-4000。
5. **精修不落库、由前端确认后 `PUT …/prompts/write`**。与提示词页签手工保存同端点，避免第二套写路径；
   弹窗关闭即丢弃（无「草稿态精修稿」概念）。备选：端点直接落库＋前端撤销（多一个反悔窗口与状态，
   弃——与「提案制」在库内其他 AI 建议不一致）。
6. **占位机制整体退役**：`Act.onClick` 改为必填，「不可用」一律走 `disabled`；缺少处理器不再是
   「显示规划中」，而是类型错误（编译期拦住），符合「在设计上解决」的门禁口径。
7. **面板三个重复动作撤销**（同 ⑪ 口径）：与 `reconcile` 收尾、提示词页签 AI 润色同产出的动作不再
   在右栏重复；在 ADJUSTMENTS #27 ⑫ 登记为设计修正而非功能缺失。
8. **记账口径**：检查 `ai_check_{kind}`、补全 `outline_fill_gaps`、精修 `prompt_refine_{mode}`，
   失败各留 `_fail`；补全与起草同族，**记账先于解析**（调用已完成＝钱已花，产物不合格也要留痕）。

## Risks / Trade-offs

- [模型返回非 JSON → 检查静默为空] → 提示词强约束只输出 JSON；有格式时逐条校验；弹窗提供「重新检查」。
- [关系类素材在端点内查询 → 章节越权/跨书取数] → 查询恒以 `project.id` 为界（novel_id 过滤）。
- [精修稿覆盖作者手工改的提示词] → 弹窗显示完整修订稿＋「采纳并保存」显式按钮；保存走既有链有版本快照兜底。
- [占位退役后新增动作忘配处理器] → `Act.onClick` 必填，缺处理器为编译错误；单测覆盖各页签动作归属。
- [六类检查名与原型文案漂移] → 面板文案取 storyline.html aiActs 原文；类别键用后端枚举，映射表集中在 `lib/aiCheck.ts`。

## Migration Plan

1. 后端：新端点与提示词模板随代码发布；无 schema 变更、无数据迁移。
2. 前端：面板/弹窗随构建发布；已存提示词不受影响。
3. 回滚：三端点均为新增（无既有调用方），前端回滚旧构建即恢复占位态；无状态残留（产物不落库）。
