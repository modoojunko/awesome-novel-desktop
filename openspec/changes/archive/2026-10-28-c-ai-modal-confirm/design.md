# c-ai-modal-confirm — Design

## Context

出卡交互（AiCardModal：点行→生成中占位→结果卡→采纳/换一个/关闭即弃＋回执撤销）是本规矩的参考实现；本次四整改点分散在三处，各自复用其所在界面已有的弹层基建，不新造组件体系。

## Goals / Non-Goals

**Goals**
- 四处违规统一为「出卡过目 → 采纳才写入」；关闭一律即弃。
- 交互最小增量：能塞进既有弹层的塞既有弹层（卷纲规划台完成态），只有纯表单页新增轻量出卡（封面/头像、章纲补全）。

**Non-Goals**
- 不动卷纲抽卡「确认成卷」（#3 边界：有摘要确认步、付费链路刚拍板，留口径）。
- 不动正文流式写作/一键续写（写作面本体，豁免）。
- 不动后端端点与提示词。

## Decisions

**D1. 卷纲：规划台完成态即审阅面。**
手写路完成态直接在 genbox 内渲染产物全文（七字段＋伏笔建议＋checks，可滚动），「回填」改「采纳 · 回填卷纲」——采纳语义在文案上坐实。生成中关掉的原「后台完成自动回填」臂删除（NovelWorkspace effect），改为完成后 toast 提醒「打开规划台过目后采纳」；`takeAutoBackfill` 钩子保留（显式采纳仍走它），`autoBackfill` 标志语义变为「未过目的待采纳载荷」。

**D2. 章纲补全：产物与写入分离。**
`runFillGaps` 只取数并置 `gapsDraft`，`adoptGapsDraft` 才 `setOgForm`＋进编辑态。出卡逐字段展示（FILL_FIELD_LABELS 单源进 chapterForm.ts）；仍只补空缺格，落库照走既有保存链。

**D3. 封面/头像：工坊内二次出卡。**
`extractDraft` state 承载 `{kind, text}`，同一张卡承载采纳/换一个（重掷替换卡内文本不重复弹层）；采纳写入对应描述框后照旧「显式保存才落库」——出卡加的是过目门，不改保存语义。

**D4. 文案统一口径。**
出卡说明句统一三件套：「采纳才写入（写入后仍可改）；关闭即弃；『换一个』重新生成」。

## Risks / Trade-offs

- 卷纲「关掉也不影响」的后台完成臂是既有 UX，删除后后台完成要多一次打开过目——以 toast 提醒补偿；e2e 无断言该臂，单测钩子层不受影响。
- 章纲补全出卡后「检查后保存」的旧提示语义由采纳 toast 接管（「已采纳 N 项补全，检查后保存」）。
