# c-cog-cells-slim — 设计

## 去留判据（数据定案）

保留格 = AI 认知补充候选（COG_FILL_KEYS，11 格）；退役格 = 纯手填且全库零填充（19 格）。
本地库实测（novel-v0.40.db 快照，99 张卡、全部在写书）：11 格各 5 卡有值（集中在唯一一本细调设定的书，由 AI 补全写入），19 格历史填充为 0。用户实测（角色屏截图）与数据同向。

保留清单（= COG_FILL_KEYS，天然闭环）：w1 w5 / s1 s5 / v1 / p2 p6 p3 p4 / b1 / e3。
退役清单（19）：w2 w3 w4 / s2 s3 s4 / v2 v3 v4 / p1 p5 / b2 b3 b4 b5 / e1 e2 e4 e5。

## 关键决策

1. **零迁移**：cog/dossier 为 JSON 列，退役键留在旧数据里也不呈现、不参与写入（单格写入白名单用 COG_KEYS，AI 补全白名单用 COG_FILL_KEYS，均自动收窄）。与「认知层新增格位不需要迁移」同一条对称原则。
2. **v1→v2 老字段改落层主格**：world_view→w1、self_image→s1、values→v1、environment→e3。原落点（w3/s2/v2/e1）退役后不可写；层主格语义最宽，是老字段的最近似归宿；legacy 原文双写回滚基准不变。upgrade_drill 断言随迁。
3. **镜像同步**：前端 `characterModel.ts` 是后端常量的逐字镜像（parity 正则对拍锁死），两端同批改。
4. **提示词仓零改动**：模板不手抄格名，键位清单由后端渲染（`cog_briefs`/空格键位均从 COG_FILL_KEYS 派生）；已 grep 提示词仓，19 格 label 零引用。
5. **不回收键名**：退役键永久空置，不复用（避免旧数据残留键「复活」成脏数据）；将来要补新格按既有口径追加新键即可（新增格位零迁移，规格已有场景）。

## 风险

- 层内格数变少（价值观/行为/环境仅剩主格 1 格）：版式自适应（主格带 `full` 通栏），层头计数变 `n/n`。链路文案「六层是一条链」不变——六层仍六层。
- 存量导出包（v2 yaml）里带退役键：导入走单格写入白名单 → 自动拒绝，无脏写。
