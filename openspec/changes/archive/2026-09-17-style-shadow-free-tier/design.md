## Context

见 proposal.md — Why。约束：影子行的存储与清洗口径（#392 已定案并有 11 例测试）不动；本次只动「档位可达性＋手工编辑面」。全站门控口径基准：手工编辑免费（如章纲表单、全书文风三区、提示词手动编辑），AI 生成归 PRO（如章纲 AI 起草、文风蒸馏、影子 AI 建议）。

## Goals / Non-Goals

- Goals：免费档获得与全书文风三区同权的本章影子手工编辑；AI 建议入口明确 PRO。
- Non-Goals：不改影子端点/存储形状；不做免费档的 AI 建议试用额度；不动付费墙其他面。

## Decisions

**手工编辑直接行内（输入即改、失焦即存）而非弹窗表单**：影子一行只有「取值＋理由」两个短字段，行内编辑与既有行布局同形、无新弹窗层级；备选＝编辑弹窗——否决（两个字段的弹窗交互过重）。**添加行用滑块（选择六行参数之一）而非自由维度名**：与 suggest 白名单同集（六行），避免手工时代引入脏维度（PUT 本身不设白名单，靠 UI 收口径）。

## Risks / Trade-offs

- [失焦即存产生多次 PUT] → 端点轻（单行 JSON 落库），可接受；不做去抖以求简单可测。
- [免费用户无基线时编辑影子无注入效果] → 面板保留既有「先完成蒸馏」说明；影子先行可存，蒸馏后即生效。
- [PUT 无维度白名单＋免门控＝免费可写任意维度] → UI 限六行；API 层宽松属既有定案（#392 锁现状），不在本次扩权。

## Migration Plan

纯前端＋spec；无数据迁移。回滚＝回退前端提交（写入的影子数据形状不变，无害）。
