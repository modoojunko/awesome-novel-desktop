## 设计决策

### 让位制而非改唯一约束 / 物理清除

- **改部分唯一索引**（只约束活跃行）：SQLite 建偏索引容易，但既有库迁移要重建表（SQLite 不支持 DROP CONSTRAINT），风险与收益不成比例。
- **撤销窗口过期后物理清除**：为 8 秒窗口配清理器，窗口边界竞态复杂；且 TokenLog 按配置聚合用量、换绑审计按 id 反查配置名，硬删行会让历史归属断链。
- **选定：让位制**——软删行不可见，改名零感知；无 schema 变更、存量数据零迁移（被占的名字在下一次新建/改名时自动让位）；撤销与历史链路原样保留。

### 关键实现判例（评审轮固化）

1. **flush 分批**：让位 UPDATE 与调用方随后的改名/INSERT 被 SQLAlchemy 归并同一 executemany 批次时，SQLite 唯一约束逐行检查会同批自撞（顺序依赖：组合跑红、单跑绿）。修＝`_assert_name_available` 末尾显式 `flush()`，让位语句先单独落地（同事务，失败整体回滚，无部分提交）。
2. **朱雀保留名豁免**（评审 P1）：让位循环遇 `vendor="zhuque"` 改判 409。凡做「占用资源让位」先查谁把这名字当 KEY 用。
3. **路由层约束兜底**（评审 P2）：`IntegrityError` → 回滚 → 409，治让位名与字面名相撞的构造态与并发交错窗（500 变 409）。

### 旧守卫去除的安全性

update 路径原 `ApiConfig.id != config_id` 守卫冗余：改名分支仅在 `updates["name"] != config.name` 时进入，自身不可能是重名源；软删让位集更不含自身（自身是活跃行）。
