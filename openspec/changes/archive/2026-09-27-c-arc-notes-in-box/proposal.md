# 散想法入口＝主线大框（用户拍板口径）

## Why

规格写「起草主线…**接受散想法输入**」，右栏行描述也写「散着说想法也行」，但前端从不发送 `input`（`StoryArcForm` 恒发 `{}`）——「散想法」这个入口在界面上不存在。用户 2026-09-27 拍板：**不新增输入框，就用主线面板已有的「这本书从头到尾说什么」大框承接**——作者想到什么直接写在里面，生成时自动算作输入。

真机实测（隔离栈，见 `real-machine-check.md`）：把散记写进大框（「圣银教团最后背刺／血渴只暂时睡着／加一场雨夜码头追凶」）后点起草，产出三点全部吸收、设定专名与铁律照原文使用——**能力已成立**；缺的只是把这件事在提示词与规格里说清楚：现在那块标题是「当前主线（未填部分用（未填）标注）」，没有告诉模型「这里可能是散想法/半成品，顺着扩写、关键词别丢」。

## What Changes

- **`arc_draft.prompt` 改口径**：把「当前主线」块改称**「作者已写在主线框里的内容」**并注明「没写全很正常：可能是散想法、半成品或已成形草稿」；任务句与要求句明确——框里已有内容（含散记）就是本次起草的输入，**顺着扩写、关键词与要求尽量吸收、不要原样复述**；「（未填）」降级句保留。接口 `input` 通道保留并改称「作者这次的补充说明（通常为空）」。
- **规格对齐**（`storyline-settings`）：素材条款里「作者散想法」的定义改为**「作者在主线框里已写的内容（散记/半成品/成稿同权）」**，接口 `input` 明确为「可选补充说明通道」；素材顺序条款随之更新（主线框块＋补充说明行，任务与 JSON 仍压尾）；门槛不变（有简介/有输入/框里有内容任一即可）。
- **非目标**：不新增任何输入框、不加存储字段、不改前端（`StoryArcForm` 与右栏文案零改动）、不动校准与体检的既有口径（校准本来就吃主线全文；体检不吃作者输入）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `storyline-settings`: MODIFIED「右栏 AI 三行（全部聚焦主线）」——散想法入口定义为「主线框已写内容」（接口 input 降为可选补充通道），并把「顺着扩写、关键词吸收、不复述」写进起草口径。

## Design Impact

无用户可见界面改动（零前端改动，右栏描述文案原句「散着说想法也行」在本口径下**由虚转实**，无需改字），故不触发原型先行与 design 门禁；受影响端＝仅 C端 后端。

## Impact

- **代码**：`client/backend/prompts/arc_draft.prompt`（块标题＋任务/要求句）。
- **接口/存储**：无变化（`{input?}` 仍可选；主线框内容仍走 story_arc 读取）。
- **测试**：`test_story_arc.py` 增模板口径断言（新块标题、关键词吸收要求句、旧「当前主线」标题不再出现）；真机关键词吸收走人工 A/B（evidence 文件）。
