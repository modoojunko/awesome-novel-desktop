## Context

见 proposal.md — Why。二三/四期实现已合入 main（#383/#386/#388/#389/#390/#392 及本变更所在 PR），本文件记录这些行为落地时的关键技术决策，供 spec 归档后追溯。约束：用户拍板「同样的对象不要另外建新表」；原型 storyline.html 为行为事实源；C端 为单机 SQLite 单后端。

## Goals / Non-Goals

- Goals：把已实现行为固化为契约锚点；记录决策理由（排队门禁落点、回退清理范围、影子存储选型、推演兜底策略、六来源组装复用）。
- Non-Goals：不改动任何已合实现；不引入新表；不覆盖一期收尾提案（archive-reconcile 在途变更自管）。

## Decisions

1. **排队门禁作为写路径守卫而非状态机迁移**：frontier 为派生读（首个未归档章），不落列不落表；prose PUT 与 AI 写章端点在执行前查 `is_writable`，非 frontier/ghost 返回 409。备选：把「排队」做成显式状态字段——否决（同一事实两处存储，回退/归档需同步，违「对象不另建表」）。
2. **回退＝截断＋幽灵化，不删除**：被回退章保留数据并记 `ghost_of`；派生数据按章序清除（出场引用状态变化、来源章关系、该章伏笔留痕、收尾提案、版本快照）。备选：物理删除——否决（不可恢复且与「旧稿支线只读保留」的原型语义相悖）。
3. **文风影子落 `chapters.style_shadow`（JSON 列）**：拍板③「记章节档案」——影子是章级差异不是新对象；读写走专用小端点（PUT 形状清洗防全对象替换误覆盖）。备选：独立影子表——否决（同对象第二份存储）。
4. **推演端点 AI＋确定性兜底**：原型 sim 本身是确定性算法（关键事件环＋模板走法），AI 是增强；因此 AI 失败回落确定性推演（`source=fallback`）而非报错——弹窗永远可用、产物口径两端一致。备选：失败 502——否决（原型无失败态）。
5. **六来源展示复用写作组装链**：prompt-sources 用 `build_chapter_context`＋同款渲染函数出投影，避免「展示一份、注入一份」漂移；预览截断 120 字为纯展示，不承诺完整注入文本。
6. **走法定形在服务端**：moves 的 `k/label/out` 由后端定形（顺/拗、角色动作前缀），前端只做选择与回显——保证弹窗文案与「收进章纲」的走法行口径单源。

## Risks / Trade-offs

- [影子与基线漂移（蒸馏重跑后影子仍覆盖旧维度）] → PUT 不设维度白名单、suggest 白名单过滤；维度治理留待后续版本。
- [回退清理范围含未来新增派生表] → 清理清单集中在 `revert_to_chapter`，新增章级派生数据必须登记到该函数（代码注释同样声明）。
- [确定性兜底被误认为 AI 产物] → 响应含 `source` 字段（UI 不区分展示，接口层可查）。
- [排队门禁影响既有 API 备料/测试流] → e2e 备料顺序按 frontier 语义调整（#391 先例）；新写路径用例须先归档前章。

## Migration Plan

- 加列走 `main.py` 幂等 ALTER（style_shadow/ghost_of/origin_chapter_id/state_change），存量库首启自动升级；`ch_ref→origin_chapter_id` 一次性回填。
- 回滚：代码回退即可（加列不删；ghost 章数据仍在，`ghost_of` 列无写入方即失效）。
