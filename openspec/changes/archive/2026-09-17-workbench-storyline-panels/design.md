## Context

见 proposal.md — Why。约束：storyline.html 为两件原型件的唯一事实源；右栏面板的动作清单里未实现项按用户拍板先占位；数据一律复用既有端点（零后端改动）；中栏页签序按原型（…角色关系/伏笔/操作）。

## Goals / Non-Goals

- Goals：补齐中栏第 8 页签与右栏随页签面板；把「规划中」占位作为未实现动作的统一呈现口径。
- Non-Goals：不实现占位动作背后的能力（逐个补，见 Open Questions）；不改右栏卷模式；不动导航与顶栏。

## Decisions

1. **右栏面板保留进度卡与卷模式，只把「章节态的辅助区」改为页签感知**：原型右栏整体随页签变，但 C端 进度卡（目标字数就地编辑）是有测试覆盖的真实功能，整块替换会丢功能；故=header→locked 提示→AI 生成正文工具→**页签感知辅助面板**→进度卡。备选＝完全照原型替换——否决（换皮减功能）。
2. **正文页签的续写/润色/扩写沿用原工具卡（带描述），不降级成动作按钮**：这三项是有交互细节（选区/流式状态）的真实工具，卡片形态信息量更高；其余页签动作用紧凑按钮列表。
3. **未实现动作＝禁用按钮＋「规划中」标签**（沿用既有 `.tag-plan` 与 book.html rail 先例），点击零请求；后续补一个解开一个。
4. **统计卡懒取**：仅激活页签取数（prompt-sources / style-shadow baseline / graph / hooks+volumes / world），失败显示「—」。备选＝各页签把统计上抛——否决（跨组件状态与轮询复杂度不成比例）。

## Risks / Trade-offs

- [与中栏页签重复取数（同端点二次 GET）] → 均为轻量只读端点且仅在激活页签触发；可接受。
- [占位动作被误读为可用] → 禁用 + 「规划中」标签 + title 说明，三重信号。
- [「下游挂着旧设定」等统计为「—」被当成故障] → 属未实现能力（重写流立项后补），显示「—」为诚实降级。

## Migration Plan

纯前端；回滚即回退提交。无数据迁移。
