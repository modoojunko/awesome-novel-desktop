# c-kb-instance-list · 知识库列表改实例行——每行一个实例，行顶归属链

## Why

知识库列表当前按「知识条目」组织（一行一个 title），但 boss 拍板的模型是「**拆书出来的都是实例**」——每条写法案例是一个实例，列表应该**每行一个实例**，行顶展示归属链（题材 → 父知识 → 知识点），让「实例归属什么知识、知识归属哪个父知识」一眼可见。原型的行形态 boss 已验收（2026-11-06，drafts 原型）。

## What Changes

- **后端**：新增跨知识实例列表查询——`GET /api/kb/instances`，全量返回扁平行（每行含：row_kind 判别、实例文本、出处、所属知识 id/标题、**后端拼好的归属链数组**、来源标、created_at；**不含 fields_json**——列表只渲染一句话，抽屉点开走既有单知识实例查询），支持 genre/concept/q 参数；素材行（origin='material'，未归属）以 `row_kind=material` 同列表返回（带素材标）。过滤边界：已归属素材（archived）不重复出现、已归档知识（archived_at 非空）的实例排除、情节素材排除（永不归属）、JOIN 侧 user_id 隔离
- **前端**：实例侧来源（界面词「全部来源/拆书/手录」）下列表主体改实例行列表——每行一个实例：行顶归属链（题材段为非链接文字，知识各级 accent 色可点下钻）＋实例内容一句话＋出处行（按值渲染，拆书链路书名/章号现状为空、空片段不渲染）；右侧收录日期＋来源标；素材行带「待归属素材」标
- **数据源分臂**：来源筛选为「官方精选」或「已隐藏」时保留现知识行列表（基线层条目只住这里，现有分组/空态/同步/隐藏管理不动）；实例行列表不混入基线层内容；角色设定视角除外（CharacterInstanceView 不动）
- 实例臂内筛选分工：来源（拆书/手录）与「跨题材通用」档由前端按行过滤（全量在内存）；计数行按实例口径（全量返回，N 与分类分布同口径、均含待归属素材行）；角色设定视角（CharacterInstanceView）不动
- 首页副标题恢复为已验收原型文案「存的是拆书拆出的好写法和自己踩过的经验，写新书时能用上。」（覆盖 c-kb-knowledge-v2 旧文案）
- 点实例行或链上知识级 → 打开对应知识详情抽屉（走既有 `entry(knowledge_id)` 兜底路径——实例行 id 是实例 id，不是 entries id）；素材行点开 → 既有素材提示卡（现交互，抽屉 material 分支）

## Impact

- 后端：`kb/service.py`（跨知识实例查询——JOIN kb_entries 拿标题/题材/类别，应用层拼归属链）、`kb/router.py`（`GET /kb/instances` 端点）
- 前端：`KnowledgeBasePage.tsx` 实例侧列表改实例行（官方精选/已隐藏臂不动）；`kbApi.ts` 加封装与行类型
- 素材行（origin='material'）混排显示，带素材标；总结归属后自动变为实例行
