# Proposal: c-0vol0ch-empty-state

> 补建卷宗：实现已经 PR #450 合入 main（用户直接给出设计稿 `docs/design-c/drafts/0vol0ch-empty-state.html`
> 要求「把现有的改成这样」，未走先行提案）；本卷宗按 openspec 归档纪律补记需求变化并归档立卷。

## Why

零卷零章的写作页此前**没有起点**：三栏各说各话，且新增无路可走——

1. 顶栏「当前主线」定位在无卷无章时整块留空（`hereTarget === null`），没有任何起手动作位。
2. 中栏是「开始创作」通用面板（标题＋一句说明），「有卷但未选中」与「零卷零章」两种情形共用
   同一块文案，既没区分也没入口。
3. 左栏空态只提示「点击左上「＋」添加第一卷」，而**「新增一章」在空书里根本不存在**：章的
   创建入口只挂在卷上（卷 hover 的「＋」或建卷弹窗的初始章数）；直接建章会被
   `createChapter` 以 toast「请先创建卷」拒绝＝死路。
4. 右栏未选中态只给一句卷语境引导（「在左侧目录里选中一卷…」）——空书里同样无处可选。

设计稿（storyline.html 派生：数据清空为 0 卷 0 章 ＋ 空态三处）给这四种情形一套明确起点。

## What Changes

- **顶栏主线定位**补「空书」态：`空书 · 第 1 章待写 · 未开始 · 还没有卷与章节 · ＋ 新增一卷`
  （与「当前主线」态互斥）。
- **中栏空态两分支**：零卷零章＝起手卡 `.e-empty`（「这本书还没有开始」＋说明句＋双入口
  「＋ 新增一卷」／「＋ 新增一章」）；有卷未选中＝同容器一句选章引导。原「开始创作」面板退役。
- **左栏空态**：提示文案改设计稿原文；空书态底部新增 `.tree-add` 两入口（替代空书里没有对象的
  「确认全部已填章节」）；非空书态左栏结构零改动（书树仍按 book.html 基线）。
- **起手链行为**：空书「＋ 新增一章」先垫「第一卷」（程序默认序号形态，可改名）再排「第一章」，
  新章直接落章纲页签。
- **右栏未选中态**：按设计稿补原型的无语境 aiShell——`当前页签 / 未选` 行 ＋ 通用引导语 ＋
  四格全书统计（当前主线／悬置伏笔／全书章节／基于旧设定）＋ 免费档脚注。
- **结构**：「添加卷」弹窗由 `OutlineTree` 移入 `modals.tsx`，工作台壳层持有，空书态三处入口共用。

## Capabilities

### Modified Capabilities

- **workbench** —— 三条需求改写：①`EmptyState without settings gating (N4)`（空态落到写作页
  当前实现：起手卡两分支／左栏空态与两入口／先垫卷的起手链／三处入口同实体）；②`书内顶栏
  （行头归一：单行 appbar）`（bar-here 补「空书」态）；③`右栏「AI 辅助」面板（随页签切换，
  动作全部落地）`（未选中态由「通用空态说明」细化为四格全书统计面板）。

## Design Impact

- **受影响端**：仅 C端（S端 零改动）。
- **受影响屏/弹层**：书工作台 → 写作页（空书态与未选中态）；「添加卷」弹窗（实体上移，外观与
  内部契约零变化）。
- **对象状态**：书生命周期「设定中（0 卷 0 章）」的写作页呈现；章「待写」占位与「拟定」章
  不受影响；不新增状态位。
- **共享段**：SHALL NOT 触碰两端共享段（`base.css` 令牌与基础组件类未动）；改动全部落在
  C端屏级 `src/design/book.css` 与工作台组件内。
- **原型先行**：是。设计源＝`docs/design-c/drafts/0vol0ch-empty-state.html`（用户交付的设计侧
  工件，drafts 目录、未入 parity 基线）；偏差登记＝`docs/design-c/prototypes/ADJUSTMENTS.md`
  新章「0vol0ch-empty-state.html 空书态落地」10 条（含两处不动的壳层文本留档）。
- **设计工件产出方**：设计侧（用户直接给出草稿）；实现侧只做对齐自查（同视口逐栏截图对拍）
  与偏差登记，不另出设计稿。
