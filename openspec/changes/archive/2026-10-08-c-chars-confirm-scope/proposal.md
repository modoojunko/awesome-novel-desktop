# c-chars-confirm-scope — 角色面板：卡级自动保存与整项确认分家

## Why

内测吐槽（2026-10-08 转述）：「角色设定页里，某个角色的设定保存 和 整体角色设定的确认 混一起，容易搞晕」。实勘后是三件事叠加：

1. **两个粒度的「保存 / 确认」同屏同词**：人物卡区的「已自动保存」（单格 PATCH，防抖 600ms 自动落库）说的是**这一张卡**；面板页脚的「确认完成 / 保存修改」说的是**整项**——跑全书确认门禁、计入设定 N/7 进度，未确认时还「确认即前进」跳到下一项。按钮不带对象名，两处都用「保存 / 确认 / 已保存」这套词。
2. **门禁对象不是眼前这张卡**：门禁两档（第一次确认只查主角名称＋一句话人设；此后查主角与每张非路人卡的六项）。在配角卡上点「确认完成」可能直接通过并跳页（被读成"这张卡确认了"）；已确认态点「保存修改」可能报**别的卡**的缺口（「还差：银铎缺 能力上限、能力代价」）——而改动其实早就自动存好了。
3. **设计稿本有解法，实现漏落**：`docs/design-c/prototypes/character-settings.html` 的 `syncFoot()` 本就把页脚提示做成**动态缺口摘要**（「还差 N 处：…」「改动会自动保存，随时可以确认」），实现只落了通用静态句「高级项可后补 · 确认即计入进度」；缺口数据（列表接口 `gaps`，后端 `card_gaps` 已算）前端至今**零消费**，缺口只在点击后由 toast 事后告知。

## What Changes

- **角色面板页脚提示改按档位给缺口摘要**（把设计稿口径补进实现）：五态——无主角 / 第一次确认缺主角项 / 第一次确认可过 / 此后确认有缺口（点名首张卡＋缺口卡数）/ 齐了。有缺口走 warn 语气常驻（复用既有 `.warnline` 提示行与 note 家族，不新增档位/胶囊）。缺口取列表接口既有 `gaps` 字段（后端零改动、前端零新增请求）。
- **已确认态主按钮按保存模型分派**：角色 / 伏笔是自动保存制——右下角按钮与成功回执不再叫「保存修改 / 已保存」（改动早已落库，点它是**重新确认**），统一「重新确认」「已重新确认」；表单制面板（简介 / 题材 / 世界 / 主线 / 文风）保持「保存修改」不变。
- **人物卡保存态归位**：四态保存提示从卡区上方独立一行移回卡头右侧（与主角徽标、合并/删除同列，即原型 `ch-side` 位置），并加对象限定词「这张卡…」——与页脚整项口径在视觉与措辞上分开。
- 明确不做：不改门禁判据与两档语义（后端零改动）；不改「确认即前进」；不动右栏 AI 行、卡内其它文案与列表行；不给角色列表行加缺口角标（本轮只做分家）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `character-settings`: 「确认门禁两档与退回」补齐**面板脚缺口摘要**（按当前适用档位、默认点名首张卡、warn 常驻）与**已确认态按钮/回执口径**（「重新确认」而非「保存修改」）＋人物卡保存态归属卡头带对象限定。
- `foreshadow-settings`: 「确认门禁与内容有变降级」补齐已确认态按钮/回执口径（同为自动保存制，「重新确认」）。

## Design Impact

- **受影响端**：C端（S端零改动）。
- **受影响屏/弹层**：设定屏 · 角色面板（页脚提示 + 主按钮 + 人物卡头部保存态）；设定屏 · 伏笔面板（页脚主按钮与回执文案）。
- **对象状态**：复用既有四态保存提示（saving/saved/dirty/failed）与 note/warnline 提示行——不新增状态档位、胶囊形态或提示语气（info/ok/warn/err 词表不变）。
- **共享段**：不触碰（不改 `base.css` 令牌与基础组件类、不改 pill/notice/sk/panel/f-err 家族；`warnline` 是既有关）。
- **原型先行**：需要——`docs/design-c/prototypes/character-settings.html` 同批落笔（`syncFoot()` 分档、已确认态主按钮文案、卡头保存态限定词），偏差登记 `docs/design-c/prototypes/ADJUSTMENTS.md`。
- **设计工件产出**：实现侧自查（含 `design:lint`；`design:check` 的角色屏 parity 用例为"记录不阻断"态，本批回归其报告差异率）。

## Impact

- 前端：`components/novel/workbench/SettingsView.tsx`（角色页脚分档渲染 + 按钮/回执按保存模型分派）、`components/novel/settings/CharacterManager.tsx`（卡头保存态归位 + 门禁缺口经新回调上抛，含 `CharGateHint` 类型）。
- 测试：新增单测（SettingsView 角色页脚五态与按钮分派；CharacterManager 缺口上抛与卡头保存态）；e2e `settings-forms.spec.ts` 角色链补页脚断言、`foreshadow-settings.spec.ts` 按钮改名、`design-parity-book.spec.ts` 角色种子把占位空 `gaps` 改为按种子实算（两侧提示文案才逐字对齐）。
- 原型：`docs/design-c/prototypes/character-settings.html` ＋ `ADJUSTMENTS.md` 登记。
- 后端：零改动（`gaps` 已在 `GET /novels/{id}/characters` 列表响应中下发）。
