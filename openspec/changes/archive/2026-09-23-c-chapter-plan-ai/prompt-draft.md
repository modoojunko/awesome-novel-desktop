## 1. chapter_split 模板全文（system）

```text
你是长篇小说的章节结构顾问。这一卷的起止边界已由卷纲定好，剧情一章一章拆。现在拆下一章：请按下面的素材，给出 3 个互斥的剧情方向，供作者挑一个排上。

<<material_blocks>>

硬规则：
1. 所有方向接同一条进场：进场只有一句，不同方向接的是同一句话，不同的只是这一章往哪走。
2. 不凭空添人添事添地点：只用素材里出现过的元素组合；人物、势力、地点的名字照设定原文写全（申报要用它对拍）。
3. 【世界铁律】是红线：任何方向不得违反、不得绕开。
4. 本章结尾停在"还没完"的地方：谁或什么变了、但没被解决，让读者想立刻看下一章。
5. 素材标注「本章是本卷末章」时例外：三个方向的本章结尾都必须收在卷纲第四问「预期结局」上，把这一卷收掉，不另开新悬念；收束以【结局（作者写的）】为准。
6. 反转不靠巧合：预期被打破，靠的是前面埋过的东西顶上来，不是天降设定。
7. 冲突一层压一层：解决小的、撞上更大的；不平铺一个坎磨到底。
8. 方向走到头，故事状态要真的变了：人、关系、处境至少一样和进场时不同。
9. 方向之间必须在结构上真的不同——差异轴互不相同，不是同一套的三种措辞。只想得出两套就只给两套，并在 note 里写明原因。

先给差异声明，再给卡——
- diff.axes：每个方向一个差异轴，从 <<split_axes>> 里选，互不相同。
- diff.one_liner：每个方向一句「这一章被推向哪里」，各 ≤20 字。三句要互换位置读不通：把某句挪到另一个方向上就讲不通，才算真的互斥。合格例：「撕页藏进怀里」「交出半条航线」「信标当众暴露」；不合格例：「发现一个秘密」「知道一个真相」——放哪个方向都通。只想得出两套时给两句，并在 note 写明原因。
- 卡面的 axis 必须与 diff.axes 对应位置逐字一致。

每张卡给这些字段——
title（章标题，≤12 字，可空）｜plot（本章剧情：目标→阻碍→结果，≤150 字）｜obstacle（碰到的挑战：剧情推进时撞上的墙，≤60 字）｜ending（本章结尾：停在哪里，≤80 字）｜acts（本章行动：谁做了什么，一行一条，最多 4 条、每条 ≤60 字）｜stage（阶段：从 <<plot_stages>> 里选最贴的一档）｜why（这一章吸引人的是哪一下，≤30 字）｜gap（这一章差在哪，≤30 字）。
cast／factions／places：这一张卡用到的全部人物名、势力名、地点名，照设定原文写全；没有就给空数组。

评分（剧情吸引力）——你只排名次，等级由系统算：
- 四维各看各的字段：反转只看 plot＋ending｜递增（冲突层层递增）只看 obstacle＋plot｜推进（剧情推进）只看 plot＋ending｜拉力（结尾拉力）只看 ending。
- ranks：每一维给每张卡一个名次（数字，1＝该维最好）。名次从 1 连着排、不跳档；可以并列，但并列必须在 reasons 里说明原因。
- reasons：每一维一句 ≤20 字的话。该维第一名唯一时，这句话是第一名的依据——从得胜卡对应字段里摘一段连续原文（4–12 字），不要改写、不要概括（系统会逐字查找，找不到视为不合法）；该维并列第一时，这句话写并列的原因。
- why／gap 只评这一卡自己，不提另外的卡；全文不要出现任何等级、字母或分数，也不要自创 grade 之类的字段。

checks：0–3 条，只写你拿不准、或与卷纲有张力的地方，每条 ≤40 字。

只输出 JSON，不要其他文字：
{"diff":{"axes":["加速","关系","收束"],"one_liner":["…≤20字","…≤20字","…≤20字"]},"directions":[{"axis":"加速","title":"…≤12字","plot":"…≤150字","obstacle":"…≤60字","ending":"…≤80字","acts":["…≤60字"],"stage":"矛盾升级","cast":["…"],"factions":[],"places":["…"],"why":"…≤30字","gap":"…≤30字"}],"ranks":{"反转":[1,2,3],"递增":[1,1,2],"推进":[2,1,3],"拉力":[3,1,2]},"reasons":{"反转":"…≤20字","递增":"…≤20字","推进":"…≤20字","拉力":"…≤20字"},"checks":["…≤40字"],"note":""}
```

注入说明：
- `<<material_blocks>>` 由端点按 §5 顺序装配成整块传入；模板只在规则里**引用**块名（【世界铁律】【结局（作者写的）】），不感知块序——块序与预算的断言写在装配器单测（tasks 3.2）。
- `<<split_axes>>`＝`加速／关系／线索／代价／危机／收束`、`<<plot_stages>>`＝`开局铺垫／冲突初现／矛盾升级／重要转折／高潮爆发／卷末收束`——服务端闭集常量注入（同卷级 `<<focus_axes>>` 先例），模板与校验共用一个单源。
- 三张卡**不带进场字段**：进场由服务端统一渲染到卡面（三卡天然一致），模型只读不写。
- 模板全文不得出现「伏笔台账」「主线全景」字样与内容（§5 负面清单＋grep 断言）。

## 2. user 消息模板

首次：

```text
请给出第 <<chapter_no>> 章的 3 个剧情方向（只输出 JSON）。
```

重试：user 固定为 `请给出 2 到 3 个剧情方向（只输出 JSON）。`，失败原因追加到 **system 末尾**（照卷级先例 `system + "\n\n（上一次……。）"`），温度 0.7 → 0.3。喂回短语由服务端按校验失败点拼装（全部机器可判）：

| 失败点 | 喂回短语（填入「上一次〈…〉」） |
|---|---|
| 不是合法 JSON | 的输出不是合法 JSON——只输出一个 JSON 对象 |
| 三轴重复／条数与卡数不齐 | 的差异轴重复了——axes 互不相同、条数与卡数一致才合格 |
| 未知轴／与声明不一致 | 的第 X 张 axis 不在闭集里或与 diff 不一致，那张卡已丢弃——axis 必须与 diff.axes 逐字一致 |
| 两卡同质 | 的第 X 张与第 Y 张的（剧情，结尾）太像——把其中一张重写成结构上不同的版本 |
| 名次依据寻不到 | 的〈维度〉第一名的依据在得胜卡字段里找不到——依据要从得胜卡字段里摘原文 |
| 字段不合法 | 的第 X 张缺 plot／ending、stage 越界或字段超长，已丢弃 |
| 末章结尾越界 | 的第 X 张结尾没收在卷纲「预期结局」上——末章结尾必须收卷 |
| 只出两套未写原因 | 只给了两套但 note 为空——note 必须写明原因 |

## 3. 输出 JSON schema 逐字段表

总则：AI 输出预算**严于 DB 列宽**（summary/ladder_exit 300、challenge 150）——手写输入框 maxlength 与 AI 输出预算同值，两条路的值都落在 DB 列宽内（spec 明文）。schema 外字段一律忽略——**模型自给的 grade／字母不读、不透传**，字母只由服务端算。

| 字段 | 类型 | 上限 | 必填 | 服务端校验 | 落库去向 |
|---|---|---|---|---|---|
| `diff.axes` | string[2–3] | 每值 ∈ 章级闭集 | 是 | ⊆ 闭集、互不相同、条数＝directions 条数；重复/条数不齐 → 整批重试一次；未知值 → 引用它的卡丢弃（不改写） | 不落库（差异声明＋卡面轴展示） |
| `diff.one_liner` | string[2–3] | 各 ≤20 | 是 | 非空；超限截断到 20（纯展示，不影响互斥判定） | 不落库（随轴展示） |
| `directions[]` | object[2–3] | 最多取前 3 张 | ≥2 张合法 | 逐卡校验，非法丢卡（见下） | — |
| `.axis` | string | ∈ 闭集 | 是 | 与 `diff.axes[同序号]` **逐字一致**，否则丢卡 | 不落库（落库的是 stage） |
| `.title` | string | ≤12 | 否 | 空 → 排上时默认「第N章」；超长 → 丢卡 | `chapters.title` |
| `.plot` | string | 1–150 | 是 | 非空，否则丢卡；超长 → 丢卡 | `chapters.summary` |
| `.obstacle` | string | ≤60 | 否 | 可空；超长 → 丢卡 | `chapters.challenge` |
| `.ending` | string | 1–80 | 是 | 非空，否则丢卡；超长 → 丢卡；**末章**（剩余配额＝1）时与卷纲「预期结局」difflib 相似度 < 0.5 → 丢卡（阈值实现期待定，见 §7 备注） | `chapters.ladder_exit` |
| `.acts` | string[] | ≤4 条 × ≤60 | 否 | 去空行、逐条超长 → 丢卡；条数 >4 → 丢卡 | `chapters.chapter_acts`（TEXT 一行一条） |
| `.stage` | string | 六档闭集 | 是 | ∈ 六档，越界 → 丢卡（**不改写**——卷级静默改写教训） | `chapters.plot_stage` |
| `.cast`／`.factions`／`.places` | string[] | 不设上限 | 否 | 去空串；与已知实体集合（角色 name＋aliases／势力名／地点）做差 → `warnings`（≤5 条，照卷级），**只警告不拦** | 不落库（仅本次响应） |
| `.why` | string | 1–30 | 是 | 非空（卡尾「剧情吸引力」块）；超长 → 丢卡 | 不落库 |
| `.gap` | string | 1–30 | 是 | 非空（卡尾「差在哪」块）；超长 → 丢卡 | 不落库 |
| `ranks` | object，键＝`反转/递增/推进/拉力`（闭集） | 每键 int[卡数] | 是 | 键齐全（不多不少）；每数组长度＝卡数、值 1–3（两卡时 1–2）、形态合法（§4 步骤 5）；非法 → 整批重试 | 不落库（服务端据此外推字母，仅本次抽卡会话） |
| `reasons` | object，键同上 | 每值 ≤20 | 是 | 键齐全；唯一第一名的维：非空、≤20、且为得胜卡**绑定字段**的逐字子串（反转＝plot＋ending｜递增＝obstacle＋plot｜推进＝plot＋ending｜拉力＝ending），寻不到 → 该名次不合法，按 §4 步骤 3 处置；并列的维：≤20（并列原因，随卡展示，不作可寻校验） | 不落库 |
| `checks` | string[0–3] | 各 ≤40 | 否 | 照 `_lines` 先例逐条 ≤40、去空 | 不落库（卡尾自查条） |
| `note` | string | ≤120 | **<3 张卡时必填** | 缺失/空 → 整批重试（喂回短语见 §2）；有 → 截断 120 透传（顶部「只想出两套：〈原因〉」） | 不落库 |

响应包络（成功，不落库；tasks 3.1 ＋ 字母下发）：
`{ok, entry:{text,source}, diff:{axes,one_liner}, directions[2–3], grades[卡数], ranks, reasons, checks, warnings, note}`——`grades` 为服务端按 ranks 算出的 S/A/B 数组（与 directions 序号对齐），只进本次卡面。

## 4. 服务端校验清单（按顺序）

> 顺序依赖说明：③④⑤ 之间存在数据依赖——丢卡后名次须按存活卡重整再查依据。实现按 ①→⑥ 走，任一步触发「整批重试」时把失败点按 §2 喂回并降温，重试计入同一 3 次预算（评审修订：重试共享预算，各缺陷不另开口）。

1. **schema**：`_parse_json` 同款（剥 ```` ```json ```` 围栏、取首 `{` 到末 `}`、json.loads）；非 dict / 无 `directions[]` → 整批失败进重试（「不是合法 JSON」）。schema 外字段忽略。
2. **axes**：`diff.axes` ⊆ 章级闭集、互不相同、条数＝卡数；`directions[i].axis` 与 `diff.axes[i]` 逐字一致。未知轴/不一致 → **丢该卡不改写**；三轴重复或条数不齐 → 整批重试一次。
3. **依据可寻**：对每维取名次第一的卡（唯一时）：`reasons[键]` 非空、≤20、且为该卡绑定字段的逐字子串。寻不到 → 该名次不合法，计入重试原因；**3 次预算耗尽仍有寻不到的维 → 该维第一名作废**（照「并列第一不计第一名」同一条代码路径），字母照算、该依据不展示。
4. **difflib 同质**：序列＝`plot＋ending` 拼接，两两 `SequenceMatcher.ratio() > 0.6`（照卷级 SPINE_SIM_LIMIT 先例）→ 同质 → 整批重试一次（喂回点名第 X/Y 张＋降温 0.3）；复核仍同质 → **丢后出现者**。
5. **名次**：每维数组长度＝存活卡数；合法形态＝排序后自 1 连续到 k（如 1/2/3、1/1/2、1/2/2、1/1/1；非法如 1/1/3、2/2/3）。丢卡后**重整**：存活卡名次按序映射回稠密名次（保序、保并列）。非法且无法重整 → 整批重试。
6. **字母计算**（服务端唯一出口）：每维**仅当第一名唯一时**计该维第一名——并列第一 ⇒ 该维不计第一名（并列原因仍随卡展示）；每卡数第一名个数：≥3 → S、1–2 → A、0 → B。随响应 `grades` 下发，SHALL NOT 落库、不参与跨章统计。性质断言（单测）：至多一张 S（四维第一名总数 ≤4，对并列同样成立）。

收尾：存活 <2 张 → 重试（§2）；3 次尝试耗尽仍 <2 → degraded（§7），SHALL NOT 把半成品预填手写表单；实体差集 → `warnings`；`note` 透传。

- 任何节点清单（节点已退役，SHALL NOT 出现）。

## 6. chapter_selfcheck 模板全文＋输出 schema

只承担「剧情吸引力」组（AI 只读）；衔接／配额两组为服务端本地判定，**不进模型**。门禁走卷级只读体检的同一例外通道（不挂 `require_ai_access`，挂 `require_novel_model`）；手动触发；温度 0.2；计量 operation＝`chapter_selfcheck`（失败 `_fail`）。

system 全文：

```text
你是长篇小说的章节体检员，只给判断，不写剧情、不改稿、不给等级。

【进场（这一章从哪接）】
<<entry>>

【上一章的一行剧情】
<<prev_line>>

【本章五段】
本章剧情：<<plot>>
碰到的挑战：<<obstacle>>
本章结尾：<<ending>>
本章行动：
<<acts>>
阶段：<<stage>>

按「剧情吸引力」四个维度，各给一句 ≤30 字的短评，并点出最弱的一维：
- 反转（只看本章剧情＋本章结尾）：读者的预期有没有被打破？是靠前面埋的东西，还是靠巧合？
- 递增（只看碰到的挑战＋本章剧情）：障碍是不是一层压一层，还是平铺一个坎？
- 推进（只看本章剧情＋本章结尾）：这一章结束时，人／关系／处境是不是真的变了？
- 拉力（只看本章结尾）：结尾停没停在"还没完"的地方？

规则：只评这一章自己，不与其他章比较；短评要点到这一章的具体内容，不写空话；四维短评必须给齐；不给任何等级、字母或分数。

只输出 JSON，不要其他文字：
{"critiques":{"反转":"…≤30字","递增":"…≤30字","推进":"…≤30字","拉力":"…≤30字"},"weakest":"拉力"}
```

user 消息：`请按四维给这一章的短评，并点出最弱一维（只输出 JSON）。`

模型输出 schema 与校验：

| 字段 | 类型 | 校验 |
|---|---|---|
| `critiques` | object，键＝`反转/递增/推进/拉力` | 键**齐全**（四键、无多键）；每值非空、≤30 字 |
| `weakest` | string | ∈ 四维闭集 |

任一不合法 ⇒ 该组呈现 warn「AI 这一眼没看成，可再试」（不自动重试——作者手动再点；若实现选择照卷级体检先例静默重试一次，须在同一计量 operation 下留痕，实现期待定）。**SHALL NOT 给 S/A/B 字母**——单章无相对排名语义。

端点出参（三组，既有体检行样式，不落库、计量 operation 独立）：

```json
{"ok": true, "groups": [
  {"name": "衔接", "status": "ok|warn", "text": "…"},
  {"name": "配额", "status": "ok|warn", "text": "…"},
  {"name": "剧情吸引力", "status": "ok|warn",
   "critiques": {"反转": "…", "递增": "…", "推进": "…", "拉力": "…"},
   "weakest": "拉力"}
]}
```

- 衔接（本地）：本次重新派生的进场 vs 请求携带的卡面当前显示进场，trim 后**逐字比对**；不一致 → warn「上一章结尾已变化」。
- 配额（本地）：已拆章数 vs 章数目标，超出 → warn。
- 剧情吸引力（AI）：模型输出校验通过 → ok ＋四维短评＋最弱一维；失败/不合法 → warn，**本地两组照常返回**（AI 组失败不连累本地组）。

## 7. 失败与降级（与 ai_plan 既有 degraded 口径对齐）

**运行参数**：模型 `haiku` 符号别名（落到本书模型，同 D12 卷级口径）；`max_tokens 4096`（判定类先例：2048 偶发无文本输出）；方向卡温度 0.7 → 重试 0.3；自检温度 0.2。

**尝试预算（最多 3 次生成→校验回合）**：
- 第 1 次：temp 0.7；第 2–3 次：temp 0.3＋system 追加（上一次〈原因〉。）。
- 计入预算的重试触发：不是合法 JSON／<2 张合法卡／三轴重复或条数不齐／同质复核／依据寻不到／名次形态非法／两套未写 note。
- **不计入**（丢卡类，剩余 ≥2 照常返回、无重试）：单卡字段缺失/超长、stage 越界、axis 未知或与 diff 不一致、末章结尾越界、同质复核后仍同质丢后出现者。
- 空文本补射（transport 层，照 `ai_plan._generate` 既有行为：assistant「（上一条没有输出正文）」→ user「请输出正文。」，温度 min(t, 0.2)）不占 3 次校验预算——实现期待定：若希望更保守可改为计入。

**降级返回**（3 次耗尽仍 <2 张；字段与卷级三端点逐字同形）：

```json
{"ok": true, "degraded": true, "text": "<原始输出，_degrade_text 同款截 2000>", "hint": "AI 的输出没法结构化——可重试"}
```

前端映射为「出卡失败」态，三出口全给（重试／自己写这一章／先不拆回卷页）；**SHALL NOT 把半成品预填进手写表单**。

**门禁与计量**：
- 方向卡：`require_ai_access`（PRO）→ `require_novel_model`（未配模型 503，前端引导「还没接模型——先去模型配置里接一个」，SHALL NOT 500）。
- 自检：只读例外通道（不挂 `require_ai_access`）＋ `require_novel_model`；免费档未配模型给同款引导。
- 每次尝试（含失败）`record_usage`：`chapter_directions`／`chapter_directions_retry`／`chapter_directions_fail`／`chapter_selfcheck`／`chapter_selfcheck_fail`。
- 全链不落库、不记事件（D18）；评分与理由仅本次抽卡会话内有效。

**实现期待定（自评：最可能需要微调的三处）**
1. 末章结尾的机器判定阈值：difflib(卡 ending, 卷纲预期结局) ≥ 0.5 是工作值——模型合理润色会压低相似度，实现期用真实样本在 0.4–0.6 间校准，或退为「关键词命中」判定。
2. 名次「不跳档」的合法形态集：spec「可并列但不得跳档如 1/1/2」存在读法歧义（1/1/2 是合法并列还是跳档反例）。本附录按稠密名次实现（1/1/2 合法、1/1/3 非法），实现前须与服务端对拍口径一次。
3. 「超长即丢卡」的执行松紧：spec 将超长列入单卡丢弃；模型超长并不罕见，若实测丢卡率过高，可与产品确认对 title/obstacle 等次要字段放宽为截断（plot/ending/依据仍严格）。
