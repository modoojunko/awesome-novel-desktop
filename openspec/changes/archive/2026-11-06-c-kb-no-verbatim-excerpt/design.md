# 设计：拆书收录不产原文示范段条目＋收录即建实例

## 上下文

- 2026-11-04 真机反馈（222 条拆书条目验收）：文风「示范段」条目的知识定义/实例/正例全是逐字小说原文，同屏重复三遍；逐字原文入库踩版权红线。
- v2 知识模型（c-kb-knowledge-v2，已合 main）把「知识定义」与「实例」分离：定义=提炼写法（允许空、显示「知识定义待补」），实例=案例（文本＋出处＋原文摘句）。
- 内容仓批量工具已同口径（原文示范段不收）。

## 目标

- 拆书收录映射跳过 `style.examples`（逐字原文），计数进 warnings；手法/文笔（提炼写法）照常收录。
- 收录落库时同步生成第 1 条实例（文本=指令、来源=拆书＋书名、quote=证据/例），不再依赖启动迁移补建。

## 非目标

- 不改写法块/写作提示词的文风示范注入（那条链路走书内设定 style_samples 键，不经知识库）。
- 不做跨书同技法聚合（同名技法并成一条知识多实例）——属「按题材总结」后续项。
- 不改基线层（kb_baseline_entries）结构。

## 决策

1. **示范段剔除放映射层**（`map_deconstruct_products`），不是闸门层——闸门的示范段规则（≤500 字）保留给手录等其他来源；拆书路径直接不产出，warnings 计数可被任务详情/收录回执看到。
2. **收录即建实例**放 `collect_task_to_kb` 落库循环内（db.add 同事务），不调用 `service.add_instance`（其内部 commit 会打破收录的单事务原子性）。启动迁移 `populate_kb_instances_v1` 对已有实例的知识跳过，两侧幂等。
3. **v0.45.1 二进制兼容**：新增列/表为 additive DDL，0.45.1 二进制的模型不含 v2 列 → SELECT 按已知列映射，额外列忽略——旧二进制照常读写该库。

## 风险

- 已有的其他来源 sample 条目（手录）不受影响——删除只针对 `src_kind='deconstruct' AND payload LIKE '%slot: sample%'`。
- CI runner 上 Test 步挂死（零输出 6h×2）为环境问题，与本 change 无关（本地全量 8m10s 全绿）；归并行会话 v2 套件排查。
