## Why

规格明确要求"用户确认退款时 SHALL 立即冻结对应权益（停止使用）"，但实现从未把权益台账行置为 frozen——整个退款流程（冷静期＋微信退回中）套餐一直可用且显示"生效中"（2026-09-05 线上单 S20260905-4B79DE6C7B86F39B 实证）。领域层 `License.merge` 早已预留并跳过 frozen 状态，属于接线缺失而非新机制。用户拍板：退款流程一启动就必须冻结对应套餐。

## What Changes

- 确认退款（进冷静期成功后）：该单已激活可用码行 active → frozen，可用性立即暂停；grant_start/expires_at 原样保留，排队位不变
- 冷静期取消：frozen → active 解冻，精确还原原展示与权益
- 退款到账：相位判定认 frozen 起点——排队中/未激活 → revoked 收回；已起算 → frozen 恢复 active（剩余权益继续有效）
- R1 扫描新增两路自愈：退款中订单补冻结（冻结写半截）/ 已取消订单补解冻（解冻写半截），幂等可重入
- R3 扫描 D/E 与 pg_http CAS 收回条件同步覆盖 frozen 行
- 我的套餐：冻结行保留在明细中并显示"退款处理中·已冻结"标识，不再计入生效档位/到期（License.merge 既有逻辑自动排除，零改动）
- spec 措辞对齐：「退款进行中码不动」明确为"不提前收回、不提前相位判定"，与"立即冻结"不再字面冲突

## Capabilities

### Modified Capabilities

- s-payments：冷静期冻结语义落地（冻结/解冻/到账两相位的 frozen 覆盖 + 半截态自愈）
- s-pay-account-views：我的套餐退款冻结行过渡展示

### New Capabilities

- 无

## Design Impact

- 受影响端：**S端**（后端 server + S端 账户页「我的套餐」tab）；C端不受影响（C端按 license API 消费 tier/到期，冻结后 API 自然不再计入，无需改码）
- 受影响屏/弹层清单：我的套餐 tab 明细行（新增冻结标识）；订单详情时间线不变；退款页不变
- 对象状态：codes 行启用词汇表中既有值 frozen（待激活/排队中/消耗中/退款冻结/已回收——本次接线"退款冻结"）；orders 状态机不变
- 是否触碰两端共享段：否（S端 徽标复用既有 pill/info 词汇，无新胶囊形态、无裸色值）
- 是否需要原型先行：不需要（纯 S端 且不触共享段，按 tasks 规则以「双端影响判定」任务替代）
- 设计工件由谁产出：实现侧自查
