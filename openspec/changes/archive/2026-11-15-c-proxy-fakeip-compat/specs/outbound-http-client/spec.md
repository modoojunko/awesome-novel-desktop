## ADDED Requirements

### Requirement: fake-ip 代理环境的出站校验放行

C 端后端对 CDN/更新链路的出站校验（https＋可信域＋DNS 解析结果公网闸）SHALL 在 TUN 型
代理的 fake-ip DNS 环境下放行可信域出站：当目标为烘焙可信域且 https，且 DNS 解析结果
**全部**落在 fake-ip 保留段（198.18.0.0/15）时，校验 SHALL 判放行并照常发起连接（连接
路径由代理按域名转发）。解析结果混杂（fake-ip 段地址混任一真实非公网地址）或含其他非
公网地址时 SHALL 照旧拒绝；非可信域与 http 目标 SHALL 照旧拒绝。该策略 SHALL 由四条
出站链路（更新检测、提示词包、知识基线、知识树）共享同一实现，行为一致；校验判定结果
（公网／fake-ip／拒绝）SHALL 可被调用方取得，用于失败原因细分与诊断留痕。kb 两链既有的
开发态环回逃生口（宿主为 127.0.0.1/localhost 时跳过公网闸）语义保持不变。

#### Scenario: TUN fake-ip 下四条链路可用

- **WHEN** 用户开启 TUN 模式代理（fake-ip DNS），可信域域名解析全部返回 198.18.x.x
- **THEN** 更新检测、提示词包、知识基线、知识树的出站校验放行并正常完成获取，不再判网络不可达

#### Scenario: 混合解析仍拒绝

- **WHEN** 解析结果同时包含 fake-ip 段地址与任一真实非公网地址（内网/环回等）
- **THEN** 出站校验拒绝该目标，行为与改动前一致

#### Scenario: 干净环境行为不变

- **WHEN** 无代理机器上可信域解析为真实公网 IP
- **THEN** 校验放行且判定为「公网」，行为与改动前一致
