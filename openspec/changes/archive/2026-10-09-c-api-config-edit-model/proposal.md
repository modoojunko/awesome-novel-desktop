## Why

用户实绩（2026-10-09 截图）：中转站配置「测试连接」报「模型回复格式不正确或回复为空……所试模型 aion-3.0，请核对模型 id 与接口格式」——点开「编辑」想换一个模型重测，编辑弹窗里没有任何模型选择位。

根因＝`ApiConfigForm` 把「模型名称」整块 `!isEdit` 隐藏（模型值恒空、保存时丢弃 model）；但连接测试必须用模型做真实生成探针（2026-10-05 拍板「仅凭可达性不算通」），已存配置恒用模型列表首项（`_first_model`）——探针模型失败后用户无处改选，只能删配置重建。

## What Changes

- **编辑弹窗渲染模型选择位**（与新建同款组合框）：初值＝已存模型列表首项（＝该配置已选模型/探针优先模型），清单种子＝已存模型列表，弹层立即可改选或手填；已存初值视同手改，不被拉取/测试的「清单首项」默认选中覆盖；「已存 N 个模型」（种子）与「已拉到 N 个模型」（拉取）文案分源。
- **编辑态放开清单拉取**：「获取模型」按钮／Key・Base 失焦自动拉取同新建口径（raw 轻探针需要明文 Key——未重填时按钮禁用＋title 提示；Ollama 免 Key）；接口格式切换作废清单时不施加供应商预填（编辑沿用已存值，规格既有明文）。
- **测试连接用所选模型**：已存配置测试端点 `POST /api-configs/{id}/test` 增可选请求体 `{model}` 作探针优先模型覆盖（编辑态未重敲 Key、用已存密钥测试时把表单改选模型传进去）；空/缺省回落已存首项，落库保头逻辑不变；重敲 Key 的路径照旧走 raw 端点（原已透传表单模型）。
- **保存置首**：编辑保存把改选值置模型列表首项随 PUT（保留其余已存项按原序，截 100 对齐后端手动路径上限）；留空省略模型列表字段（沿用已存值，与「留空则保留当前密钥」同语义）。

## Impact

- **Specs**：`model-api-config` MODIFIED「供应商默认值预填」（模型字段口径创建表单→创建/编辑表单＋编辑种子/置首语义）、「按接口格式探测连接」（探针模型取用顺序头部增调用方显式覆盖）、「模型清单自动拉取」（编辑表单同口径拉取＋获取模型按钮门）。
- **Code**：`client/frontend/src/components/api-config/ApiConfigForm.tsx`、`pages/ApiKeyConfigPage.tsx`、`hooks/useApiConfigs.ts`；`client/backend/api_configs/{router,schemas,service}.py`。
- **Tests**：`tests/test_api_key_config.py`（test 端点 override＋空串回落）；前端 `apiConfigForm.test.tsx`／`apiKeyConfigPage.test.tsx` 编辑态模型用例×8（种子/改选提交/测试带模型/按钮门/清单文案/重置再种子/清空省略字段/清空后测试两路径）。
