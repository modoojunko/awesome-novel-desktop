## 设计决策

### 编辑态模型选择的语义锚点＝「models 首项＝已选模型」

配置的「已选模型」没有独立列，就是模型列表首项（探针优先模型 `_first_model`＝`models[0]`，落库保头逻辑维持「首项＝用户登记/手选值」）。因此编辑态的选择器初值、测试覆盖、保存落点三点全部锚在首项语义上：打开显示首项、测试探首项（可覆盖）、保存改写首项——不引入新字段、不改表结构。

### 三处状态与三个坑（实现/评审固化）

1. **种子值视同手选**：`modelPickedRef` 在编辑种子非空时置 true——否则重填 Key 拉回清单后，「默认选中清单首项」（2026-10-07 拍板）会静默顶掉用户的已存已选模型。
2. **清单来源分源**：种子清单（已存）与拉取清单用 `listFresh` state 区分文案（「已存 N 个模型」≠「已拉到 N 个模型」），诚实呈现列表新鲜度。
3. **保存省略字段**：模型留空＝沿用已存值，PUT **不带** `models` 字段——与「留空则保留当前密钥」同语义（对照 2026-09-18 覆盖率专项：空串当更新值会清掉已存数据）；带值时 `[picked, ...其余已存项].slice(0, 100)`，对齐后端手动路径 >100 即 422 的上限。

### 已知边界（未改的既有行为）

- `api_format` 变更保存时后端无条件清空模型列表（规格「改格式后模型缓存失效」）——即便同请求带了 models 也被清；改格式＋改模型一次保存会丢改选值，须重测后重选。属既有规格行为，本 change 不翻转。
- 编辑态「获取模型」依赖明文 Key：Key 未重填时按钮禁用（raw 轻探针无「用已存密钥拉清单」的端点；`refresh-models` 端点现为 stub，如后续要做已存密钥刷新清单再立项）。
