## 设计决策

### 「带回全了没有」的唯一正确锚＝源行在目标在场

`book_count_migrated`（本次 INSERT 数）在 OR IGNORE 幂等语义下只对**首次搬运**有意义；重带/中断续带时它恒 0。因此完整判定与「已迁移 N 本」展示全部锚到**在场数**（`book_count_present`＝源书 id 在目标库的行数；逐表 `rows_missing`＝源行数−主键行值 IN 在场数）。老报告／history 条目缺 present/表级核对数据时退回旧口径并保守判不完整——存量用户升级后点一次「重新迁移」即生成新口径报告自愈，不需要数据迁移。

### FK 违规的两义性与降级证据链

FK 违规既可能是「内容没带过来」（父表行被吞），也可能是「旧库自带的孤儿行」（一行没丢，带着旧伤过来）。区分靠存在性核对：**每张已搬表都证明零行损（rows_missing==0 全成立）**时，违规只可能源自后者 → 判完整＋notes 实名留痕；任一表缺证（无主键/源缺主键列 → None；history 适配形态无表级数据）→ 保守判不完整，cleanup 白名单口径不放松。曾踩坑：`project_settings` 复合主键若不核可（初版只认单列主键）会让降级永不生效——复合主键用行值 IN 覆盖后全表可证。

### 真丢行的可见化：COALESCE 防线＋行损失兜底

- 旧世代源表缺 NOT NULL 约束时的 NULL 存量，直插必被 OR IGNORE 静默吞整行（比 `total_archives` 事故的「缺列」更隐蔽的「有列有 NULL」形态）→ 交集列按目标 NOT NULL 包 `COALESCE(列, 中性字面量)`，与缺失列回填同一哲学。
- 「重插也进不去」的行（目标 CHECK 拒收，如关联表恰一非空校验）防线管不了 → 通用行损失条款兜底：任一表 `rows_missing>0` 即判不完整，实名上报，不再静默。

### 话术翻案：「迁移」口径取代「带回」口径

2026-10-08 spec 曾明令用户可见文案 SHALL「带回」且 SHALL NOT 出现「迁移」；2026-10-09 用户拍板翻案（用户是作家，话术专业化；微信「聊天记录迁移」同级的消费软件口径）。动词统一「迁移」；「迁入」保留为内部/日志用语不上界面。作品与模型配置**并列表达**：标题、成功卡、toast 都不再只提书；成功卡「· M 条模型配置」取候选清单 `configs_total`（LegacyMigrateModal 预览步同源补行，端点本就返回 manifest）。

### 已知边界（未改的既有行为）

- 结果卡「已迁移 N 本书 · M 条模型配置」的 M 取自**候选清单**（迁移前快照）；引擎 report 本身不带配置条数，多候选入口（更早候选手动路径）清单缺失时降级为只报书数。
- 原型 `upgrade-carry.html` / `list.html` 文案未随本批同步（design:check 矩阵不含迁移屏，无 parity 红），另批处理。
- e2e `db-version-upgrade.spec.ts` 只更新了文案钉死断言；隔离栈全链演练随下个发版冒烟带走。
