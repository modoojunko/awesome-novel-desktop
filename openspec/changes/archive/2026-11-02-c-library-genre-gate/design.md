# Design: c-library-genre-gate

## 归一兜底为何加在组件层而非别名表

- 别名表要穷举模型自由文本，且每加一个新别名都要改目录；COMPONENT 匹配（目录名「/」拆分）用现有目录结构自带语义单元（志怪、民俗灵异、修真…），一次覆盖同义词序与子类变体。
- 顺序保证存量语义零扰动：精确 → 整名双向包含 → 组件最长命中。「都市修仙」仍先命中「都市」（既有行为），只有全部失配才进组件层。
- 归一是全链单源：收录、回填、门禁、前端 genre_norm 全走同一个 normalize_theme。

## 回填为何走读面触达

照 c-kb-library-once-migration 拍板口径：一次性老数据修正不挂 boot；读面触达＋幂等自熄（全部补完探测即返 O(1)）。补题源与收录同源（拆书 _deconstruct_genre、书 _story_genre），补写 genre＋concept_id；不动 legacy deprecated 表（读面只认 kb_entries）。

## 门禁语义（boss 拍板：硬拦）

| 卡题材 | 书题材 | 结果 |
|---|---|---|
| 空（跨题材通用/手建未设） | 任意 | 放行（通用语义） |
| 任意 | 空（书题材未设） | 放行（书侧无约束） |
| 非空 | 非空且不同域 | **拒**（400 genre_mismatch；列表不列出） |
| 非空 | 同域（归一后相等） | 放行 |

- 后端 `apply_to_book` 硬校验（权威）：同一端点同时服务「用到新书」与「书内从库导入」，一处门禁覆盖两入口。
- 前端按 `genre_norm` 过滤列表（体验层）：库卡 `_card_view` 与 `/novels` 富化各加 `genre_norm`（取与收录同源的 story.genre 归一值），前端只做相等比较，不做归一（归一权威在服务端）。
- 空态文案明示题材与「跨题材不能落卡」，避免「为什么列表是空的」困惑。
