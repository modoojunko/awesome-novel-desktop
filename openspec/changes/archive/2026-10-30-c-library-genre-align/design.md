# c-library-genre-align — 设计

## Context

开书题材面板第 01 格是封闭目录：`genres/theme_catalog.py` 的 `THEMES`（21 个大类，中文名即存储值，子类可选），前端镜像 `lib/themeCatalog.ts`（parity 对拍）；书里存 `story.yaml` 的 `genre`（大类名）＋`sub_genre`（子类名）。角色库题材此前是自由文本，与开书分类不对齐。

## Goals / Non-Goals

**Goals**：库卡题材取值域、校验、收录归一与开书第 01 格完全一致；老自由文本可平滑归一；错误可读。

**Non-Goals**：库内自建题材大类；库卡落子类（sub_genre）；批量重写存量数据（读取侧归一即可）。

## Decisions

**D1 目录即白名单（中文名存储）**：直接复用 `THEMES` 名集合，不另造库侧枚举。理由：开书已把「中文名＝稳定键」定为封闭目录契约（未知 400），库侧再定义一套必然漂移。

**D2 `normalize_theme()` 单源归一**：精确命中→本身；包含匹配（双向）→目录大类；否则空串。用在三处：库卡写入口（非空且归零→400，提示去目录选）、书内收录（`story.yaml genre`）、拆书收录（产物 genre 文本）。历史自由文本（「古装玄幻」）自然归一到目录大类。

**D3 前端选择器复用同一镜像**：`CardEditorModal` 题材格改为 `<select>`（「未分题材」＋`THEMES`），与题材面板同一份 `lib/themeCatalog.ts`；不提供自由输入，从入口保证值与目录一致。

**D4 空值＝未分题材**：允许空并单列「未分题材」分栏；不强制每张卡有题材（库内手建卡可能先收后分）。

## Risks / Trade-offs

- [历史自由文本归零] → 仅在读取路径归一（收录时），不动存量行；拆书产物若全是目录外词，会落「未分题材」，由作家在库里补选——比静默保留错位词更一致。
- [子类不落库] → v1 够用；后续要按子类分栏再加列并扩契约。

## Migration Plan

无 schema 变更；无数据迁移。回滚＝恢复输入框与旧校验（已写入的目录内值仍是合法自由文本）。
