# Change: c-renwei-check

## Why

用户故事地图已拍板（2026-10-17）：作家的修稿循环是「**验（朱雀基线）→ 查（人味检测，定位）→ 改（人工边注）→ 再验……直到作家觉得可以**」。当前产品在这条线上有两个缺口：

1. **查这一层缺失**：朱雀只回答「占比多少」，不回答「哪几处不像人、怎么改」；作家只能通读找感觉。
2. **去AI味改写与循环冲突**：修稿向导的①步检查（五六项规则）与人味检测重复；其 AI 逐段代笔已拍板退役（2026-10-17，代价清单见设计说明 §3.3）——作家要的是「告诉我怎么改、我自己改」，不是「AI 替我改」。

本 change 新增**人味检测**（纯本地确定性体检：19 项指纹对照 320 章真人基线，零模型调用、零额度、正文不上传、毫秒级），并以它为唯一检测引擎，**退役去AI味改写链**。算法与交互已经原型验证：用户故事地图、四拍报告弹窗（说明→运行→结果→标记到正文）、左右分边注改稿闭环（逐段重扫消卡）均经用户拍板，原型见 `docs/design-c/drafts/ai-novel-c端-人味检测-原型.html` 与《ai-novel-c端-人味检测-设计说明.md》。

## What Changes

### 新增：人味检测（查 → 改）

- **本地检测引擎**：19 项指纹（标点 6／句段 6／词汇 5／内容 2）＋人味率（0-100%，对照 320 章真人基线的加权 z 映射）＋定位 findings（正则类精确定位到词、窗口类定位到段、整章密度类只进对照表）＋修稿优先级（权重×偏离 top3，附纠正改法）。引擎为纯函数，判据与词表从资产包 `_人味指纹.py` 全量移植（演示词表只用于原型），基线常量（均值±SD＋P25–P75）入库为冻结常量表。
- **检测端点**：`POST /api/novels/{id}/chapters/{ref}/renwei-check`——登录即可（无档位门、无 Key 门、无配置态），同步返回；SHALL NOT 调用模型、SHALL NOT 记模型账、正文不出本机。≥1,500 字才出人味率（短章「打不了分」语义）；MTLD/Hapax <2,000 字出「样本不足」。
- **四拍报告弹窗**：说明页（流程图讲清 验→查→改→再验 循环，作家点「了解了，开始检测」）→ 运行态 → 结果页（人味率头卡＋先改这几处（仅 <70% 时）＋定位问题清单＋整章对照表）→「标记到正文」（作家点击才回正文上边注）。文案基调面向作家（§design：不说指纹/基线/权重，说「真人常见范围」「分量 高/中/低」）。
- **正文左右分边注**：问题段标色；左边距留给朱雀批注（既有标注左移），右边距人味简述与段落对齐，悬停展开「为什么＋怎么改＋标为已改/跳过」。标注画在覆盖层，正文宽度与位置锁死不被挤跑；边注宽度自适应剩余空白、放不下换行。
- **逐段重扫消卡**：改带标注的段 → 约 0.7s 重扫该段，通过即精准消卡（其余保留）；跳过＝作家一票不再提示；改无标注段 → 全部失效提示重测。章头「人味改稿 n/10」徽章实时走；清零转绿并引导「点朱雀重检再验一轮」。
- **右栏入口**：正文页签检测区，朱雀检测行之下新增「人味检测」行（本地 · 免费，无门控无配置态）。

### 退役：去AI味改写链

- **前端**：修稿向导四步弹窗（PolishWizard 及其链路）、右栏「去AI味」动作卡（`ai-polish`）、相关测试与 e2e。
- **后端**：`/write/polish` 选区去AI味端点、`quick_verdict` 快扫、`/ai-flavor-scan` 向导检查端点（其规则由人味检测引擎收编）。
- **prompts 仓（跨仓）**：`polish_text.prompt`（v5）退役下架，sync/manifest 同批。
- **保留不动**：选中改写的润色（扩写/压缩已先期退役）、生成侧反AI结构红线＋人味写法（生成时预防层）、朱雀检测（循环终点）、章节体检（语义层，报告尾引导语衔接）。

## Capabilities

### New Capabilities

- `renwei-check`: 本地人味检测——检测引擎与端点、四拍报告弹窗、正文左右分边注与逐段重扫消卡、章头进度徽章、右栏入口行；文案面向作家（禁止实现词汇上屏）。

### Modified Capabilities

- `polish-wizard`: 整体退役——唯一需求「去 AI 味修稿向导（四步弹窗）」移除。
- `prose-writing`: 需求「选区变换（去AI味）」移除（`/write/polish` 端点与去AI味口径、`ai-polish` 按钮行随之退役）；润色路径与生成侧反AI红线需求不变。
- `tier-gating`: 需求「Feature capability registry」——`ai-polish` 功能键随功能退役从注册表移除。
- `tier-access`: 需求「端点门禁对拍守卫」——关键档位 key 枚举移除 `ai-polish`。
- `workbench`: 需求「右栏「AI 辅助」面板」——正文页签动作清单移除去AI味卡、新增人味检测行；需求「正文页签查看/编辑两态」——显式动作枚举更新。

## Impact

- **端**：C端前端（工作台正文页签、右栏、报告弹窗、正文标注层、编辑器）＋C端后端（renwei-check 引擎与端点、polish/ai-flavor-scan 下线）＋prompts 私有仓（polish_text 退役，独立 PR）。
- **Design Impact**：
  - 受影响屏/弹层：工作台正文页签（右栏检测区、正文标注覆盖层、章头徽章）、人味检测报告弹窗（说明/运行/结果三态）、修稿向导弹窗（退役）。
  - 对象状态（对照 §5 状态语言总表）：报告相位（说明/运行/结果）、检测总档（未检/已标/改稿中/全绿/已失效）、单项判定（✓ 达标 / ⚠ 超界 / · 参考或样本不足）；语气词沿用 info/ok/warn/err——人味率档位胶囊 很像人=ok、边缘/偏机器=warn、机器味重=err，未引入第四种语气。
  - 共享段：不触碰 base.css 令牌与两端共享组件段（新增样式均为 renwei 前缀局部类，边注覆盖层不进共享段）；若实现期确需动共享段，须双端同批（预期不需要）。
  - 原型先行：✅ 已完成并经用户拍板——`docs/design-c/drafts/ai-novel-c端-人味检测-原型.html`（真机抓取底座 v3）＋《ai-novel-c端-人味检测-设计说明.md》（用户故事地图＋8 项拍板记录）。设计工件由设计侧产出，实现侧自查。
- **挂账处置**：未归档 change `c-polish-v5-diagnostic-gate`（改写 polish 口径）与 `c-deai-wizard-keep-advance`（向导收口）随本退役撤销——两个目录删除，处置记录写入本 change 的 design.md；v5 的诊断知识由人味检测报告与生成侧红线承接，不丢失。
- **其他**：`e2e-assertion-polish` 无 polish 断言（历史命名），不在 delta 内；`prompt-crafting`/`chapter-data` 等仅历史提法，不动。算法参考实现已存在：`docs/design-c/drafts/check-renwei-demo.py`（19 项指标＋人味率＋优先级的完整纯 Python 实现，原型数字全部由它实算）。
