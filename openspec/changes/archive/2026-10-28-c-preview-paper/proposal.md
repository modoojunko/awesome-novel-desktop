## Why

`c-prose-paper`（2026-10-22）把写作正文页上了「纸」：桌面（中性灰）→ 白纸（纸边投影＋纸边距）→ 680 版心。但立项时明确把预览划出了范围（提案原文「不涉及书架、设定、预览、模型配置及其弹层」），于是现在两页直接对比出现视觉断层：写作页是白纸浮在灰桌面上，预览阅读区的「白纸」主题却没有自己的纸面——底色直接回落应用底色 `--bg`（oklch 98% 浅灰），正文 66ch 直接铺在灰底上，看起来「一片灰」，还停留在上纸之前的旧观感。用户已实际反馈这处不一致。

预览阅读器本就有独立的三档主题（白纸/护眼/夜间），本次只把默认「白纸」档对齐正文纸面（同一套纸面令牌：桌面＋白纸＋纸边投影），护眼/夜间两档保持整面填色不动。

## What Changes

- **预览阅读区默认主题上纸**：默认「白纸」主题下，阅读区分两层——桌面（阅读列底色，与写作页同源中性灰）→ 纸（白面＋纸边投影＋纸边距）；章元信息（卷标签/章标题/状态行）与正文都落在纸上。
- **纸面几何与写作页同源**：纸宽、纸边距、桌面缝沿用 `c-prose-paper` 的同一套令牌与退化顺序（宽屏 64px 纸边距 → 先挤纸边距到 20px 下限 → 再让内容列让路；纸两侧恒留最小桌面缝），两页纸宽观感一致。
- **护眼/夜间主题保持整面填色**：两档主题继续平铺满阅读区（现状行为），不上纸、无桌面缝；纸面样式只挂默认主题。
- **纸面令牌单源化**：`c-prose-paper` 挂在 `.col-editor` 作用域的纸面令牌扩大作用域到预览视图（同一处声明、两处消费），不在预览侧复制第二份值。
- **不动**：阅读配置四轴（字号/字体/行距/主题）的档位、默认值与分书记忆；滚动容器仍是 `.pv-prose-wrap`；目录/右栏/概览卡等界面骨架；正文数据与接口。
- **不引入**：纸色偏好、写字范围虚线框（预览纯只读，无编辑态）、真分页、纸张纹理、人味边注测量那套编辑态逻辑。

## Capabilities

### New Capabilities

（无——预览阅读器的结构与阅读配置契约不变，改的是阅读区的呈现。）

### Modified Capabilities

- `preview-reader`：阅读区呈现契约变更——新增「预览阅读区纸面呈现（白纸主题桌面／纸两层）」；「阅读配置」要求中主题一节的口径从「主题作用于正文底色与文字色」细化为「白纸＝桌面＋纸面呈现、护眼/夜间＝整面填色」。

## Impact

- 前端：`client/frontend/src/components/novel/workbench/PreviewView.tsx`（阅读区加纸面包裹层，章头与正文进纸）、`client/frontend/src/design/book.css`（纸面令牌作用域扩大到 `.preview-v`；`.pv-prose-wrap` 换桌面底；新增 `.pv-paper` 白面规则与护眼/夜间两档回退）。
- 设计资产：`docs/design-c/prototypes/preview.html` 同批改（否则 `design:check` 的预览 parity 必红）＋ `prototypes/ADJUSTMENTS.md` 登记本轮偏差。
- 测试：`previewReader.test.tsx` 复跑（阅读配置与目录行为不变）；design-parity 预览基线随原型更新。
- 不改后端、不改数据库、不改接口、不改提示词。
- 无 **BREAKING** 的数据/接口变更；界面观感变化见下方 Design Impact。

## Design Impact

- **受影响端**：C端（桌面客户端与 Web 预览同源）。
- **受影响的屏/弹层**：书工作台 → 预览页签 → 阅读区（中栏）；仅默认「白纸」主题的呈现变化，护眼/夜间两档与左栏目录、右栏配置/概览骨架不变。**不涉及**书架、设定、写作正文页签（已上纸）、模型配置及其弹层。
- **新增对象状态**：无新业务状态。呈现层只有主题档位（白纸/护眼/夜间）既有三态，白纸档的呈现从「整面浅灰」变为「桌面＋纸面」。对照状态语言总表，本 change 不新增提示语气词、不新增胶囊/徽标形态。
- **是否触碰两端共享段**：否。改动全部落在 `book.css`（C端业务层）的预览阅读区与 `.col-editor` 纸面令牌作用域，不碰 `base.css` 共享令牌段、不碰 S端。
- **是否需要原型先行**：需要。`prototypes/preview.html` 的阅读区 CSS 与实现同构，须同批改为纸面形态并在 `ADJUSTMENTS.md` 登记（实现 PR 内完成）。
- **设计工件产出方**：实现侧按本 change 落地；原型同步与 ADJUSTMENTS 登记由实现 PR 同批完成（design-system 既有要求）。
