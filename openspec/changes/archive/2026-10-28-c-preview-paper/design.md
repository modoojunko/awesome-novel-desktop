## Context

预览阅读区中栏的现状（`book.css` 与 `prototypes/preview.html` 同构）：`.pv-read` 底 `--bg`；`.pv-prose-wrap` 是滚动容器（`overflow-y:auto`，`padding: 36px 48px 96px`），底色 `var(--pv-bg, var(--bg))`——`--pv-bg` 只在护眼/夜间两档主题类上定义，默认「白纸」档没有任何主题类，于是回落到应用底色 `--bg`（oklch 98% 浅灰）；正文 `.pv-prose` `max-width: 66ch` 居中，直接铺在灰底上。写作正文页在 `c-prose-paper` 已是「桌面（94.2% 灰）→ 白纸（纯白＋纸边投影）」，两页对比预览显得一片灰。

三个约束决定实现形态：

1. **纸面令牌已存在且已拍板**：`c-prose-paper` 的令牌（桌面／纸面／纸边／纸投影／纸边距／版心／桌面缝）挂在 `book.css` 的 `.col-editor` 作用域。预览要的是同一张纸的观感，不是第二套纸。
2. **滚动容器不能搬**：`.pv-prose-wrap` 是预览阅读的滚动容器，章级导航（上一章/下一章）依赖它；翻章/切章行为与滚动口径不能动。
3. **主题三档是既有契约**：白纸/护眼/夜间按书持久化、即时生效；护眼/夜间的整面填色是已验收行为，不能被纸面样式波及。

## Goals / Non-Goals

**Goals:**

- 默认「白纸」主题下阅读区呈现「桌面 → 纸」两层，与写作页同一观感语言（同桌面色、同白纸、同纸边投影）。
- 纸面令牌单源：一处声明、写作页与预览两处消费，杜绝第二份同值漂移。
- 护眼/夜间两档行为零变化（整面填色）。
- 滚动容器、章级导航、阅读配置行为全部不动。

**Non-Goals:**

- 不做写字范围虚线框（预览纯只读，无编辑态）、不做人味边注测量。
- 不做纸色偏好、真分页、纸张纹理。
- 不改阅读配置四轴的档位、默认值、持久化与作用域。
- 不动目录列、右栏配置/概览卡的界面骨架。

## Decisions

### D1：纸面令牌单源——扩大 `.col-editor` 令牌块的选择器作用域

`book.css` 里 `c-prose-paper` 的令牌声明块从 `.col-editor { … }` 改为 `.col-editor, .preview-v { … }`，预览视图直接消费同一组值。

- **为什么**：预览需要的正是「与写作页同一张纸」。复制一份值到 `.preview-v` 必然漂移——`c-prose-paper` 自己就有「两条同文本 `clamp` 必须同改」的教训，再造第二份同值令牌是把坑挖深。
- **否掉的替代**：把令牌上提到 `:root`——作用域失控，任何新界面都可能顺手消费纸面令牌，纸的语义从「正文列/阅读区专属」扩散成全局皮肤；`book.css` 是 C端业务层，双选择器作用域足够。
- **共享段判定**：`book.css` 不属两端共享段（`base.css` 才是），本决策无跨端影响。

### D2：纸是一层流内包裹 `.pv-paper`，滚动仍在 `.pv-prose-wrap`

`PreviewView.tsx` 在 `.pv-prose-wrap` 内新增 `<div className="pv-paper">`，把 `.pv-chapter`（卷标签/章标题/状态行）与 `.pv-prose` 一起包进去；`.pv-prose-wrap` 换桌面底（`var(--paper-desk)`）并去掉自身 padding（纸自带 `margin` 与纸边距，几何复用写作页同一套 clamp 双变量与 `min` 宽公式）。

- **为什么**：与写作页同构（`.editor-wrap` 桌面／`.prose-paper` 纸），两页的层级语义、类名故事、注释口径一致；滚动容器不动 ⇒ 章级导航与滚动行为零改动。
- **否掉的替代**：不新增节点、直接把纸样式压在 `.pv-prose-wrap` 上——桌面与纸必须同屏分层（桌面要在纸两侧可见），一个节点当不了一层纸；伪元素承不了内容。
- **空态与加载态**：`loading` 或空章时章头与「本章还没有正文」提示照旧渲染在纸内，纸面不因内容为空而消失（与写作页 `c-paper-empty-fill` 的「纸至少撑满可视桌面」语义对齐：`.pv-paper` 同样给 `flex: 1 0 auto`，短章/空章纸也撑满桌面）。

### D3：护眼/夜间用显式回退，不用 `:not()` 长链

纸面样式（桌面底、`.pv-paper` 白面/投影/纸边距）挂默认规则；`.pv-theme-sepia`、`.pv-theme-night` 两条回退规则把 `.pv-prose-wrap` 恢复整面填色与原 padding、`.pv-paper` 退化为透传（无底、无影、无纸边距）。

- **为什么**：实现侧 `rootCls` 本来就只在非白纸档挂主题类，两条回退即可穷尽；`:not(.pv-theme-sepia):not(.pv-theme-night)` 长链在原型侧还要同步同构，可读性差且 `design:check` 对拍的是渲染结果，显式回退与条件类等价。
- **风险与对策**：将来新增第四档主题时，回退规则漏写会白纸档样式外溢——在两条回退处加注释「新增主题档必须同步回退」，`design:lint` 的颜色来源检查不覆盖此项，靠注释与评审守住。

### D4：纸宽与写作页同式，内容列仍由阅读配置决定

`.pv-paper` 宽度沿用写作页同款公式（`min(680px + 2×64px, 100% − 24px)`、先挤纸边距到 20px 下限再让内容列让路）；纸内正文保持 `.pv-prose` 的 `max-width: 66ch` 居中——66ch 随字号档位（14/16/18px）变化，纸宽不随之变。

- **为什么**：纸是稳定的空间参照（同一窗口下写作页与预览页纸宽一致），正文列宽是阅读偏好变量——纸宽跟字号走会让「纸」在调字号时跳宽，破坏纸的稳定感。66ch（约 530–590px）窄于 680 版心，纸内左右留白比写作页略宽，是阅读页的呼吸感，可接受。
- **否掉的替代**：纸宽改绑内容列（`fit-content`）——调字号纸跟着跳，且窄列下退化顺序（先挤纸边距再挤内容）无法用同一条 clamp 表达。

## Risks / Trade-offs

- **[预览 parity 基线必红一次]** `prototypes/preview.html` 与实现同批改，`design:check` 的预览 parity 才能回阈值内——两处不同批合入必红，实现 PR 内同批完成。
- **[纸内留白观感]** 66ch 内容在 808 纸内左右留白偏宽（D4 的既定取舍）；原型阶段截图确认，失衡再回到 D4 重新拍板，不带病落地。
- **[主题回退遗漏]** 新增第四档阅读主题时忘记回退纸面样式（D3 注释守卫）。

## Migration Plan

纯呈现层改动，无数据迁移、无接口变更。默认主题（白纸）的呈现变化对用户即刻可见；护眼/夜间用户零感知。回滚 = revert 前端两个文件＋原型同批 revert。
