# c-kb-write-block · 写法块选择器+注入（知识库二阶段⑥）

## Why

知识库第一阶段（c-knowledge-base，已合 main＝3c27f297）完成了「存/看/管/进书/备份」，但**写正文时还没有任何知识注入**——作家沉淀的手法与场景写法（"打斗句长≤12字""哭戏禁比喻"）躺在库里，写章提示词依旧只靠每本书的静态设定。二阶段⑥把消费链闭环：写章时按剧情从知识库挑选知识，组成「本章写法块」注入 user 层，让库真正参与每一次动笔。delta 草案已在 c-knowledge-base 归档 drafts/c-kb-write-block/（四轮评审打磨过的措辞全保留），本变更将其升级为正式实现。

## What Changes

- **选择器（后端）**：写章时按作家章纲确定性挑选知识——出场角色直取章纲角色字段；场面/情绪/章位由章纲概要与剧情条目经封闭词表＋别名表归类（不调用模型）；归类不出不硬猜（只出基线与通用兜底）。打分＝匹配度×有用率×新鲜度，经物化标签索引出候选短名单（≤200）后内存打分；配额手法 ≤6＋场景定性写法 ≤4、总预算 ≤2K tokens
- **注入（后端）**：`write/router.py` 组装链在**存储稿选定之后、输出契约收尾行之前**拼接「本章写法块」（块首三句声明：不改剧情／红线契约优先／条件标签语义）；量化维度条目经章级文风影子并轨（`write/style_shadow.py`），写法块不另立数值声明；不落库、不进弹窗持久化编辑区
- **留痕与反馈（后端＋前端）**：每章生成落 `kb_match_runs`＋`kb_match_items`（批1 已建表）；同章同素材重试复用运行记录（字节一致）；续写/补足按章节复用；作家可逐条标记有用/没用回写 `kb_prefs` 权重
- **守护语义**：未启用库零变化；停用后无块；零命中不出空块（含块头）；块内文本与收尾行/分量行/续写行最长公共串 <8 字（入库判据式拒收）
- **评估（CI）**：别名归类单测＋golden 集选集一致率＋冲突率=0 断言进 CI 门禁

## Capabilities

（无——全部落在既有能力上）

### Modified Capabilities

- `prose-writing`: ADDED 知识库写法块注入需求（注入点、块首声明、影子并轨、复用语义、守护语义）

## Design Impact

- 受影响端：**C端 only**（S端不动；提示词包不动——块首声明与条目格式是代码拼装固定文案，非 AI 模板）
- 受影响屏/弹层：
  - 章级提示词弹窗：新增只读展示区「本章写法块（自动注入·不落库）」（仅启用库的书出现；不在持久化编辑区）
  - 写作页/章详情：选择清单留痕入口（逐条「有用/没用」标记）——最小形态＝提示词弹窗只读区内逐条附标记钮
  - 不动：知识库页、设定面板、书架
- 对象状态：无新增全局对象状态；条目新增权重回写（既有 kb_prefs 表）；提示词弹窗新增只读区块（既有弹窗信息层级）
- 两端共享段：不触碰（design-system 共享段零改动；只读区用既有 panel/modal 词汇与 info/ok/warn/err 语气词）
- 是否需要原型先行：**否**——只读区块＋标记钮为既有弹窗模式的最小扩展，实现侧自查；若 boss 要求视觉稿再补
- 设计工件：实现侧自查（文案遵循 design-language §13 口径：按钮用动词、无内部术语）
