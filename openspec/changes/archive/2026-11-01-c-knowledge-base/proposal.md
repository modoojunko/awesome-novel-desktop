## Why

写作知识库是「拆过的书、踩过的经验」的沉淀层：同一账号下的手法/文风/文笔/世界/角色造法只有一份，被各书的库圈用、被写章提示词按剧情挑选。现在拆书产物落书即丢通用部分、作家经验无处沉淀、写章提示词没有任何知识注入——正文质量依赖每本书从零手填设定。设计已完成（`docs/design-c/drafts/ai-novel-c端-写作知识库-整体方案.md`、`-选型.md`、`-数据结构.md`、原型 v29 全绿），评估确认数据结构能承接六类知识与 10 万级条目，开始立项实现。

## What Changes

- **新增账号级「写作知识库」**：L0 元模型（concepts/entries/entry_tags/relations/organize_runs/libraries/library_items/prefs 八表）＋L1 概念注册表（六概念：文风/文笔/世界设定/角色设定/手法/情节-P1）＋21 题材目录（含 `""` 通用）。
- **条目＝公共信封＋按概念强校验 payload**：一条知识只讲一个侧面；带 `when_json` 的文风/文笔＝场景条目（逐章挑），不带＝基线（快照）；校验闸（指令 ≤240 句末断、原文 ≥20 字逐字同默认不收、幂等键、when 概念白名单、场景条目槽位闸 role/pov 禁改）。
- **四条数据来源**：手录（首页空态 CTA，免费）、拆书「收进知识库」（PRO，显式动作＋幂等）、文风蒸馏确认卡沉淀（免费）、种子（21 目录＋概念树，装包即有）。AI 整理只写关系永不写条目。
- **库自动长成**：某题材×概念（及通用×概念）首个条目入库时自动生成默认库（自动圈全部条目）；场景条目在库内按 scope 分组；无「派生」流程（10-30 拍板移除）。
- **写章时按剧情动态组装提示词**：→ c-kb-write-block 子变更（第二阶段，见 roadmap）
- **混合型消费**：文风/文笔基线条目启用库时快照进本书 `style`（system 恒定层不动，spec 字节一致红线保持）；世界设定纯快照；角色设定起草型（挑原型复制落卡，不进提示词）。
- **角色库迁移到知识库**：角色库不是独立系统——扩 CharacterPayload schema 到角色库全量字段（dossier 8 格/cog 11 格/persona/arc），写迁移脚本把 `character_library` 全量行迁入 `kb_entries`（concept="角色设定"，幂等），角色库 UI 改读/写 kb_entries，`character_library` 表 deprecated。
- **知识库首页**：题材栏（只显有内容+全部+跨题材通用+更多折叠）＋六概念页签（带白话说明）＋条目按题材×概念分组标题行组织（不做独立库卡——库卡等 ③ 启用功能上线后亮相）；全局图推迟到 ⑦ AI 整理同批（① 没有关系边，图是纯层级树无"发现关联"价值）；全部文案用作家日常用语。3D 星图为 Lab 实验不进 P0。
- **AI 定期整理关系**（P0-E，PRO）：拆书入库后/闲置 7 天/手动触发，按题材跑，置信 ≥0.75 上星图、0.5–0.75 待确认、<0.5 丢弃，空题材跳过。
- **备份**：账号级八表进配置包新段（FORMAT_VERSION 升 v9——v8 已被角色库占用）；书内三表（bindings/match_runs/match_items）进单书备份随书级联。

## Capabilities

### New Capabilities
- `knowledge-base`: 账号级写作知识库——知识模型与校验闸、概念注册表与题材目录、手录＋种子导入、默认库自动生成、浏览界面、角色库迁移（角色库 UI 改读写 kb_entries）。

### Modified Capabilities
- ~~`prose-writing` / `deconstruct-book` / `backup-restore`~~：**已移至子变更**（c-kb-write-block / c-kb-import / c-kb-backup），不属本变更范围——完成页显式动作、五类维度映射、长度/原文闸、幂等键、题材归属。

## 拆分策略（P0 整改）

按仓规「一个变更随一个实现 PR 归档」，本变更收敛为**批1（底座＋浏览界面）**；批2–7 各立子变更，各带 delta＋tasks：

详细计划见 **`roadmap.md`**（勾一个做一个）。两阶段：

**第一阶段（建库，当前）**：① 底座＋浏览 → ② 拆书入库 → ③ 启用落设定 → ④ 角色原型 → ⑤ 备份

**第二阶段（动态拼装，建完再看）**：⑥ 写法块选择器＋注入（含红线仲裁、影子并轨等冲突方案在此阶段定） → ⑦ AI 整理

本变更 spec/tasks 仅约束 ①（底座＋浏览）范围。

## Impact

- **后端**：`models/kb.py` 七模型＋书内三模型注册；`kb/` 新包（concepts.py 注册表、payloads.py 六概念 Pydantic 含角色全量字段）；角色库数据迁入 kb_entries（`character_library` deprecated）；备份 v9 段（→ c-kb-backup 子变更）。
- **前端**：知识库页（写作工具入口）、条目抽屉、库页、全局图（vendor force-graph 177KB）、书内来源行、蒸馏确认卡「存进知识库」。
- **档位**：拆书入库与 AI 整理走 PRO（AI 拆书既有档）；手录/蒸馏沉淀/浏览免费。
- **兼容**：全加法，未启用任何库的书零变化；旧代码不读新表；`FORMAT_VERSION` 8→9 与角色库 v8 顺序兼容（先 v8 后本变更升 v9）。
- **非目标**：3D 星图 Lab、情节消费、手动圈库、向量检索、自定义题材、跨库手动圈选（均 P1+）。
