# c-intro-draft-interview — 简介起草：先问三问、三候选挑一

## Why

线上真机验证（10-29）：书是西式奇幻（黑暗奇幻）、书里已有完整设定，但「AI 起草」只凭「书名＋题材＋五格」起稿，产出与作者心里的书相去甚远——**在「题材确认 → 简介」这一步，系统里本来就只有题材信息**，只凭它的生成上限就是"该题材的典型盘"（用户判断：「这里就缺信息」）。补的不是更多模板规则，而是**生成前向作者要一小口信息**，并让作者在 3 条差异化候选里挑一条再改。

## What Changes

- **起草改为两段式「先问后起」**：点「AI 起草」→ 弹窗先出 3 个可选小问题（主角是谁/什么处境、想要的味道或困境、必须保留/必须避开；均可跳过、关弹窗不丢）→ 提交后一次生成 **3 条差异化完整简介候选**（每条 ≤500 字、六段骨架、≤12 字故事核标签）→ 作者点选一条「填入所选简介」→ 整段替换＋回执撤销。
- **交互**：三卡并列默认选第一条；「换一个」按同组答案重出 3 条；卡内「改一下问题」回表单且保留已填答案。**推翻** 2026-10-28「单稿＋重掷、不做多候选挑选」的口径。
- **后端**：`draft` action 收 `answers{protagonist,taste,musts}`（各 ≤200，都可空）；响应改 `{"candidates":[{label,synopsis}],"act":"replace"}`；作者补充优先于题材典型盘与五格（世界名词仍须来自题材世界）；temperature 0.8→0.9（拉开三条差异）；**平滑降级**：旧版模板只回 `{"synopsis"}` 时包成 1 条候选。
- **模板 v4**（prompts 仓）：三候选 JSON 契约＋「作者补充优先」规则＋「三条故事核必须不同」规则＋自检⑦；世界体系一致性硬规则与双示例沿用 v3。
