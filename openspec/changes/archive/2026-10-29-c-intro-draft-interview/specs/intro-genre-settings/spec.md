# intro-genre-settings Delta — c-intro-draft-interview

## MODIFIED Requirements

### Requirement: 简介「AI 写作助手」（四能力，标准档起）

- 简介右栏 SHALL 为一个「AI 写作助手」卡片：头部＝**档位角标**（随套餐：免费版／标准会员／PRO 会员／MAX 会员，文案单源）＋标题「AI 写作助手」＋可选功能性副行（无 Key／缺模型等下一步动作；SHALL NOT 出「已解锁/套餐归属/只加工不代写」这类套餐文案）＋四个**并列**能力行（**起草 / 体检 / 补缺失 / 润色**，非先后流程；起草列首位）＋底部来源/去向声明。
- 每行 SHALL 为：能力名称（上）+ 描述（下，从属）+ 右侧箭头，整行可点。
- **起草**（c-intro-draft-interview，用户 2026-10-29 拍板；推翻 10-28「单稿＋重掷、不做多候选」的口径）：只凭题材起稿信息量不足，起草 SHALL 为**先问后起的两段式**——点「AI 起草」先出 3 个可选小问题（① 主角是谁/什么处境 ② 想要的味道或困境 ③ 必须保留/必须避开；均可跳过、关弹窗不丢），答完提交才发请求。后端 SHALL 注入：题材目录（大类世界 desc＋子类基调＋案例锚）＋题材五格已填项（未填标「作者还没填」、候选 id 译回人类可读标签）＋作者三问（未答标「作者跳过了，按题材典型盘」）；**作者补充 SHALL 优先于题材典型盘与五格**（世界名词仍须来自题材世界）；请求体 `content` 在起草分支 SHALL NOT 作为模型输入（从零起草吃题材不吃旧文，已有成稿的加工走润色）。
- 起草 SHALL 返回 **3 条差异化候选**（`{"candidates":[{"label","synopsis"}],"act":"replace"}`；`label` ≤12 字为故事核短标签、`synopsis` ≤500 字；三条故事核 SHALL 不同——主角类型/冲突形态/钩子切入点各异）。出卡为三卡并列（默认选中第一条），作者点选后「填入所选简介」＝整段替换＋回执一步撤销；「换一个」＝按同组答案重出 3 条；卡内「改一下问题」SHALL 回到三问表单并保留已填答案。**平滑降级**：旧版模板只回单稿（`{"synopsis"}`）时后端 SHALL 包成 1 条候选（label 兜底「候选 1」）。起草提示词 SHALL 按六段模板骨架组织（与六段模板/体检白名单同口径）＋**世界体系一致性**硬规则（具体名词必须来自题材世界，示例只教手法不借世界）＋词句禁忌（第一句钩子 / 短句 / ≤500 字 / 不写死结局）。
- 体检 SHALL 按四件事检查：① 六段模板逐项查达标/缺失；② 扫禁忌（**设定集腔 / 作者自白 / 剧透**）；③ **标题对照**（书名 ↔ 简介是否互相印证）；④ 结论。**只提醒、不拦确认**；行名与六段模板完全一致。注：禁忌第三元「剧透」与「别踩」第三元「写死结局」**用途不同（扫描规则 vs 写作引导），写死结局 ≠ 剧透，勿合并为同一枚举**。体检为诊断语义，**只分析/只提醒、不补写不改写**。
- 体检接口 SHALL 返回结构化 JSON：`{"six_segments":[{name,status(ok|missing),excerpt,note?}], "taboo":{"hits":[{rule,excerpts}]}, "title_check":{"fit":"ok|mismatch|generic","note":"…","suggestions":["…"]}, "verdict":"strong|ok|weak"}`，其中 `name` 须为六段名之一、`status` 限 `ok|missing`、`fit` 限三值。
- **标题对照语义**（`title_check`）：`ok`＝标题暗示的类型/看点与简介一致；`mismatch`＝不符（如标题像甜宠、简介是压抑复仇）；`generic`＝标题无信息（任何同类型小说都能用，如《第一章》）。`mismatch`/`generic` 时 SHALL 给 `note` 说明理由 + **≤3 条候选标题**（每条 ≤16 字，贴题材、留钩子、不剧透结局）。候选标题 SHALL 仅作参考提示，**SHALL NOT 提供「一键设为书名」入口**——书名改不改、怎么改由作家自己决定（用户拍板 2026-09-10）。**兜底**：模型未返回该字段或 `fit` 非法 → 该字段**不下发**，前端不渲染该行（**不得硬判 `ok`**，避免假绿）。
- **结构化输出策略**（跨供应商/弱模型）：体检/题材的 JSON 输出除 endpoint 后置归一化兜底外，prompt 侧 SHALL 给 **schema + 枚举 + 一个 few-shot 示例**；能用的 provider 追加 `response_format={"type":"json_object"}`（需同步扩 `AIClient.chat` 的 OpenAI 分支）。
- 补缺失 SHALL 只针对缺失段给候选；请求体 SHALL 带 `missing_segments`（前端把 introspect 的 missing 段传来），返回 `{"missing":[{name,candidate}], "act":"insert"}`；**只补缺失段、不重写作者已写段**。候选在弹窗文本卡内逐条呈现，确认才写入简介。**前置**：未先体检时「补缺失」行 SHALL 提示「先体检，才知道缺哪段」（或禁用），不得空跑（O-3）；六段全 ok 时 SHALL 提示「六段都齐了，无需补」（O-16）。
- 润色 SHALL 前后对照（入参 `{title, content}`，返回 `{"original","polished","act":"replace"}`），确认才替换；保原意、只加工不代写。**对照展示形态**＝弹窗文本卡内原句/润后**上下两行**（O-17）。
- **AI 助手交互状态机**：四个能力（起草/体检/补缺失/润色）SHALL 共用同一状态机 `idle → running → result → adopted`（异常走 `error(reason)`；起草为两段式 `form → running → result(三卡) → adopted`，其余三件套单段）；**「AI 出卡确认弹窗」为其唯一渲染面**。**前置守卫**：补缺失未先体检时该行置灰 + 「先体检」，不空跑（O-3）；**空结果**（六段全 ok 时补缺失）弹窗内显示「无需补」而非空白（O-16）；**生命周期**＝结果只在弹窗内呈现，确认写回后弹窗关闭、直接关闭即弃（不写回、不留面板残留）；「换一个」＝弹窗内重新生成，**生成历史切换退役**（O-5 生命周期随之改口径）；**save 成功但 confirm 400** → 「内容未通过校验」+ 保留 dirty（O-4）。
- **失败文案矩阵**（O-13）：400 →「请求有误，请检查输入」；403 `member_required` → 升级；403 `no_key` → 去模型配置；503 `missing_model` → 去选模型；502/非法 JSON →「暂不可用，请重试」且**不拦确认**；网络异常/超时 →「网络异常，请重试」。**重试不重复计 usage**。
- 点任一能力，生成/体检结果 SHALL 在**弹窗出卡**中呈现（生成类＝文本卡带确认；体检＝只读报告卡，无采纳）；右栏只作按钮、不内嵌答案、面板内不再渲染格下结果区。体检/补缺失/润色的 AI 请求以**当前输入框的 synopsis 为源**（`content`），不读存储旧文；起草的请求源为**题材上下文＋作者三问**（题材目录＋五格＋answers），`content` 不作为其输入；入参一律含 `title`（书名）。

#### Scenario: 标题与简介不符时给出提示与候选

- Given 书名为《我在夜晚打吸血鬼》（暗示都市奇幻），简介写成压抑宫斗
- When 执行体检
- Then 返回 `title_check.fit="mismatch"` + `note` 说明不符之处 + ≤3 条候选标题
- And 体检报告卡在六段行下方显示「标题对照：与简介不符」+ 理由 + 候选标题

#### Scenario: 标题无信息也提示（不得判为一致）

- Given 书名为《第一章》或《测试》，任何同类型作品都能用
- When 执行体检
- Then 返回 `title_check.fit="generic"` + 候选标题（非 `ok`）

#### Scenario: 弱模型未返回标题对照时不造假绿

- Given 模型输出缺少 `title_check` 或 `fit` 取值非法
- When 归一化体检响应
- Then 该字段不下发、报告卡不渲染标题对照行（**不得**补一个 `ok`）

#### Scenario: 体检六行与模板一致

- Given 简介已输入
- When 作家点「体检」
- Then 弹窗报告卡列出六段逐项 达标/缺失，行名与六段模板一致，且给出禁忌扫描结论

#### Scenario: 反馈落输入框下方而非右栏

- Given 点任一能力
- Then 结果出现在弹窗出卡内，右栏不堆长答案；简介框下方不再出现内嵌结果区（原「落输入框下方」形态随 .ai-sink 退役，确认语义不变——确认才写回）

#### Scenario: 关闭即弃

- Given 补缺失候选已在弹窗内呈现
- When 作者未点确认直接关闭弹窗
- Then 简介原文一个字不动，面板无残留结果

#### Scenario: 空简介落地即可起草

- Given 新书完成题材确认自动进入简介面板，简介为空
- When 作家点「AI 起草」
- Then 不出现「简介为空」报错，弹窗先出三个可选小问题（可跳过）
- And 提交后出 3 条差异化候选卡，选一条「填入所选简介」后简介写入全文，回执可一步撤销

#### Scenario: 起草吃题材不吃旧简介

- Given 一本书已有旧简介（或半截草稿）
- When 后端处理 `draft` 请求
- Then 注入题材目录、五格已填项与作者三问，不把已有简介喂给模型
- And 选卡采纳后旧文被整段替换，回执可一步撤销回旧稿

#### Scenario: 三问可跳过也能出候选

- Given 作家点「AI 起草」后不想回答任何问题
- When 直接点「生成 3 个候选」
- Then 照常返回 3 条候选（作者补充以「作者跳过了，按题材典型盘」占位），不报错不空跑

#### Scenario: 三候选挑一条填入

- Given 三条候选卡已出（默认选中第一条）
- When 作家点选第二条并点「填入所选简介」
- Then 简介框整段替换为第二条全文，回执显示「已采纳「AI 起草 · 标签」」，可一步撤销

#### Scenario: 改一下问题保留已填答案

- Given 候选卡已出、作家此前的三问答案非空
- When 作家点卡内「改一下问题」
- Then 回到三问表单且三个输入框保留先前答案，改完重提重新出 3 条
