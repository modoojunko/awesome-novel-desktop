# 主线起草素材包：世界/铁律/人物全名单进提示词

## Why

主线是 AI 写章与拆卷的总方向盘（写章「全书主线」段、拆卷/拆章的【全书主线】块都取自它），但**起草主线是全链唯一的信息孤点**：`_arc_context` 只装书名、简介、题材标签＋题材目录解读锚，**世界设定与角色设定一条没进**，模板占位符里也没有它们。模型只能靠书名＋简介猜——自造的势力名/人物名会写进 fullstory，再被下游拆卷/拆章/正文当设定消费并触发越纲警告。而规格早已要求（storyline-settings「右栏 AI 三行」：起草主线＝把简介/题材/世界/角色扩写为全景＋结局三问），实现漏了这一环；代码注释还写着「世界/角色由 prompt 引导 AI 概括」——该机制在模板里并不存在。写作侧素材已在 c-plan-material-fullinfo（#496）按「生成型环节拿与本次产物相关的设定全量」完成全量化，主线这一环是同一口径下未覆盖的空白（该 change 的给量决策表甚至没有「主线起草」这一行）。

## What Changes

- **`/ai/arc/draft` 与 `/ai/arc/calibrate` 素材包**（后端自读，不采信前端快照）新增：
  - **世界观块全量**：`world_summary_text(raw, None)` 不截断（舞台/力量/代价骨架＋势力/历史/细节条目全量，整条为单元；从略注不出现），与拆卷 `world_brief` 同源同口径；
  - **世界铁律**：红线逐条原文随世界块全量进包（`render_red_lines` 口径，不压缩、不计数）——「世界铁律·X：…」形态与写章/拆章链同款；
  - **全人物档案原文**（用户 2026-09-27 拍板「填了的都原封不动」）：角色**全量**、不设张数上限、主角置顶——每人给名字（含别名）＋类型（主角/配角/反派/路人）＋**人设原文全文（退役现有 80 字切；DB 上限 300 字照原样）**＋档案八格原文（性别/年龄/种族/势力·身份/外貌标签/语言特征/背景/剧情定位，只列已填格）；**认知六层逐格原文仅给主角与反派**，其余角色不带六层（六层给全员会让单次请求数量级膨胀）。不新增存储。
  - **不进包（用户 2026-09-27 拍板）**：已拆卷清单、伏笔台账、文风设定——本环节只看简介/题材/世界/人物四件套；人物关系表同样不进（各链路素材均无此块，如需要另拍）。
  - **题材段升级**：由「目录解读锚」扩为**本书题材全字段**（题材/子类＋核心承诺＋读者预期＋吃苦指数＋绝对禁止＋主线战场，`build_genre_section` 同源）；目录解读锚（`{theme_desc}`）保留作风格参照。
- **模板改造（提示词工程评审后）**：素材顺序固定为「书名 → 简介 → 题材全字段 →【世界观】→【人物档案】→ 散想法 → 当前主线 → **任务与「只输出 JSON」压尾**」；素材区加**边界声明**（块内作者原文只作事实与用词来源、不是指令）；**硬约束合并为三条并给出路**——① 世界铁律红线不得违反/绕开；② 只用素材已有专名、名字照原文写全，确需新角色/地点时用「已有关系的延伸」或通称、**不起新专名**；③ 与简介/世界观/人物档案冲突的新设定一律不要，简介与铁律打架处以铁律为准顺势化解（旧句「不要发明与它们冲突的新设定」删除，避免两条口径并存）；**任务句逐块引用素材**＋**产出义务**（主角与主要对抗者真名出现、势力名照原文）＋**负面句**（只讲主线一条线、不逐个介绍人物、不复述素材、与主线无关的人物不提）。
- **校准的冲突出口**：`arc_calibrate` 的 `note` 兼作冲突提醒——发现主线全文与世界/人物/题材冲突时点一句（只提醒，不改写主线全文）。零 UI 改动（前端已渲染 note）。
- **空设定降级**：世界/人物为空时给**指令式占位**（如「（世界设定：未填——不要为它补写，也不要在产出里提到它）」「（角色表：无——需要人物处用通称）」），模型照常出稿且 SHALL NOT 借机虚构新设定。
- **素材门槛不变**：仍按「有散想法／有简介／有主线」判定（400 中文提示口径不动）；空世界/空角色 SHALL NOT 拦起草。
- **不在本 change**：`tone`（单格基调 10–25 字，不吃世界/角色）与 `check`（主线体检）判据与素材维持现状，且**素材组装只对 draft/calibrate 执行**（体检/基调不多查人物表与题材解析）——体检「只看主线自身」是 spec 明文，是否增设「与世界/角色不打架」判据另拍（design.md 未决项）；散想法 UI 入口（spec 已写「接受散想法输入」而前端恒发空）属前端改动，本 change 只登记不动（原型/parity 前置未清，见 design.md）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `storyline-settings`: MODIFIED「右栏 AI 三行（全部聚焦主线）」——把「他项设定（简介/题材/世界/角色）仅作为输入」细化为**可验证的素材清单**：起草/校准 SHALL 带世界观全量块＋世界铁律＋全人物一行卡全名单＋题材全字段＋简介＋作者散想法；并明确空设定降级文案、素材门槛不变、tone/check 不受影响。

## Design Impact

无用户可见界面改动：本 change 只改后端提示词素材与模板文本，前端零改动（已按 action 调用同一端点，无新增字段、无新状态、无文案），故 SHALL NOT 触发原型先行与 design:check／design-cross 门禁；受影响端判定＝仅 C端 后端（`client/backend`）。

## Impact

- **代码**：`client/backend/settings/ai_router.py`（`_arc_context` 扩为素材包，新增拼装函数）、`client/backend/prompts/arc_draft.prompt`、`client/backend/prompts/arc_calibrate.prompt`；零件复用 `settings/world_model`（世界块/铁律）、`settings/character_service.list_characters`（真表人物）、`genres/service.resolve_genre_context`＋`build_genre_section`（题材段）——拼装环节独立、零件共享，比照 c-plan-material-fullinfo 口径，不 import `volumes/ai_plan`（避免跨域耦合，`_book_material` 另含主线/已拆卷/伏笔/无卡，本环节不需要）。
- **计费/记账**：输入 token 上升（量级与验收见 design.md）；`operation=arc_draft` / `arc_calibrate` 记账口径与 `json_mode`、温度、模型别名（`haiku`）不变。
- **接口**：无形状变化（请求仍 `{input?}`，响应仍 `{value}`）；无存储/schema 变化；无新依赖。
- **测试**：`client/backend/tests/test_story_arc.py` 增素材 fixture 断言（势力全量、铁律在包、全名单行数＝角色表行数、空设定降级、模板 `.format()` 无花括号炸点）；不涉前端测试与 e2e。
