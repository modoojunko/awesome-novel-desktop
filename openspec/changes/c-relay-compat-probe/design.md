# c-relay-compat-probe — 设计

## Context

连接探测与生成共用「用户填写的 base_url」，但版本段推导只兑现了一半：models 探测有裸域名补 `/v1`（`_openai_models_url`），对话探针（主链＋404 降级）与生成调用（ai_client 把 base 原样传 OpenAI SDK，SDK 实证直拼路径不自补版本段，#741 同款实证）都裸拼。同时 models 端点的 401/403 在连接测试与轻探针两处都被短路判「认证失败」，而中转站（new-api 系）的 403 多为「token 有效但分组权限拒绝清单」——lunarfox 实锤截图：填对了 `…/v1` 仍报「认证失败 (HTTP 403) 无权访问 gpt特定版分组」。见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 裸域名与带版本段 base 在 models 探测／对话探针／生成三处行为一致（spec「同源推导」完整兑现）。
- 清单 403 不再短路判死：连接测试降级到真实对话路径验证；轻探针零生成语义下回 ok＋说明引导手填。
- 401 保持硬判（Key 无效时对话必同样 401，降级白花一次请求且上游文案更准）。

**Non-Goals:**
- 不做 Base URL 保存时自动改写（2026-10-05 拍板；归一只在请求推导层发生，用户所见与库内存储一致）。
- 不动「你好」判据、探针模型 id 主链取用顺序、models 429/5xx 现判。
- 不加任何站点白名单——全部按地址形态/协议行为类型化。

## Decisions

1. **归一单源放推导层**：`connection.normalize_openai_base` 为唯一实现，四处调用（models 探测、主链对话探针、404 降级地址、ai_client→SDK）。备选「保存时归一落库」被拍板否掉（改写用户输入）；「各调用点各自补」是本次事故根因形态，禁止再漂移。
2. **版本段判据按段不锚行尾**：`/v\d+[a-z]*(/|$)`——段以 v+数字开头即算。首轮实现用 `/v\d+$` 行尾锚，被 #741 的 Gemini 兼容层用例当场逮住（`/v1beta/openai` 版本段在中段，误补成 `/v1beta/openai/v1/...`）；按段判顺带把 Gemini 清单探测从「靠 404 降级碰对」归位到真实路径。
3. **403 并入降级链而非放行**：与 #741「404 两格式同享降级」同构——降级后判据仍是「你好」探针，通才报正常，403 只是换了判定依据；对话同样 403 时如实回 auth_error（带上游原文），不假阴性也不假阳性。探测 id 链复用 #741 现解管道（已选模型 > 候选 > anthropic 占位；openai 无 id 判负）。
4. **轻探针 403 回 ok 而非 error**：零生成语义下无法验证对话路径，「认证失败」是已知误导（截图实锤）；ok＋空清单＋说明与 anthropic-404 先例同构，表单呈现 warn 说明＋手填出口而非红色失败。anthropic/ollama 的 403 保持硬判（无「分组权限」实锤，鉴权失败是更可能的真相）。
5. **403 说明单文案**（不分 API 格式）：404 的双文案差异在尾句「改成 openai 重测」——对 403 不成立（同站换格式同样 403），故 403 固定引导「手动填模型 id」。

## Risks / Trade-offs

- **真被吊销的 key 多花一次对话请求**：403 降级后探针会再吃一次 403 才判死——一次额外请求换「分组权限误伤」的清零，且上游原文保留，判准无损失。
- **归一改变假想「根路径伺服 chat」端点的行为**：该形态在中转站生态（SPA 兜底回 200 网页）不存在——今天的生成对裸域名本来就是坏的；无真实存量用户（2026-09-18 拍板）兜底。
- **探针 `thinking:{disabled}` 经 new-api 透传给 Claude 自适应模型可能 400**：报错文本含 "thinking" 触发去参重试（既有约定），风险可控；无 Fox 有效 Key 未做真 Key 实测，列入真机冒烟。
- **有 Key 失焦即自动发清单请求**：403 回 ok 后不再亮红，用户可能没注意清单为空——说明文案显式引导手填，选择器空态主入口本就是手填。
