# c-agent-fleet：域 agent 舰队＋总调度（AI 助手＝总调度 agent）

## Why

一期助手是单体 agent：一份系统提示词＋全量工具注册表，靠 `build_page_note` 按页注入上下文区分场景。走查暴露两个结构性问题：

- **提示词一个大杂烩**——设定/卷纲/章纲/正文的职责、纪律、话术全挤在一份身份定义里，页面上下文只靠注入补充，域专属纪律（如正文域的人味红线、章纲域的节奏档位）无法各自强化
- **工具全量下发**——任何页面任何请求都能摸到 30 个工具，域内精度和越域误触只靠提示词约束

boss 拍板（2026-11-16）：**每个 tab 就是独立的 agent**——设定是设定 agent、卷纲是卷纲 agent、章纲是章纲 agent；**AI 助手是总调度 agent**。会话形态另拍板：**全部先进总调度**——每条消息先经总调度分类，再转对域 agent 干活，域 agent 无独立会话身份，作家感知里永远是「AI 助手」一个对话。实施次序拍板：**harness 先行**——本 change 依赖 c-agent-harness（native FC 范式）先落地，fleet 在其上叠加。

## What Changes

- **总调度路由**：每条作家消息先进总调度 agent；总调度识别任务域并委派，域外/闲聊/跨域任务自己承接；总调度持有全域读取工具＋委派工具，SHALL NOT 持有域写工具（写操作必须委派）
- **域 agent 注册表**：AgentSpec（name/persona/domain/tool_scope）封闭注册——设定/卷纲/章纲/正文等域 agent 各有一份 persona（自身份定义派生＋域专属纪律）与工具子域（域写工具只进本域，读工具全域共享）；注册表外域 SHALL NOT 出现
- **委派执行**：总调度以原生 tool_calls 调委派工具→内嵌跑域 agent 循环（读域上下文→调域工具→产物卡），域 agent 步事件带 agent 身份标签流入**同一线程**；墙钟/停止落库/授权梯度纪律逐级继承
- **事件契约增项**：step/轨迹事件加 agent 身份字段（增项不破坏——dock 轨迹组、气泡呈现标明当前哪个 agent 在执行；作家感知仍是「AI 助手」一个对话）
- **能力围栏不变**：物理封闭的仍是全量工具注册表；域 tool_scope 是注册表的子集视图，不增删工具

## Design Impact

- 受影响端：C端 only（S端 零改动）
- 受影响屏/弹层：dock 轨迹组与气泡加 agent 身份标签（增项）；无新增屏/弹层
- 两端共享段：不触碰
- 原型先行：不需要（呈现为 dock 既有轨迹组加身份标签，无新布局）
- 依赖：c-agent-harness 合入后实施（委派走原生 tool_calls；文本协议降级路径下委派退化为总调度自答＋转域指引）

## Impact

- 不影响：write_gate 授权梯度、线程模型（仍按 tab 分线程）、压缩、能力围栏、档位门控
- 风险：委派嵌套循环的墙钟预算切分（总调度＋域 agent 共享单回合墙钟）；分类错误的兜底（委派错域时总调度可召回重派）
- 测试迁移：路由测试（域分类）、委派测试（嵌套循环/事件标签/纪律继承）、越域写拒绝测试
