# prose-writing Specification (Delta)

## REMOVED Requirements

### Requirement: 基于确认提示词生成

## ADDED Requirements

### Requirement: 基于方案卡定稿提示词生成

- 正文生成 SHALL 采用 system/user 两层指令：system 层为本书恒定内容（见「写作铁律注入」与「system 恒定层组装」），user 层为该章动态素材；持久化的整章提示词 SHALL 仅作为 user 层内容参与组装，SHALL NOT 覆盖或写死 system 层。
- 生成入口（c-agent-dialog-prose 起）：正文经对话框方案卡发起——方案卡展示并定稿的提示词 SHALL 作为本次生成的 user 层（prompt 覆盖通道）；作家在卡上过目的文本与发给正文模型的 user 层 SHALL 一致（所见即所发）。
- 无提示词覆盖的直开路径（env 熔断回退/旧客户端）SHALL 复用本章存量 `write-prompt` 行（存在且有效时）；无存量行或触发下述代际回落守卫时，SHALL 以当前素材组装结果兜底，SHALL NOT 每次生成都静默重组覆盖作者已确认的内容。
- 存量粗组稿代际守卫（c-chapter-seam-hardcut；c-scene-density 扩第二锚）：持久化行为粗组稿（非润色三锚产物）且缺「上章结尾」块、而本轮素材含该块时，**或**缺「字数与场景分量」锚（字数线恒出＝新组装恒含该节，缺锚必是本批之前的行）时，生成 SHALL 回落为按当前素材组装的章级 user 层（生成路径本次落库回落稿）——老章存量行 SHALL NOT 绕过字数链改造。三锚判定的历史润色行 SHALL NOT 触发回落——缺锚系旧素材下润色的历史产物，SHALL NOT 以重组稿覆盖作者资产。素材不含对应块时守卫不触发，存量稿照旧复用。

#### Scenario: 方案卡定稿的提示词优先生效

- **WHEN** 作家在方案卡过目/调整提示词后点「开始生成」
- **THEN** 本次生成以卡上提示词作为 user 层内容（system 层仍由系统按本书设定现组装）；该稿同时落库为本章提示词行（`POST /write` 既有行为）

#### Scenario: 存量提示词在直开路径被复用

- **WHEN** 本章存在有效的存量 `write-prompt` 行，且本次生成走无覆盖的直开路径
- **THEN** 生成复用该存量行作为 user 层内容，不重新组装覆盖；历史三锚润色行同样受保护

#### Scenario: 旧粗组稿重生成回落重组

- **WHEN** 升级前生成过正文的章（持久化行为旧粗组稿、缺「上章结尾」块）在升级后重新生成，且上一章已有正文
- **THEN** 本次生成使用含「上章结尾（原文）」块的当前组装稿，落库行被回落稿更新

#### Scenario: 缺场景分量锚的老行回落重组

- **WHEN** 老章持久化行为粗组稿（含上章结尾块、无「字数与场景分量」节），作者发起生成
- **THEN** 按当前素材重组（含新节）落库并生成，字数链改造对老章同样生效（首章/无尾块时同样回落——字数线恒出，缺锚即旧代际）

#### Scenario: 润色稿缺锚不回落

- **WHEN** 持久化行为历史润色产物（三锚同现）但缺「上章结尾」段（旧素材下润色），本轮素材含该块
- **THEN** 生成照旧复用该存量行，SHALL NOT 以重组稿覆盖
