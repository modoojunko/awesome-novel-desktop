# c-chars-stale-reconfirm — 设计

## 一句话

「内容有变 · 待重新确认」是**存档与当前内容的比较结果**：它必须(a)在用户看得见的地方只出现一次结论，(b)在重新盖过存档后立刻消失。本批把这两条钉死在角色的确认状态上，并让伏笔面板的页脚同口径。

## 数据链（现状 → 目标）

| 环节 | 现状 | 目标 |
| --- | --- | --- |
| 角色 stale 来源 | `useOnboarding` 取 `GET /characters/gate/status`，deps `[projectId, confirmedStatus]`；回填**只置真**（`!confirmed` 才清假） | 回填**精确值**（`confirmed && stale`）；catch 保持现值（网络抖动不得把 warn 抹成绿） |
| 重取时机 | 仅项目/确认标记变化 | ＋**角色面板数据刷新成功后**（`reloadList` 成功：进入面板、单卡保存落库、增删合并后都走它）＋**每次确认/重新确认成功后** |
| stale 期间的页脚 | 仍写「已确认 · 改动自动保存，可随时重新确认」＋绿色「✓ 已确认」 | 让位：note 改「内容改过了——点「重新确认」即可，改动已自动保存」；不渲染绿色已确认标注 |
| stale 期间的页脚（有缺口时） | 缺口点名（warn） | 不变——**缺口优先**：那才是点下去会被拦的原因 |
| 伏笔 stale | 面板本地指纹派生（即时、无需重取） | 不变；仅把 `stale` 并入上报状态，供页脚同判据让位 |

**为什么不改成"每次保存都问"之外的东西**：角色的 stale 是**服务端指纹**（全书门禁字段的摘要），前端算不出（不像伏笔有本地台账）。重取点选在"面板数据刷新"这个既有点上，不新增请求时序、也不动请求数级（每次编辑突发本来就已有一次列表重取）。

## 让位口径（文案冻结）

- 有缺口（不论是否 stale）：`还差：{类型}《{名}》缺 {项…}`（warn 常驻，点名首卡；多于一张卡缀「（共 N 张卡）」）
- 无缺口且内容有变：`内容改过了——点「重新确认」即可，改动已自动保存`（note，非 warn）
- 无缺口且未确认：`主角写全了——第一次确认只看主角；配角、反派后补也行，改动会自动保存`
- 无缺口且已确认且未变：`已确认 · 改动自动保存，可随时重新确认`
- 无主角：`确认「角色」要先有一位主角——在人物卡上把谁点成主角`
- 自动保存制面板的 note **恒不含「已确认」**（设计语言硬规则：凡含该字样必须绿色），绿色只留给徽标与 done-note；stale 时 done-note 不渲染。

## 取舍与不做

- **不改指纹算法与门禁判据**（后端零改动）：本批只解决"结论滞后/打架"。
- **不给 stale 加第三方告警**：徽标已 warn，页脚再喊一遍就是把"晕"搬回页脚。
- **不把 stale 状态提升为全局**：伏笔的本地派生链已经好用（e2e ⑦ 钉着恢复），不动。

## 差异与登记（`ADJUSTMENTS.md`）

1. `character-settings.html`：`syncFoot` 补 stale 态（demo 以"确认时的门禁字段快照"判定内容有变）＋让位后的 note 文案与 done-note 隐藏。
2. `foreshadow-settings.html`：同口径（其 demo 已有 stale 概念，随本批对齐 note/标注）。
